# 模型上下文缓存 v2 验收说明（已实施，待实局验证）

关联[设计](../specs/model-context-cache-v2.md)。用户已确认实施；上下文顺序及用量聚合测试已通过，实际供应商命中率仍待新局检验。

| ID | 场景 | 通过标准 |
|---|---|---|
| MC2-01 | 相同规则与公开水位、不同席位/Schema | 固定协议、规则和 `SHARED_PUBLIC_FACTS` 的实际发送字节相同，首次差异出现在私有或动态段 |
| MC2-02 | 不同公开水位 | 事件按 sequence 稳定追加；共有部分的编码完全一致，不含时间戳、当前局面或选项重排 |
| MC2-03 | 私密与事实 | 狼刀、查验、女巫行动、未公开投票、角色指导不进入共享段；仍只出现在授权席位；当前事实覆盖过时历史 |
| MC2-04 | Schema 与记忆 | 所有旧事实与合法选项、Schema 仍在请求中；格式纠正和 token budget 生效；业务验证仍用原始 `prepared.facts` |
| MC2-05 | 适配器兼容 | DeepSeek 与通用 json-schema 路径接受消息顺序，输出继续由本地 Schema 校验；不兼容时先修订设计而不静默跳过 |
| MC2-06 | 逐次 cache usage | 完整 hit/miss 精确保留，缺失/异常标未知；按房间求加权 `sum(hit)/sum(hit+miss)`，按席位与阶段聚合可核对原始事件 |
| MC2-07 | 前后比较 | 同一冻结房间轨迹离线计算 v1/v2 最长相同前缀并核查授权；真实持久对局记录基线、新版、调用量、输入 token、hit/miss、失败数及供应商/模型/时间窗，不把冷请求与缺失值当命中率下降 |

功能通过须先满足 MC2-01～06 且离线复用前缀明确增加。MC2-07 的实际供应商比例逐次记录；供应商缓存尽力而为，不以单局达到某一百分比代替正确性验收。

v2.1 已实施。追加验收 MC2-08：相同稳定指导、不同席位的模型请求在游戏规则后有相同 system 消息，且早于公开历史、Schema、当前事实；未命中任务没有该消息，角色专属指导保留在后部私有事实。相关单元与真实房间隔离测试已通过；实际 KV 命中率只据供应商返回的 usage 统计，不从静态测试推断百分比。

## v3 分层知识验收（已实施，真实模型观测待做）

| ID | 场景 | 通过标准 |
|---|---|---|
| MC3-01 | 不同席位、同一板子与知识版本 | 协议、板子、全职业描述、全词条按固定 ID 顺序逐字节相同；无人座位或实际身份混入共享知识 |
| MC3-02 | 同一公开水位 | 共享历史在本人指南之前，跨席位相同；改变公开水位只在其后追加或按已确认投影重建，不回写旧知识前缀 |
| MC3-03 | 不同职业 | 仅本人职业指南在私有段出现；其他职业指南不出现，公共事件和旁观响应也不包含指南 |
| MC3-04 | 不同阶段／条件 | 当前命中规则只在本人指南之后出现，未命中不发送；旧 `stableGuidance` 不再抢占共享前缀，硬选项规则继续由程序执行 |
| MC3-05 | 必需预算与恢复 | 缺失知识、超限、版本摘要变更分别显式失败或拒绝不兼容房间；不会静默删词条或改变运行中房间的提示内容 |
| MC3-06 | 真实供应商观测 | 记录前缀段摘要及实际 hit/miss；与 v2.1 按同供应商／模型、近似公开水位和席位比较，不把静态相同误称为已命中 |

已先观察段序、知识装载和 `SPEECH` 命名测试失败，再接入通用组装与狼人杀。MC3-01、03、04、05 的静态与隔离数据库用例通过；Docker 全量 248/248，类型、仓库与前端构建通过。MC3-02 的字节稳定性由组装顺序和既有公开事实测试覆盖；MC3-06 的真实供应商命中率仍待新局观测，不能由静态测试推断。旧 MC2 结论保留为历史基线。

## v4 公开状态共享段（已实施）

框架输入与消息契约见[设计 v4](../specs/model-context-cache-v2.md#v4-公开状态共享段已实施)。先在旧实现观察 MC4-01 与狼人杀公开字段测试失败，再接入分段与白名单。

| ID | 场景 | 预期通过标准 |
|---|---|---|
| MC4-01 | 同一冻结公开水位、不同席位与 Schema | 共享知识、公开历史和 `SHARED_CURRENT_STATE` 在首次私有消息之前逐字节相同；合法选项与私有事实仍各席不同，首次席位差异不早于私有段。 |
| MC4-02 | 公告或阶段变化 | 共享状态准确反映新公开快照，历史保留已公布事件的来源与顺序；旧请求、重试及恢复不读取更新后的房间状态覆盖冻结事实。 |
| MC4-03 | 越权与归属 | 私有事实、未公布结算、席位专属场景及候选选项不进入共享段；玩家声称不会被提升为当前裁判状态。 |
| MC4-04 | 兼容和预算 | 未提供 `sharedCurrentState` 的其他调用方保持 v3 布局；新增段计入预算，超限前置失败；原 `prepared.facts`、Schema 与业务校验不变。 |
| MC4-05 | 诊断与真实用量 | 布局版本与段摘要可区分 v3/v4；离线字节前缀比较可复核，真实命中率只引用供应商报告，不把模拟相同前缀称作实际缓存命中。 |

框架定向、狼人杀单元和持久模型调用日志验证消息顺序、布局版本 5、无重复 `game_state`；不提供共享状态的调用方测试保持原顺序。隔离 PostgreSQL 全量回归 273/273，通过 TypeScript 与构建。首次全量回归 272/273 揭示首日预言家规则依赖旧 `phase.round`，改读公开 `day` 后定向及全量通过。MC4-05 的真实供应商命中率与已运行旧局的发布行为尚未验证，不将静态相同前缀写成实测命中。
