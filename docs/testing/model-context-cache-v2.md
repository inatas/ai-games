# 模型上下文缓存 v2 验收说明（待确认）

关联[设计](../specs/model-context-cache-v2.md)。以下为待确认测试说明，尚未生成可执行测试。

| ID | 场景 | 通过标准 |
|---|---|---|
| MC2-01 | 相同规则与公开水位、不同席位/Schema | 固定协议、规则和 `SHARED_PUBLIC_FACTS` 的实际发送字节相同，首次差异出现在私有或动态段 |
| MC2-02 | 不同公开水位 | 事件按 sequence 稳定追加；共有部分的编码完全一致，不含时间戳、当前局面或选项重排 |
| MC2-03 | 私密与事实 | 狼刀、查验、女巫行动、未公开投票、角色指导不进入共享段；仍只出现在授权席位；当前事实覆盖过时历史 |
| MC2-04 | Schema 与记忆 | 所有旧事实与合法选项、Schema 仍在请求中；格式纠正和 token budget 生效；业务验证仍用原始 `prepared.facts` |
| MC2-05 | 适配器兼容 | DeepSeek 与通用 json-schema 路径接受消息顺序，输出继续由本地 Schema 校验；不兼容时先修订设计而不静默跳过 |
| MC2-06 | 逐次 cache usage | 完整 hit/miss 精确保留，缺失/异常标未知；按房间求加权 `sum(hit)/sum(hit+miss)`，按席位与阶段聚合可核对原始事件 |
| MC2-07 | 前后比较 | 同一冻结房间轨迹离线计算 v1/v2 最长相同前缀并核查授权；真实持久对局记录基线、新版、调用量、输入 token、hit/miss、失败数及供应商/模型/时间窗，不把冷请求与缺失值当命中率下降 |

功能通过须先满足 MC2-01～06 且离线复用前缀明确增加。MC2-07 的实际供应商比例逐次记录；供应商缓存尽力而为，不以单局达到某一百分比代替正确性验收。
