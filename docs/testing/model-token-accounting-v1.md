# 模型对局 Token 用量记账 v1 验收说明

状态：已实现并验证。关联[设计](../specs/model-token-accounting-v1.md)。

| 用例 | 预期 |
|---|---|
| MT-01 单次成功 | 供应商返回 input/output usage 后，房间合计与报告调用数精确增加 |
| MT-02 失败与模拟 | 网络失败、超时、开始但未完成、模拟或脚本调用均不增加实际 Token |
| MT-03 修复与拒绝 | 两次成功供应商响应但首次格式错误时两次均计入；模型返回后游戏拒绝或过期仍计入 |
| MT-04 usage 缺失 | 完成响应无可用 usage 时仅增加未报告调用数，不估算 Token，不显示人民币 |
| MT-05 房间隔离与重启 | 两房间并行各自汇总；重复查询、服务恢复不重复计数；已结束房间仍可读 |
| MT-06 本机边界 | 非本机请求被拒绝；未知房间按既有错误处理；响应无私有上下文、密钥或原文 |
| MT-07 旧账本 | 狼人杀服务启动不要求价格变量，调用不读取或增加旧 `ww_model_budget`；旧表与原值保留 |
| MT-08 数值边界 | 负数、非整数、缺少一侧 usage 均计为未报告；求和超安全整数时明确失败 |
| MT-09 网络部署 | 从实际运行后端的同类环境访问不计费 DeepSeek 认证端点成功，4318 目录与房间读取正常；无授权时不发起收费生成请求 |

确认后先在旧实现上运行新增行为测试并记录失败，再实施；执行相关单元、类型、仓库检查，以及使用独立测试库的 PostgreSQL 集成测试。实际 Token 观测需另有授权的真实对局，不由自动测试触发。

2026-09-24 结果：接口测试先返回404；实现后本机/远端边界通过。隔离PostgreSQL的成功、失败、缺失usage、溢出与旧表保留用例3/3通过；完整套件223/223、单元118/118、TypeScript、仓库检查与构建通过。新服务恢复已有对局后，一次真实模型完成事件报告输入3,332、输出147 token，用量接口返回一致，旧预留账本未增加。未核对供应商人民币账单。
