# 配置驱动运行验收 v1（已确认）

协议以[详细设计](../specs/configured-game-runtime.md)为唯一正文。以下为验收用例说明；已运行的命令、覆盖和限制见[验证记录](configured-game-runtime-verification.md)。

| ID | 场景与验收 |
|---|---|
| EV-01 | 动作成功只产生一个事实事件；状态或记忆提交失败时事件与投递一起回滚 |
| EV-02 | 提交后、消费前崩溃；租约过期后可恢复；消费后确认前崩溃不重复动作或效果 |
| EV-03 | 跨realm、未知接收者拒绝；事后进入房间者不能获得旧私密事件 |
| EV-04 | 同投递键并发只产生一个有效后续动作；最多3次投递及4层因果链终止可观测 |
| EV-05 | 任务与奖励不因消费者失败出现半提交；无地图平台可独立运行事件基础设施 |
| AC-01 | 玩家身份由会话确定；伪造角色/NPC、失活角色和跨realm动作被拒绝 |
| AC-02 | 玩家和NPC调用同一move；NPC没有位置或缺少能力时拒绝，不走特殊绕过路径 |
| AC-03 | NPC并发请求串行、参数冲突拒绝、过期执行不能提交；NPC scope不出现在公共账号接口 |
| AC-04 | 模型等待时其他角色可完成短事务；相关revision变化后旧判定拒绝且没有部分状态 |
| AC-05 | 重放原requestId不重复扣费、移动、记忆和事件；角色既有动作规则保持 |
| MP-01 | JSON未知字段、重复ID、坏路径、未知规则、无效参数、无效出口/出生位置在启动服务前拒绝 |
| MP-02 | move只接受exitId；当前位置与出口不符、条件不满足均失败；预览与执行规则一致 |
| MP-03 | 预览后资格改变，提交再次检查；玩家/NPC分别覆盖允许与拒绝矩阵 |
| MP-04 | realm/角色初始化分别幂等；重启不重置位置、不重复发物品；内容版本不匹配拒绝运行 |
| MP-05 | 无NPC地图、无初始位置NPC可加载；最小MOD经同一HTTP宿主运行，浏览器只接收授权投影 |
| BT-01 | selector优先级、sequence成功/失败/running语义、未知节点与超限/循环拒绝 |
| BT-02 | 时间/事件同时唤醒至多启动一个动作；巡逻无需模型；无行为配置不启动调度 |
| BT-03 | 重启恢复请求与cursor，不重复移动；中断不撤销既有提交，旧分支不继续运行 |
| BT-04 | 决策只能选择白名单动作；过时状态由Action拒绝；模型超时/网络失败有界结束且不自动重试 |
| BT-05 | 叙述失败不改变原动作；叙述不写权威事实；后置反应使用新请求并遵循因果链限制 |
| BT-06 | 错过时刻不批量补跑，路线不匹配不传送，行为状态重启后保留 |

单元测试归包自身；事务、并发、恢复、数据库约束归tests/integration；青溪资格和数值断言归mods/qingxi/tests。使用可注入时钟与故障点覆盖恢复，不能靠不稳定长sleep证明并发。模型Mock只证明协议，不计作真实模型验证。

每阶段运行npm run check、npm run check:repo、相关单元测试；最终运行docker compose --profile test run --build --rm tests。数据库集成必须使用独立测试库/随机schema；宿主运行显式设置TEST_DATABASE_URL。发布前核实备份恢复、当前版本双次启动和开发库目标。真实模型未运行须单列，禁止标为通过。
