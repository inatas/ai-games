# 本机狼人杀模型测试运维 v1.1 验收说明（已实施，待用户新局）

关联[设计](../specs/local-werewolf-test-ops-v1.md)。用户已确认 v1.1；以下用例用于本机实施验证。

| ID | 场景 | 通过标准 |
|---|---|---|
| LO-01 | 错库或错项目 | 数据库名、Compose 项目或表不符合本机开发环境时拒绝删除，原数据不变 |
| LO-02 | 备份失败 | 不能产生完整本机备份时不删旧预算表和目标日志 |
| LO-03 | 历史资料范围 | 4 个已核实终态房间及其 48 个座位、96 个专属 scope、886 条请求、318 条记忆和既有 `mod_id='werewolf'` 日志全部删除；其他 MOD 数据保留 |
| LO-03a | 边界与回滚 | 发现第 5 个房间、活跃房间、外部 scope 引用或删除数量不符时事务回滚；不用 `CASCADE` |
| LO-04 | 账本退役 | 旧 `ww_model_budget` 及其唯一行清除；当前模型房间仍启动，真实 token 用量继续来自新的 `finished` 事件 |
| LO-05 | 快速启动 | 从任意工作目录执行脚本均只启动本项目 Compose app；重复运行后仍只有一个 app，页面与模型列表可用 |
| LO-06 | 启动失败 | Docker、凭据文件、镜像缺失或健康超时给出可读错误且不输出 Key、不建立房间 |
| LO-07 | 新局留痕 | 用户网页新开一局后，新房间模型成功或失败调用继续写入 `fw_event_log`；旧预算错误不再由当前服务产生 |

确认范围后先做脚本边界的可失败测试，再实现；数据库清理前后用只读统计核对。LO-07 由用户在网页真实开局验证，自动测试不发付费请求。
