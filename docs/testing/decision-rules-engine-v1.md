# 回合决策规则引擎验收说明 v1（待确认）

本文件只描述行为用例；方案确认前不生成可执行测试。

| ID | 场景 | 预期 |
|---|---|---|
| DR-01 | 中性 MOD 注册规则并命中 | 框架只读取授权决策快照和合法选项；另一个 MOD 可复用同一执行器 |
| DR-02 | 强制选项不在游戏合法集合 | 不生成新动作，记录跳过/配置原因；最终游戏验证仍有效 |
| DR-03 | 两条强制规则要求不同选项 | 显式冲突，不按规则顺序暗选一个 |
| DR-04 | 80% 概率，同一局重试、恢复和双宿主 | 同一 occurrence 只判定一次，结果与最终动作一致 |
| DR-05 | 模型或脚本提交违反强制规则的选项 | 不执行原提案；唯一确定选项经业务重验后提交，记录偏离 |
| DR-06 | 规则未触发、禁用或概率未命中 | 原合法选项集和既有决策行为保持 |
| DR-07 | 阶段变更、自爆/中断、过期返回 | 旧规则判定和旧模型结果不能提交到新阶段 |
| DR-08 | 公开旁观、对手决策输入、管理员审计 | 前两者无规则私有原因，后者能追溯规则版本、判定与覆盖 |
| DR-09 | 恢复时注册表缺少房间固定的规则版本 | 停止该房间自动决策并报告配置故障，不换用新版本 |
| DR-10 | 模型失败或截止 | 不改阶段截止和 MOD 现有默认；不会因策略引擎提前公开结果 |

确认后先建立能失败的纯执行测试，再覆盖真实 PostgreSQL 幂等、事务回滚和恢复。类型、仓库依赖检查及既有回归必须通过。未运行的真实模型与部署不记为验收通过。
