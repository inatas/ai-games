# 自然语言规则启动编译方案 v2（待确认）

## 目标和示例

规则作者只写人类语言；服务启动阶段由配置的模型将规则翻译成受限、可校验的机器规则。运行中的房间只使用固定的编译结果，不逐回合请模型重新解释规则。本方案取代此前“严格字段 Markdown + 固定词组注册表”的 v2 草案；现有 TS 规则 v1 仍是实施基线。

目录：`mods/<mod>/rules/v2/*.rule.md`。文件名是稳定规则 ID，文件内容可采用普通 Markdown：

```md
# 预言家首日上警

第一天报名竞选警长时，如果我是预言家且可以报名，80% 的对局必须上警。
其余情况由我根据局势决定。
发言时应结合自己的查验信息解释判断。
```

没有要求作者写 TS、JSON、谓词或选项 ID。文件没有明确概率、身份、时机或动作时，编译器不得猜测强制效果；只能编译为模型引导，或报告歧义要求修改原文。

## 编译产物与职责

启动阶段读取受信任 MOD 规则目录，按文件内容计算摘要。缓存中已有相同 `MOD/规则集版本/源摘要/编译协议版本` 的已验证产物时直接加载；只对新内容调用模型。模型通过现有 `ModelAdapter` 返回受限 JSON，例如：

```json
{
  "id": "seer-first-day-run",
  "when": { "scene": "nominations", "round": 1, "selfRole": "seer" },
  "chance": 0.8,
  "effect": { "kind": "require-option", "action": "nominate", "run": true },
  "guidance": "发言时应结合自己的查验信息解释判断。"
}
```

模型只产出数据，不产出可执行代码、SQL、工具调用、网络地址或任意表达式。Framework 定义 IR Schema、编译生命周期、版本快照、概率、优先级、冲突检测、持久化及审计；MOD 提供允许的场景、身份字段、动作名和参数 Schema，并用现有游戏验证器确认动作合法。未知字段/枚举、身份视角越权、缺失动作、歧义、相互冲突或无法映射合法选项时，不加载该编译结果。自然语言源文件和编译结果都由服务端管理，不从浏览器接收。

## 启动、缓存与恢复

建议在服务器启动的规则准备阶段编译，完成后才允许该 MOD 新建房间。编译结果、源摘要、编译协议版本、模型 profile 与响应摘要持久存储；每个房间固定编译结果 ID 和摘要。重启且源文件未变时使用已验证缓存，不重复付费或因为模型漂移改变老房间。源文件改变时生成新版本，旧房间继续读旧产物。缺少旧产物时停止该房间自动决策并报配置故障，不能套用最新规则。

编译模型不可用、输出非法或验证失败时，不自动启用新规则，也不悄悄退回到不受约束的模型决策；已存在房间若有其固定产物可继续。模型调用需要受信任服务端 profile、请求超时、预算和并发上限，密钥仅在服务端。具体持久表/存储接口与装配点在实施前设计；不在应用启动时自动清理数据。

## 运行时上下文与优先级

已验证 IR 在每次决策中由框架确定性评估；先由 MOD 生成合法选项，策略只可收窄。规则引导文本按真实适用条件和优先级加入**该席位私有**模型上下文，低于游戏硬规则与输出 Schema，不进入公共历史、对手输入或旁观 DTO。强制效果命中且唯一动作已确定时，框架直接提交，不调用决策模型；未命中时正文可作为引导，但不保证模型选择。多个互斥强制效果报冲突，不能按文案或模型偏好暗选。

## 验收与实施顺序

确认本方案后，先写编译缓存/失败、IR Schema、越权、动作映射、版本恢复、并发启动及私有上下文的失败用例；再实现加载、模型编译、持久产物、MOD 能力字典、运行时接入；迁移狼人杀首条规则并移除被替代的 TS 规则文件。验证类型、仓库、隔离 PostgreSQL 集成和全量回归，真实模型编译单列模型/用量/费用证据。首版不做管理 UI、运行中热编辑、任意条件 DSL、女巫 SPEAK 强制声明或模型生成并执行代码。

静态校验可证明产物格式、权限和动作边界，不能单独证明模型完全理解自然语言。应保留“源文 → 编译 IR”的可读预览及差异记录，便于审查错误翻译；是否要求新规则经人审阅后才启用，仍需用户裁定。
