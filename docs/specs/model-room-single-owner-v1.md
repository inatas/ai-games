# 狼人杀模型房间单一调度宿主 v1

状态：待确认。需求入口：[025](../../.agents/note/025-model-room-single-owner.md)；验收：[测试设计](../testing/model-room-single-owner-v1.md)。

## 方案

`WerewolfModelService`在 `migrate/recover` 之前使用专属 PostgreSQL 连接获取固定命名空间的 session advisory lock。锁在服务存续期间一直由该连接持有；关闭服务时释放连接，进程异常退出时由 PostgreSQL 自动释放。不要在模型网络等待期间持有事务锁。

未取得锁的进程以明确的 `MODEL_ROOM_OWNER_EXISTS` 启动失败，不运行 `recover`、不开放模型开局接口、不向供应商发请求；操作者停止旧实例后可重启。取得锁的进程仍按原持久房间与请求幂等逻辑恢复。读取普通观战接口、修改游戏规则和迁移已有数据库均不在本版范围。人工启动说明同步要求切换宿主模式前停掉另一实例；锁作为防误操作的最后一道门。

该锁只约束同一数据库中已实现相同锁协议的 `WerewolfModelService`，不声称阻止旧镜像或外部系统访问模型 API。上线时先停用未实现锁的旧容器/进程，核对只剩一个模型调度者，再切到新版；不能依赖新锁主动驱逐旧服务。服务准备就绪必须包含已持锁状态；失去专属连接时终止调度并使服务不可用，不能静默继续工作。当前历史房间和旧预算失败事件保持原样。
