# 模型上下文前缀缓存与用量观测 v1

状态：用户已确认实施。关联[框架需求 023](../../.agents/note/023-model-context-cache.md)与[验收说明](../testing/model-context-cache-v1.md)。

## 目标和范围

让稳定的框架协议和游戏规则位于请求最前方的独立 `system` 消息中，使相同配置的多次模型调用拥有相同前缀。保留 DeepSeek 返回的缓存用量，以实际数据验证效果。缓存命中由供应商决定，不能作为业务正确性条件。

本次不改变规则引擎、角色权限、模型选择、调用次数、供应商预算与游戏结果；不引入启动时规则编译或新的缓存服务。

## 消息契约

`packages/core` 保持现有权威关系，组装顺序调整为：

1. 固定框架协议 `system`。
2. 稳定游戏指令 `system`，仅放当前 Binding 经授权提供的规则；狼人杀使用定义中的固定规则摘要。该消息内容在同一游戏版本内保持字节稳定。
3. 可选世界观 `system`。现有世界观为游戏配置内容，版本固定；含可变资料的未来扩展须放在动态部分。
4. 当前调用的 `OUTPUT_SCHEMA` `system`；选项或场景导致的 Schema 变化从此处开始。
5. 当前事实、必需记忆、可选历史、玩家输入，维持现有角色与次序。

框架协议继续声明当前事实优于历史、世界观只是背景、模型仅提议结果。游戏规则只能进入已授权席位的上下文；预言家等私有策略指导仍由规则引擎按席位筛选，不提升为全局公共前缀。重复调用与纠正调用须保留前四项原样，仅在末尾追加纠错消息。

狼人杀当前 `definition.instructions` 同时作为 Binding 指令和 `CURRENT_FACTS.context.rules.instructions` 出现。MOD 去掉动态事实中的这份重复规则正文，保留规则版本与事实边界字段。其他调用方仍可通过 `instructions` 提供稳定指令；若某 Binding 每次提供不同指令，其共享前缀自然止于上一条稳定消息，框架不声称可跨请求缓存。

## 接口与数据

`ModelResponse.usage` 保留 `inputTokens`、`outputTokens`，增加可选 `promptCacheHitTokens` 与 `promptCacheMissTokens`。仅 DeepSeek 响应确实提供有效非负整数时写入；缺失字段维持缺失，不能用 0 代表未知。通用协议及 Mock 不要求返回缓存字段。`model.call.finished.v1` 的 `usage` 原样保存新增可选字段，旧日志可继续读取。若供应商两个字段都有值，验证 `hit + miss = inputTokens`，异常时忽略缓存子字段并保留总量。

本版不新增数据库列或迁移；事件日志载荷沿用已有 JSON 结构。重试分别记录每次响应的用量。对外展示若需命中率，可按 `hit / (hit + miss)` 计算，只有两字段齐全且分母大于 0 时展示；此次不增加前端指标。缓存 token 仍计入 `inputTokens`，现有预算预留不因缓存折扣改变。

## 安全与实施顺序

只在模型请求中包含该席位已获授权的规则和事实。模型密钥、响应正文不进入缓存用量记录。消息重排不改变最终执行时的宿主校验。确认后：先写组装顺序、私有信息、缓存字段解析及缺失字段的失败测试；再实现；最后跑定向测试、类型检查、仓库检查与现有集成回归。真实 DeepSeek 试跑需要单独使用已授权的真实调用预算。
