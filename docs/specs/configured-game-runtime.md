## 目标与边界

MOD优先用JSON描述内容、地图规则、动作参数及行为树。首版只支持JSON，加载后严格Schema校验；YAML留作同一数据结构的后续输入适配，不维护两套语义。配置不允许代码字符串、eval、动态导入或客户端上传执行。

配置难以表达的既有规则保留为受信任MOD的短TypeScript函数，通过显式注册ID引用。它们不是沙箱脚本，不声称能安全运行第三方不受信任代码。首版不增加Lua、脚本虚拟机、通用表达式语言、任意效果解释器、插件市场或热加载。

复用现有包、Binding、ModelAdapter、Schema校验、PostgreSQL事务和realm锁。只抽取已有玩法或中性验收场景需要的接口；不新增微服务、消息代理、事件溯源、通用工作流引擎或分布式Actor框架。SSE/WebSocket及前端重做不在本轮，原快照轮询继续可用。

## 三层职责

| 层 | 新增职责 | 不承担 |
|---|---|---|
| platform | 持久事实事件、投递记录、幂等消费基础 | 房间判定、NPC决策、具体游戏规则 |
| game-systems | Actor与Action、地图规则、移动、事件空间策略、NPC调度和行为树 | 门派、技能数值、剧情与奖励实例 |
| MOD | JSON内容、规则参数、行为配置、受信任扩展函数、初始化装配 | 自建可靠提交或直接绕过动作修改运行状态 |

core仍负责通用判定与可靠提交，不导入Actor、地图或行为树。服务器装配事件消费者与调度器。平台的事件收件人由系统策略提供，平台只核验realm与主体合法性。

## 内容与初始化

每个MOD提供一个清单：id、contentVersion、地图文件、NPC文件、行为文件及使用的Action/规则ID。文件路径限定在MOD内容目录内；重复ID、未知字段/处理器、坏引用、无效拓扑均在接受请求前失败。版本固定到运行realm，启动发现不匹配时拒绝服务该realm，不静默改写已有世界。

静态定义与运行实例分开：地图与NPC分别加载，NPC可没有初始位置；位置、revision和行为进度属于数据库。房间表现沿用现有投影，不同时扩展地图编辑器或坐标引擎。

初始化显式分为realm初始化和角色初始化，均在事务内幂等执行；正常启动只装配与加载，不能重复发物品、重置NPC位置或重置行为进度。最小MOD样板提供内容目录、注册入口、两个房间、一个NPC、移动规则与验收说明，不复制框架实现。

## Actor与Action

ActorRef为带类型的引用：character使用scopeId，npc使用realmId和npcId。user是账号，不作为游戏执行者。玩家Actor由服务端会话推导，客户端不能指定NPC或别人的角色；NPC动作只允许受信任调度入口发起，并验证其realm、启用状态和动作白名单。

Action请求包含requestId、actor、actionId、params及预期状态版本。动作注册项包含参数Schema、读取事实、资格判定和事务内执行函数。条件预览与最终执行调用同一规则；预览不代替最终校验。共同移动处理器通过角色/NPC位置适配读写现有表，不新增统一实体表，也不要求NPC具有角色库存和全部玩家能力。

保留Harness的scope执行协调。NPC增加一个服务端专用fw_scope映射，用于请求串行、幂等、租约与可选记忆；它不创建用户、会话或玩家角色，不能经公共账号API访问。所有执行按realm→执行scope→请求锁顺序；模型前读取事实并释放事务，最终提交重验actor、地图/内容版本和相关实体revision。角色沿用现有scope。

同requestId同参数重取结果，不重扣资源、不重发事件；不同参数拒绝。不同NPC有独立scope，共享资源仍遵循realm锁。失败或过期执行不能提交部分变化。Action执行函数负责允许的状态修改，不把任意JSON字段当成数据库补丁。

首个共用Action为move。既有其他行动逐项接入公共执行入口，但保留其MOD规则函数；不借本轮改变成长、战斗、奖励或角色属性方案。

## 地图配置与移动

沿用MapDefinition的房间、出口及版本，出口增加conditions数组，每项为已注册ruleId与严格校验的params，数组为全部满足。首版不提供嵌套布尔表达式；特殊逻辑由一个注册规则表达。旧requirement由青溪接入时直接转换，不保留双入口。

概念配置：

```json
{
  "id": "gate", "from": "square", "to": "hall", "direction": "north",
  "conditions": [{"ruleId": "qingxi.canEnter", "params": {"place": "hall"}}]
}
```

move参数只有exitId，终点由受信任地图决定。检查执行者当前位置、出口起点、终点存在、全部条件及适用能力。NPC没有位置时拒绝移动；未支持的能力默认拒绝，不把NPC当作自动通过者。资源消耗只迁移已有MOD规则，不能因示例配置凭空增加体力或钥匙机制。

成功提交位置与revision、既有必要记忆和actor.moved事件；失败不改变位置或资源。NPC同样经过move，不从行为树调用updateNpc绕过检查；管理初始化不冒充移动。地图可见范围及锁定原因沿用当前契约，秘密条件不在投影中泄漏。

## 事实事件与投递

事件表示已提交事实，不表示待执行命令。最小事件包为eventId、realmId、type、actor、requestId、causationId、chainDepth、contentVersion、payload、createdAt；首批只实现actor.moved与实际接入需要的类型。类型有独立Schema，不建立万能事件字段解释器。

platform_events在Action最终事务内写入，与状态、请求结果及记忆一起回滚。它是运行事件记录，fw_memory仍是按scope检索的记忆，不能自动把所有事件复制到所有scope。

同一事务按受信任策略记录platform_event_deliveries：eventId、consumerId、recipient引用、status、leaseUntil、attempts、nextAttemptAt、errorCode；唯一键为事件/消费者/接收者。空间系统在事件发生时确定知情范围，消费者执行时再确认接收者仍有效且未跨realm。无人订阅仍保留事实，不凭消费时的新位置让NPC获知旧秘密。

服务器使用有界批次轮询待投递记录，短事务领取租约后释放锁再处理。采用至少一次投递：本地消费变化与完成标记同事务；产生后续Action时以投递唯一键派生稳定requestId，崩溃重投只重取原动作。租约过期可重新领取，最多3次投递后标记failed并可查询；网络模型失败不由投递器重新调用，原决策失败记录为终态。不同事件不承诺全局顺序，处理器总是检查当前事实。

任务成功和必须同时发生的奖励仍在原事务处理；不能拆成可能丢失的事件回调。事件订阅通过服务端注册，不向浏览器暴露内部事件表。每条因果链最多4层，每次消费最多派生一个动作；超限终止并记录原因，防止NPC互相无限唤醒。事件/消费历史首版不自动清除，后续按实际容量制定保留策略。

## 调度与最小行为树

game-systems持久化NPC行为状态：realmId、npcId、executionScopeId、behaviorId、contentVersion、enabled、nextWakeAt、cursor、revision及当前决策requestId。首版每个NPC只配置一棵树；无行为配置不启动循环。

节点仅支持selector、sequence、condition、action四种。selector从左到右选择首个成功或运行分支；sequence依次执行，遇失败结束，遇运行保存进度；condition只能引用已注册的确定性规则；action提交已注册Action并返回running，后续根据同requestId结果转为success/failure。每次唤醒至多提交一个新动作，树深最多8、节点最多64，不允许引用成环。

时间唤醒依nextWakeAt；事件唤醒通过已有投递记录触发。多个唤醒合并，由NPC执行scope保证不会同时推进两次。每次唤醒重新检查高优先级条件；分支切换清除旧cursor，已提交动作不撤销，正在处理的动作先等待终态，不能启动第二个动作。失败保留原因，并在配置的正数间隔后重新判断；错过的巡逻时刻不集中补跑。

树本身不访问数据库、不调用网络、不持事务等待动作。巡逻路线由MOD配置为出口序列，当前位置不符时停止该分支并记录失败，不自动寻路或传送。重启恢复当前requestId和cursor，不能重复走一步。首版不做复杂日历、并行节点、子树市场、补偿流程或离线世界模拟。

## 模型在动作前后的边界

前置选择是独立decision步骤：输入只有授权事实与当前允许的动作列表；输出严格限定actionId和params，允许返回不行动。通过现有Harness记录决策结果，再提交独立Action，两步不共享长事务。首版仅提供显式选择入口与一个中性验证案例；行为树无需新增模型专用节点，可引用注册的决策能力。

决定当前Action成败的模型判定继续在该Action的assessment Binding中进行，最终仍重验状态。模型不能决定绕过规则，也不能生成SQL或任意效果。

后置叙述以已提交结果为输入，独立请求，失败显示确定性反馈，不改变原动作状态。生成内容作为非权威展示文本，与事实字段分开；首版不自动写成有效世界事实或把它交给后续NPC充当证据。配置可关闭叙述，默认关闭。

后置反应通过事件唤醒一个新decision/Action，有独立requestId与因果链限制。单个决策最多一次模型调用，沿用已有最多一次格式纠正及超时/预算保护；模型网络失败不自动重试。玩家直接点选和普通NPC巡逻均不需要模型。

实现约束：决策结果标记decisionOnly，叙述标记displayOnly，两者均不能作为新的叙述事实来源。调度器遇MODEL_*终态错误保留原因并停止周期重试，新的外部事件可再次唤醒；没有行为配置的宿主不启动定时循环。后台轮询仅处理有界批次，不提供全局事件顺序保证。

## 数据变更、检查点与升级顺序

新增表由其拥有层迁移：platform负责事件/投递，game-systems负责NPC scope映射与行为状态；现有fw_requests与fw_memory复用。新表唯一约束覆盖投递幂等、每realm/NPC唯一scope与行为状态。不额外建第二套Action请求表。

每阶段编码前核对Git差异和忽略规则，建立包含相关既有状态的本地检查点并记入对应note；未经运行检查不称稳定基线。数据库变更前单独核实本项目开发库/卷，备份并在隔离库验证恢复；代码检查点不能替代数据库备份。遵循未发布阶段破坏性升级政策，不提供旧版回填或双协议；必要时显式重建开发库，启动绝不清库。正常重启必须保留当前版本状态。
