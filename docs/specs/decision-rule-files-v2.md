# 可读规则文件方案 v2（已被自然语言编译提案取代）

本文件记录较早的“固定字段 Markdown + MOD 词组注册表”草案，不再作为当前待审阅方案。当前方案见[自然语言规则启动编译 v2](decision-rule-compilation-v2.md)。

## 目标与现状

用户要求游戏规则文件极简、可由人直接阅读，不把 TypeScript 谓词和选项查找代码当作规则配置。当前 v1 实现位于 `mods/werewolf/src/decision-rules/`，它仍是已实现基线；本方案获确认后，以可读规则文件替换该配置入口。通用执行器继续归 `packages/turn-based`，不解释游戏词语。

## 文件和格式

MOD 使用 `mods/<mod>/rules/v1/*.rule.md`。文件名是不随展示文案改变的规则 ID；`v1` 是整套规则的版本。首个文件拟为 `mods/werewolf/rules/v1/seer-first-day-run.rule.md`：

```md
# 预言家首日上警
适用：预言家在首日上警报名
优先级：100
概率：80%
执行：上警

首日应积极争取警徽，发言时结合自己的查验信息说明判断。
```

只有标题、四个固定元数据字段和一段自然语言正文；不支持代码、任意表达式或通用 YAML 特性。`概率`与`执行`可同时省略，此时规则只向模型提供正文引导。写了`执行`时，概率缺省为 100%。自然语言正文只影响本席模型上下文，不参与动作合法性判断，不被当作游戏事实。`优先级`只在同一决策中排序规则，不越过游戏硬规则。

## 框架与 MOD 分工

- 框架按服务端可信目录加载 UTF-8 文件，严格解析字段、校验重复 ID/未知字段/概率与优先级，按版本与内容摘要固定房间规则集；按优先级执行、稳定抽样、冲突检测和内部审计。启动/开局前发现格式错误应拒绝该规则集，不跳过错误文件继续运行。
- MOD 提供一个小型、受信任的**词汇注册表**：将完整的`适用`值映射为触发谓词，将`执行`值映射为从当次合法选项中定位动作的函数。狼人杀只注册“预言家在首日上警报名”和“上警”等该游戏用到的词组。未注册词组在加载时拒绝；不让模型解释触发条件或自行编造动作。
- 框架只把当前席位实际适用规则的正文按优先级加入该席位的私有模型上下文，附规则 ID/版本；不进入公共历史、其他席位输入或浏览器 DTO。若强制选项已由框架直接提交，本次不调用模型，正文也无需发送。概率未命中时，可以把正文作为引导送给模型，但不声称该次必须上警。
- 已开局房间固定规则集版本及内容摘要。部署文件更新后，旧房间恢复必须找到原版本与摘要；找不到则报告配置故障，不悄悄套用新文案。规则判定和游戏动作仍沿现有原子提交与固定截止处理。

## 实施范围与顺序

确认 v2 后：先写失败的加载/校验、词汇映射、上下文隔离和数据库恢复用例；再实现通用文件加载与规则解析、MOD 词汇注册、决策上下文装配；迁移 WW-R01 到 Markdown 文件，删除被替代的 TS 规则配置入口，并更新全部调用方。旧代码无需兼容，但当前版本房间正常重启的数据约束保留。无管理 UI、运行中热编辑、模型自动生成规则、SPEAK 声明强制或真实付费模型调用。

## 验收边界

文件读起来能独立说明规则；未知字段/词组、重复 ID、越界概率和同级冲突均失败且不提交动作；本席适用正文进入模型上下文，其他席位及公共视图不可见；80% 判定与 v1 一样稳定；已固定房间不能被新文件改写；强制规则命中仍由游戏验证器校验合法动作。具体用例和证据回填根 note 022 与狼人杀 note 002。
