# 输入上下文预算 100K 字节 v1.1（2026-09-23 已确认）

## 目标与单位

将现有 `buildContext`/Harness 的默认输入容量，以及狼人杀模型房间的明确容量，统一提高到 **100,000 UTF-8 字节**。`conservativeCounter` 仍按每条消息正文的 UTF-8 字节数加固定协议开销计数；此数值不是供应商 tokenizer 的 token 数，也不声明供应商模型窗口必然足够。用户已明确选择字节单位。

## 改动范围

- 通用 `buildContext` 默认 `inputBudget=100_000`、内部预算窗口默认 `window=128_000`。现有 `min(inputBudget, window-outputBudget)` 约束保持；通用默认输出预留仍为1,500。显式传入更小或更大的预算/窗口仍按原接口生效，不擅自覆盖宿主策略。
- 狼人杀模型房间的 Harness 装配明确使用 `inputBudget=100_000`、`modelWindow=128_000`，保留 `outputBudget=500`、原调用/总时限和模型支出预算。无网络模拟对局采用同一组输入/窗口参数，避免“演示8K、正式12K”的口径不一致。
- 保持必需内容不可静默裁剪。只有可选记忆仍按剩余预算筛选；100K也装不下时继续在调用适配器之前返回 `CONTEXT_TOO_LARGE`，由游戏在原阶段截止后按默认动作处理。原日志事件 `model.context_rejected.v1` 与真实调用区分保持不变。

不更换计数器、不压缩历史、不改变六区授权内容、Schema、输出 token 上限、供应商路由或数据库结构。更大的输入可能增加供应商费用/响应时间，也可能超出实际模型窗口；后续用户另行授权了单局真实供应商调用，实测结果见[运行说明](../model-robot-run.md)。单局通过不等于任意长局均可装入供应商窗口。

## 接口与风险边界

不新增公共接口或持久字段。`inputBudget`、`modelWindow` 仍由受信任服务端设置，用户请求不能改写。输出预留和模型超时不变；供应商拒绝超长输入时按现有受控失败处理，不能伪装成功。事件日志仍记录最终实际提交的请求，便于检查容量增加后是否仍触发拒绝。
