# 房间制回合游戏框架（v1与v2已实现）

归属：[需求019](../../.agents/note/019-turn-based-matches.md)。

## 定位

### 连续阶段窗口扩展（v1，已实施）

需求：[032](../../.agents/note/032-shared-stage-deadline-and-failure-continuation.md)，2026-10-09 已确认并实施。业务分支与参与者由宿主定义，框架只保存时序及提交边界。

Phase.windowGroup 为非空字符串。Room.windowGroup 保存 {key,startedAt,deadlineAt,durationMs}；初次入组以 windowMs 建立，相邻同 key 复用原期限且不能改变 durationMs，新 key／离组建立正常窗口。phaseStartedAt 为当前步骤开始，phaseDeadlineAt 为原组截止，actionDeadline 不越过它；固定等待可复用而不额外调用模型。到期 fallback 应直接离组，不串联新的过期步骤加时；恢复不重新计时。

RoomDefinition.fallbackOnFailure?(room):boolean 默认 false；只有控制器终止失败、启用该钩子且有 fallbackDecision 时才立即接受默认动作。失败原因先登记在 pendingJobs，不伪造模型返回。授权／宿主／数据库异常仍停止并保留真实错误，不用默认动作掩盖。未启用沿用原到期默认。minDecisionTimeMs?(room):number 指派发所需最少剩余时间；不足时记跳过原因并使用既有默认动作，不调用供应商。规则明确选项先于模型准入。

Decision.origin 为 model／script／rule／default／external；acceptDecision 增加可选来源参数，默认 external。运行时真实入口赋值，主输出不能覆盖来源。接受动作、来源、窗口及后续阶段在同一短事务保存；模型等待不持锁，scope／epoch／恢复沿用原契约。

fallbackDecision(room,seat,reason?) 的可选 reason 区分 GAME_DEADLINE（截止结算）、INSUFFICIENT_TIME（准入不足）和已记录的终止错误码。宿主据此决定续接还是直接离组；原二参调用方不受影响。startPhaseWindow 为公共纯计时入口，运行时在持久化阶段转换的同一事务使用；固定等待通过宿主准入／默认动作收集，不产生供应商调用。

RoomDefinition.revealEvent?(event):boolean 可限制非公共事件终局展示；缺失仍按现有终局公开，公共事件不隐藏，actorView 的原席位权限及可信 inspect 保持。日志、网络重试及附加记忆不换协议。验收见[窗口扩展测试](../testing/turn-based-matches.md#连续阶段窗口与失败续接v1已实施)。

2026-09-20用户明确要求编写基于房间的回合制游戏框架，不强制整合当前MUD框架，最底层统一。本架构方向与下述v1契约已确认并实现；v2抢占增量亦已获明确确认并实现。

第二层由两种并列框架组成：现有MUD框架，以及独立的房间制回合游戏框架。两者共同使用第一层基础能力，各自拥有运行模型、游戏状态和客户端视图。第三层通过相应框架的公共接口接入。本文仅定义第二层职责与契约，使用题材中性的示例；具体游戏规则和接入说明归对应MOD文档。

```text
第三层        MUD类MOD                 回合制MOD
                  │                        │
第二层        MUD游戏框架           房间制回合游戏框架
                  └──────────┬─────────────┘
第一层                 统一基础框架
              模型 / 身份与授权 / 存储 / 可靠提交
```

独立包packages/turn-based（公共入口@game-ai/turn-based）承载回合框架，packages/game-systems继续承载MUD能力。房间制回合框架不依赖game-systems，不要求ModHost的MUD WorldView、地图房间、NPC表、任务或行为树。两个第二层框架不互相导入；应用层按游戏类型装配。

统一底层意味着复用现有core/model/storage/identity/platform中适用的公共能力，不复制模型适配、scope隔离、幂等和事务机制，也不要求所有游戏启用聊天、队伍或钱包。公共契约若包含MUD专属假设，在后续设计中明确抽离边界及调用方变更；不在底层增加具体游戏身份、动作语义或阶段规则。

这里的房间是承载一局游戏的逻辑房间，不是地图房间或语音房间。每个room独立运行，宿主决定创建和调度哪些房间；当前接口支持AI座位，不提供真人匹配或大厅。

## 核心能力

1. 房间与座位：定义人数、入座状态，全部AI座位配置就绪后自动开局。
2. 对局生命周期：等待、进行、结束及失败状态；保存对局进度，正常重启不重复开局。
3. 回合与阶段：由游戏定义阶段、执行顺序、行动资格与推进条件。
4. AI角色：每席绑定一个LLM配置，拥有独立身份、上下文和私有记录；相同模型也不共享私有信息。
5. 信息视角：区分公开信息、角色私有信息、阵营信息；服务端构造各角色能看到的上下文。
6. 动作与结算：AI提出行动，游戏规则校验和结算；公共系统保证提交与恢复一致性。
7. 旁观与复盘：进行中只提供公共视角；结束后开放身份与隐藏行动复盘。隐藏数据不能提前发送到浏览器。

## 分层归属

| 层 | 职责 |
|---|---|
| 基础层 | 模型调用、授权、存储、事务及可靠提交 |
| 第二层：MUD框架 | 地图、NPC、任务等现有持续世界能力 |
| 第二层：房间制回合框架 | 独立的房间、座位、对局、阶段调度、AI隔离和记录投影 |
| 第三层：游戏MOD | 人数、动作语义、业务规则、信息投影和终局条件 |
| 应用装配 | 启动房间、调度对局、提供只读旁观页面 |

## 后续设计事项

新增能力必须描述为独立通用契约，并用中性测试验证。具体阶段图与规则实例由MOD维护，不作为框架协议正文或范例。当前不设计通用DSL、多游戏编辑器或全局框架重写。

验收方向：满员开局、阶段按规则推进、角色信息隔离、同轮未公开选择不泄漏、提交幂等与重启恢复、终局前后旁观权限切换。v1实现与验证证据见需求019；v2新增验收不与既有证据混用。


独立性验收：仅装配统一底层、房间制回合框架和中性测试游戏时即可运行完整对局，不加载MUD框架或创建地图/NPC/任务表；依赖检查禁止两个第二层框架互相引用。现有MUD回归单独验证。


## 按实际需求抽取共用系统

2026-09-20用户明确：背包、道具等将来可能被多个游戏框架使用，出现实际需求后再抽象。当前保留已有系统归属，不为未来复用预先搬迁库存、设计统一道具协议或建立新的公共系统包。后续由多个游戏的具体需求确定共同契约，再决定共享模块的位置；不得让两个游戏框架为复用某个系统而互相依赖。统一底层不等于将所有可设想的共用玩法系统立即下沉。

## 实施契约 v1（2026-09-20）

用户已以“按定下的边界，开始编码”授权实施通用框架。本节记录已批准的v1实现契约，不包含具体MOD规则或UI。

- 独立入口@game-ai/turn-based，只依赖core公共入口及Schema校验；宿主注入既有HarnessStore和按profile配置的ModelAdapter。无MUD、platform表或真人账号依赖。
- RoomDefinition为受信任代码：人数、初始化、阶段计划、角色投影、动作Schema/资格校验、阶段结算及终局投影。MOD回调是同步纯计算，不允许持事务等待网络。
- Room有唯一runKey及规则id/version；满员自动从waiting转running。每座位独立fw_scope，modelProfile由服务端白名单映射。相同runKey/座位参数幂等，不同参数冲突。注册未知模型、越界座位、变更已开始配置均拒绝。
- 每阶段有独立递增实例号、round、公开名称、sequential或sealed收集模式、执行座位列表。sequential按列表顺序决策并可公开发言；sealed收齐前不发布本阶段事件给其他席位，结算只执行一次。MOD阶段结算返回下一阶段或终局结果；系统不解释游戏角色。
- 表tb_rooms保存对局及持久待执行请求，tb_seats保存独立scope映射；tb_rooms JSONB保存MOD状态、有序事件和阶段收集记录。全部写入在短事务锁定room后操作，锁顺序room→scope→Harness request。不复制底层幂等/模型纠正/租约逻辑。
- tick一次推进最多一个座位决策。登记时持久化requestId、输入快照、模型profile及memoryVersion，释放事务后交给Harness。并发调度共享同一请求；最终apply重验当前阶段和requestId，原子提交状态、事件、有效记忆和请求结果。已提交不重调；未提交响应丢失不能保证模型供应商计费一次。
- 模型失败/非法动作后blocked，无自动重新调用或随机代打；受信任宿主显式resume后允许创建新请求。恢复先处理Harness过期请求；未过期请求等待原租约，不重复调用。预算按最大阶段数和最大决策请求数限制，超限aborted且不揭密；调用超时/上下文限制复用Harness。
- 公共读取spectate只返回白名单座位信息、公共阶段名、公共投影及可见事件，不发送私有状态或内部job。正常finished才加入复盘投影和隐藏游戏事件；blocked/aborted不揭密。actor上下文包含授权投影和公开/本人事件；不从旁观复盘DTO生成。HTTP及会话鉴权由后续宿主装配，当前不提供公网路由。
- 所有接口为服务端API；trusted inspect/actor接口不得直接映射到未鉴权HTTP。正常重启不清库；新增表显式迁移，无旧库删除。

验收正文见[框架测试契约](../testing/turn-based-matches.md)。
