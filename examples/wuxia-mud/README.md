# Quickstart：青溪镇武侠世界

已实现世界MVP v2：12个房间、5名NPC、3类复用场景、局部SVG地图、寻药任务、背包与成长。每用户拥有一个持续保存的独立江湖，不是多人共享世界。

## 启动与游玩

在仓库根目录运行：

```sh
docker compose up --build -d
```

打开[江湖一隅](http://localhost:3000/)，输入用户名和密码；新用户自动创建，已有账号恢复当前存档。默认保持登录，右上角登出。旧角色保留属性及往事，升级时首次安置在村口，不强制开新局。

点击场景人物或下方同名按钮查看操作；出口按钮负责移动。地图可拖动、缩放及回到当前位置；点击地图节点仅查看，不会瞬移。浅色节点是可见但尚未探索的相邻地点。手机界面切换地图、场景、行囊与任务；移动时保持所选面板。

推荐从新档走一遍：

1. 村口→青石街→药铺，点击药师并接受寻药委托。
2. 药铺→广场→山道→林地，查看并拾取药包；背包出现药包，地面物品消失。
3. 沿原路返回药铺，交付药包，任务完成且银两+2。
4. 到广场，接济村民两次：银两共-4、侠义达到2。
5. 到武馆请求拜师；AI选择ACCEPT时武学+1、师承青松道人；DEFER也是合法结果，可继续历练。
6. 武馆后院可切磋，武学≥2获胜且银两+3。拜师后可进入内室。
7. 溪边查看旧石碑触发一次奇遇；GIFT银两+4，GUIDANCE武学+1。

在假定拜师ACCEPT、尚未奇遇的新档路径中，第6步后属性为银两21、侠义2、武学2。移动也会记录事件并增加版本，不再使用旧四动作演示的固定五步版本计数。刷新或重新登录恢复位置、背包、任务和历史；“另起一段江湖”经确认后才新建存档。

## AI与游戏的分工

交谈、拜师、奇遇使用模型；移动、任务、物品、行善和切磋由游戏计算。交谈按本地见闻主题选择有限answerId，界面展示受控模板，不是无限自由对白。可填写一句补充说明帮助模型判定，它不会被解释为任意游戏命令。

默认Mock固定选择GUIDE/ACCEPT/GUIDANCE，无需模型Key；真实模式复用仓库配置的服务端模型适配。页面明确显示当前模式。详见[开发指南](../../docs/development.md)。

## 开发接入

| 文件 | 职责 |
|---|---|
| [world.ts](src/world.ts) | 房间、出口、NPC内容、配置校验及局部图投影 |
| [scene.ts](src/scene.ts) | 当前scope的世界状态读取、场景对象与可用动作 |
| [game.ts](src/game.ts) | 增量迁移、初始化、严格行动Binding与事务内规则执行 |
| [Web视图](../../apps/web/src/world-view.tsx) | SVG地图、三类场景素材、对象选择和出口操作 |

游戏通过@game-ai/*公共入口使用Harness；框架不反向导入武侠规则。prepare在短事务中读取当前事实，模型等待不占数据库事务；apply重新检查版本、位置和资格。NPC不是常驻Agent。

新增同类房间只修改游戏内容配置：稳定ID、模板、坐标和显式出口；双向需要两条出向记录。坐标不决定可达。部署内容变更须按需求流程设计内容版本兼容，不直接覆盖旧存档版本。
