# 未发布阶段的破坏性升级

适用场景：结构/API/存档调整、兼容代码处理、数据库初始化、迁移、开发库重建或数据恢复。实施前同时加载[开发确认](development-approval.md)、[实施与安全](implementation-and-validation.md)，涉及大改时加载[Git检查点](git-checkpoints.md)。

用户已明确确认：当前不保证旧代码、旧API或旧存档兼容。结构调整直接更新全部调用方与测试，移除被替代的入口、迁移回填与兼容分支。数据库按当前结构初始化，必要时允许重建本项目开发库；不在应用启动时自动删除数据。删除前仍须核实具体数据库/卷及项目归属，不得影响其他项目。正常重启须保留当前版本数据，鉴权、事务和幂等保护不可作为兼容代码删除。
