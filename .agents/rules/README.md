# 项目规则索引

任务开始时先读本索引，再按实际工作范围加载命中的规则全文，不默认加载全部正文。任务涉及多个场景时同时加载；范围扩大或发现新的触发条件时，必须在执行相应操作前补读。已读取且未变化的规则在同一会话内无需重复读取。

| 场景 | 必须读取的规则 |
|---|---|
| 新增功能、需求调整、方案审阅、开发实施或续做（含next/继续），处理提前实现 | [开发方案确认与实施门禁](development-approval.md) |
| 架构/代码评审、模块规划、代码或文档归属、需求编写、跨包/MOD接入 | [目录职责与文档归属](repository-layout.md) |
| 代码/可执行测试修改、运行检查、模型接入、数据库或部署操作 | [实施、验证与安全](implementation-and-validation.md) |
| 计划或开展跨模块重构、核心替换、大范围迁移、界面重做、实现重写 | [大改前Git检查点](git-checkpoints.md) |
| 结构/API/存档兼容调整、数据库初始化/迁移/重建/恢复 | [未发布阶段的破坏性升级](breaking-changes.md) |

只读查询、普通Git同步、纯排版或失效链接修复不因该任务本身触发开发审批；若转入功能开发或其他列出的操作，先补读相应规则。按需加载不表示规则可选或允许绕过门禁。

AGENTS.md提供加载入口及文档归属、开发顺序的总说明，本目录维护各场景的详细规则正文；ARCHITECT.md维护架构与依赖约束，需求note记录具体方案、确认范围和进度。MOD继承项目规则，并按目标目录的AGENTS.md（若存在）补读本地指引；不能另建相反的审批流程。规则缺失或存在影响当前操作的冲突时先说明并处理，不猜测规则内容继续操作。
