# 需求：公共账号与持续档案

Status: implemented

## 需求

用户使用用户名密码登录；不存在时自动创建，默认记住登录。每用户只有一个当前游戏档案，长期保存操作结果，主动新建才开始新局；右上角提供登出。

## 范围

框架公共账号、持久会话、授权和当前档案管理，宿主只初始化题材状态。设计版本v1已获用户确认，详见[设计](../../docs/specs/accounts-worldview.md)及[测试设计](../../docs/testing/accounts-worldview.md)。不包含找回密码、第三方登录及历史档案切换。

## 验收

### v2 新角色失败反馈与恢复（已确认，待实现）

- 重置接口返回的 `SCOPE_BUSY`、`STATE_CONFLICT`、`IDEMPOTENCY_CONFLICT` 等错误必须传递到界面，不能统一显示为“新角色尚未确认，请重试”。
- 客户端保留的重置请求在 4xx 失败后清理；成功响应后以返回的 `currentScopeId` 恢复当前档案并重新读取世界。
- 重复提交同一 requestId 仍遵守服务端幂等契约，不创建第二个角色。
- 新角色确认弹层点击“取消”必须关闭弹层，并清理尚未提交的本地重置请求；已提交中的请求仍可通过明确的重试入口恢复。

- [x] U-01至U-09：自动注册、密码校验、持久会话、退出和隔离。
- [x] U-10至U-14：新局原子性、幂等、并发和行动切换边界。
- [x] U-15至U-17：界面恢复、用户切换及旧游客数据保留。

## 当前进展

公共identity模块、Cookie会话、单一当前档案、事务授权和浏览器登录组件已实现。Docker回归28组通过；浏览器登录、刷新续玩、登出、重登、新局确认已实测。见[验证记录](../../docs/verification.md)。
