# 需求：可组合的多游戏上下文

Status: draft

## 需求

框架应为不同游戏组装不同的世界观、背景故事、场景、玩家与NPC当前状态、长期记忆和本次任务，使游戏只提供题材数据与权威状态，不重复实现上下文顺序、预算、安全隔离和审计。

## 范围

多游戏Context Profile、版本绑定、静态资料块、宿主动态状态块、NPC选择、记忆检索、固定优先级、预算与调用清单。框架不解释游戏语义、不计算NPC状态、不把NPC记录自动实例化为Agent、不用自然语言规则代替宿主validate/apply。详见[设计v1](../../docs/specs/context-composition.md)及[测试设计](../../docs/testing/context-composition.md)。

## 验收

- [ ] CTX-01～04：不同游戏及版本严格隔离，静态和动态块顺序稳定。
- [ ] CTX-05～08：NPC实时状态、可见性、事实优先级与模型修正调用一致。
- [ ] CTX-09～12：必需/可选预算、缺失来源、注入防护与确定性。
- [ ] CTX-13～15：调用清单可追溯，无AI动作不组装，现有世界观平滑迁移。

## 当前进展

现有实现只支持scope绑定的一份完整世界观、宿主`facts`、记忆和输入，能证明基础顺序与预算；尚无通用背景资料块、NPC快照协议或逐块调用清单。已完成v1设计与测试说明，等待用户审阅，未修改实现代码。

## 待完善

待确认Context Profile/Block接口、静态资料采用JSON清单加Markdown文件、动态NPC状态由宿主prepare提供、调用清单单独持久化等方案。确认后先生成CTX行为测试，再实现。
