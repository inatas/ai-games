# 029 发言意图与行动命名统一

Status: implemented

## 需求与归属

用户要求统一使用 `SPEECH`，不再在同一发言链路中混用 `SPEAK`、`speak`、`speech`。任务意图 `DecisionInput.intent/current_action.request_type` 是跨 MOD 的通用契约，因此由框架层拥有；狼人杀的裁判行动接入见[狼人杀需求 008](../../mods/werewolf/.agents/note/008-public-evidence-and-terms.md)。

## 方案 v1（已实施）

统一命名规则：**任务类型**用大写 `SPEECH`，与 `SELECT` 并列；**字段与游戏内部类型**用小写 `speech`，包括模型输出 `{speech}`、MOD 行动 `{kind:'speech',text}`、公开事件 `type:'speech'`、阶段名和配置键。`SHERIFF_CAMPAIGN_SPEECH` 等场景名保留。动词只允许在自然语言说明中出现，不作协议枚举值。

将通用 `DecisionInput`、`current_action.request_type`、模型／脚本分支、规则匹配、默认提交及审计日志中的任务值从 `SPEAK` 改为 `SPEECH`；MOD 裁判行动 `kind:'speak'` 改为 `kind:'speech'`，更新全部生产调用方、脚本、测试夹具和当前契约文档。其他动作、语义、超时及游戏结果保持不变。具体协议与验收见[Robot 模型运行时](../../docs/specs/robot-model-runtime-v1.md)和[狼人杀模型接入](../../mods/werewolf/docs/model-integration-v1.md)。

当前项目处于未发布阶段，不增加旧枚举兼容分支。修改持久房间的行动格式和定义版本前，先检查实际运行中房间；不得因部署自动删除或重建房间。若有运行中房间，先提出可核对的处理方案，不让正常重启悄悄改写其规则。无数据库表迁移、密钥、付费模型调用或 UI 功能变化。

## 范围

统一框架决策意图与狼人杀发言行动命名；输出正文键仍为 `speech`。旧协议房间须在部署前另行核对，不能隐式迁移。

## 验收与实施顺序

- ST-01：框架只接受 `SPEECH | SELECT`；`SPEAK` 不再作为任务类型输入或输出。
- ST-02：狼人杀模型、脚本、超时默认和裁判均产出／接收 `kind:'speech'`；发言正文仍为 `{speech}`，200 字边界不变。
- ST-03：公开发言、警长发言及遗言事件的语义、顺序和旁观展示不变；回放与日志使用当前命名。
- ST-04：全仓运行时／测试夹具无旧协议枚举和旧行动类型；历史讨论文档可保留旧词并标记为历史。
- ST-05：检查真实房间状态及部署前后恢复；不自动清理旧房间。类型、仓库、单元与隔离数据库回归通过。

用户确认具体方案后，按仓库规则先写失败测试，再改通用契约与 MOD 调用方，完成回归并回填证据。
