# 020 Robot用户目录

Status: implemented

## 需求

Robot是具有独立userId的用户。用户确认按沟通结果产出座位工具与robots，先写note再开发。

## 范围

根目录robot-users/users存放每用户JSON，assets存放素材。默认12个独立UUID用户，含昵称、性别、头像、立绘、固定初始人格、随机脚本控制配置和固定短句。modelProfile预留为null，本轮不调用模型、不生成人格。

配置不保存登录凭据、资产、好友或对局记忆。UUID与现有用户标识形式一致，未来账号和社交落库另行接入。本轮不注册真人账号数据库。默认复用三套获授权的素材。

应用服务端严格校验目录及素材边界，只投影公开资料；MOD接收类型化阵容，不反向读取根目录。用户不绑定狼人杀身份，开局再分配身份。资料快照随本局保存，换座后头像和昵称按用户保持。

## 验收

唯一ID和受支持配置校验；公开投影不泄露控制配置；随机补满保留已有成员；12名不同用户才能手动开局；重复开局请求幂等；整局发言与资料按用户阵容展示。

### v3：Robot模型席位运行时方案（2026-09-22，待确认，仅文档）

用户要求给出“对robot user的模型调用、模型路由、上下文组装输入、结果输出”的方案。已核对现状：`RoomRuntime`已按`Seat.modelProfile`逐席路由，`model-profiles/*.json`只保存环境变量名，但服务端缺profile→适配器装配层与Robot→席位绑定；调用时序、截止默认与编解码属[运行时v3](../../docs/specs/turn-based-model-runtime-v3.md)提案；上下文机制见[Context Composition](../../docs/specs/context-composition.md)；狼人杀场景与SELECT/SPEAK契约见[MOD方案](../../mods/werewolf/docs/model-integration-v1.md)。

方案正文：[Robot模型席位运行时v1](../../docs/specs/robot-model-runtime-v1.md)。四段要点：

- **路由**：profile定义（仅env变量名）→启动期Registry装配（缺env、非法或重复即启动失败，不在局中降级）→开局把Robot的`control.modelProfile`写入席位；脚本席位映射为内置`script-fixed`/`script-random`，与模型席位共用同一注册表；`DemoRooms`无模型演示基线不动。
- **调用**：只由受信任宿主驱动；短事务登记→释放锁→Harness调用→校验→原子提交；绝对截止点、网络失败不重试、密封阶段按席并行、阶段切换与抢占使旧响应失效；新增按profile的token/费用预算。
- **上下文输入**：MOD决定该席授权投影（六区加persona/roleStrategy），core决定装配顺序与预算，model包只接收messages；必需内容不截断，超限在调用前失败并走默认结算。
- **结果输出**：严格Schema校验＋业务二次验证＋解码＋单事务提交；SELECT只执行`selected`，`candidates`仅内部日志，非法selected等同无合法输入并在截止点默认结算。
- **安全**：密钥只在服务端环境，公开投影不泄露profile、人格与战术标签；未就绪profile的用户保持不可选且不降级为随机脚本。

验收RM-01～RM-12见方案正文；实施顺序为确认范围→Git检查点→中性失败测试→profile装配与席位绑定→v3运行时→MOD上下文与编解码接入→分层验证。本轮只写文档，未改实现代码与可执行测试、未调用模型、未建检查点。

待裁定：首个profile/供应商/试运行席位与并发、请求/token/费用预算；脚本席位是否并入注册表；ContextManifest是否本轮落地；模型局路由前缀与页面形态；人格来源范围；v3与MOD方案v1.6是否与本方案同批确认。据此，v1“真实参赛需扩展模型运行时、合法个人视角、输入输出、截止默认与请求失效并明确试运行模型及预算”的后续需求已具备可审阅方案，仍为待确认。
