## 开发方案 v1.2（2026-09-23，待确认）

用户审阅 v1 后指出公共列不应使用座位号与内部 scope 表示发起人；应以通用 `user_id` 标识真人或 Robot，以 `mod_id` 标识游戏类型，以 `room_id` 标识该 MOD 的游戏实例。狼人杀 `room_id` 为对局房间 ID；武侠 `room_id` 为 realm ID。`seat_id`、`scope_id`、phase 等归扩展详情，不作为公共列。用户随后增加两项要求：日志本身应足以还原一局回放；NPC 动作和通用系统定时任务下一期讨论。因此 v1.2 增加完整回放帧与实例内提交顺序，删除拟议公共 `initiator_type`，本轮仅记录用户动作和为对局回放不可缺少的游戏裁判自动结算（`user_id=null`、详情注明原因），不接入 NPC 或通用任务日志。

唯一契约见[统一执行事件日志 v1.2](../../docs/specs/execution-event-log-v1.md)，验收用例见[EL-01～EL-16](../../docs/testing/execution-event-log-v1.md)。本 note 管公共日志、Harness、回合运行时及持久查询接口；狼人杀无模型审计演示的接入见[本地001](../../mods/werewolf/.agents/note/001-ai-spectator-mvp.md)。

本次范围：PostgreSQL 追加式执行日志；底层统一 `append(tx, event)` 与受信任分页查询；Harness 的准备、模型尝试和结果记录；用户发起的平台事实事件；回合房间的开局完整资料、每次已提交变化的可回放帧、脚本/模型提交、默认结算及阶段推进；从日志独立读取完整狼人杀公共回放和授权席位回放，不能再读当前房间状态；狼人杀使用同一模型上下文装配路径、可控模拟模型完成对局，并提供仅本机可读的审计检查入口。当前平台事实事件、房间可见事件和 `fw_model_calls` 不被改写成日志；日志事件本身不触发游戏消费。明确不包含真实供应商调用、NPC 动作、通用系统定时任务、旧局补录、日志前端、外部分析平台与生产管理员系统。

接口、数据、状态与边界：通用事件信封分离唯一 `eventId` 和稳定 `eventType`，携带 `userId/modId/roomId/requestId`、发生时间、结果码及受限 `details` JSON。回放事件另有实例内严格递增 `streamSequence`；开局帧、已提交后完整旁观/授权视角帧、计时边界与终局揭密都在日志中，回放只读日志。状态变更与对应帧同事务；模型请求发出前后分别记录尝试与输出，失败也能留痕，但不得使失败的游戏状态变为有效。请求幂等键约束重复写入；原始上下文和原始输出始终内部级，不能出现在旁观、对手上下文或普通游戏历史。密钥和鉴权头不得进入日志。具体表、索引、长度、保留与查询规则见契约。

验收：先写可失败的中性数据库行为测试，覆盖帧与状态原子提交/回滚、重复请求、多宿主并发、恢复、实例流顺序、分页、权限和密钥排除；再验证 Harness 记录的是**实际传给适配器的最终 messages**、Schema 和原始返回，不是事后重建摘要；最后在不启用网络模型的狼人杀 Demo 中走完一局，删除/屏蔽房间当前状态后，仅凭日志重建与原局一致的公共和席位回放，并检查私密信息水位、调用场景和截止默认。真实 PostgreSQL 与演示证据单列，不以 Mock 代替供应商实测。

实施顺序：用户确认 v1.2 范围 → 保存当前工作区 Git 检查点（现有未提交改动须保留，密钥与运行日志不提交）→ 中性失败测试 → 通用日志表/API → Harness 与房间运行时接入 → MOD 审计 Demo/回放入口 → 类型、全量回归、真实数据库与全局演示验证。当前只写方案，未改实现、测试、数据库或运行配置，也未发起真实模型调用。

## 开发方案 v1.3（2026-09-23，待确认；取代上述 v1.2）

用户明确第一期**不做用户侧业务事件**，只解决所有大模型调用的 event log；以后再考虑把通用信封扩展到周边业务。因此本期不做业务打点、日志驱动回放、NPC/通用定时任务审计或支付场景。v1.1/v1.2 中的相关需求记录保留供未来讨论，但其中设计文档已按本期范围重写，不能将旧正文当作当前方案。唯一当前设计见[模型调用事件日志 v1.3](../../docs/specs/execution-event-log-v1.md)，验收见[EL-M01～EL-M10](../../docs/testing/execution-event-log-v1.md)。狼人杀本地无网络验证见[MOD接入](../../mods/werewolf/docs/event-log-audit-demo-v1.md)。

以通用信封 `event_id/event_type/occurred_at/user_id/mod_id/room_id/request_id/result/details` 为主；每次实际进入 `ModelAdapter.generate` 的 attempt 都有请求开始事件和结束/失败事件，记录**实际传给适配器的最终 messages、Schema 与 token 上限**，以及原始返回、模型名、token 用量、耗时、错误码。房间调用从受信任席位绑定获得 Robot `user_id`，详情记录 `seat_no`、`mic_no`（发言麦序；非发言阶段为空）、本席身份与阶段；跨游戏调用缺少适用字段时为空，不伪造。密钥、Authorization 头和对手私密数据不得暴露到浏览器；完整日志仅内部查询。现有 `fw_model_calls` 用量摘要并入新日志，不保留两个冲突的权威源。

先用实际 PostgreSQL 和可控本地模型适配器验证零网络费用的整局：按每个 `request_id + attempt` 抓取适配器收到的请求，与日志逐字段比较，并检查狼人杀玩家/身份/麦序、成功/失败/纠正及信息水位。测试先行、幂等、崩溃恢复和旧尝试不得伪装成功。当前仅修订文档；未改实现、可执行测试、数据库或运行配置，未调用正规模型。

实施顺序：用户审阅确认 v1.3 → 保留现有工作区的 Git 检查点（秘密不入库）→ 可失败行为测试 → 公共日志结构与 Harness 插桩 → 狼人杀元数据接入及本地模拟验证 → 全量检查与真实 PostgreSQL 测试。此前 v1.2 关于完整回放的设计不在本次编码范围。
