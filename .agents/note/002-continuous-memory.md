# 需求：综合持续记忆与上下文组装

Status: proposed

## 需求

角色不持续占用模型会话，仍能在后续交互中引用过去事实、摘要和未了事项；历史事件只是事实，不自动实例化为Agent。

## 范围

事实投影、不可变事件、摘要、开放事项；scope/可见性过滤；必需来源、可选历史去重排序及预算。宿主决定触发时机与当前事实，MVP不做embedding、自动压缩或剧情定时器。

## 验收

- [ ] F-19/20：预算排序正确，必需超限明确失败。
- [ ] F-21/22：作用域隔离与持久恢复。
- [ ] F-23/25：事项只关闭一次，来源合法并同事务提交。

## 当前进展

[存储](../../packages/storage/src/postgres.ts)使用统一fw_memory表区分kind；[上下文](../../packages/core/src/context.ts)按来源和预算组装。中性数据见[契约](../../docs/testing/fixtures.md)。

## 输入上下文 100K 字节 v1.1（2026-09-23，待确认）

用户查看无网络狼人杀审计演示后要求将输入上下文放大到100K；经追问明确单位为 **100,000 UTF-8 字节**，不是100,000模型token。此为当前上下文预算行为的增量调整，原v1.3模型日志与游戏规则授权不自动覆盖实现。详细方案见[输入预算100K设计](../../docs/specs/context-budget-100k.md)和[验收用例](../../docs/testing/context-budget-100k.md)。本节尚未获方案实施确认，未改代码、可执行测试或运行配置。

拟改通用Harness上下文默认输入预算由8,000升至100,000、默认内部窗口由16,000升至128,000（均沿用现有保守字节计数），保持输出预留、必需块不可截断、可选记忆按预算裁剪、显式宿主覆盖与超限前拒绝。狼人杀模型服务由12,000明确调到100,000，同时传128,000窗口；本地模拟审计采用相同配置。不会改供应商协议、真实模型价格/支出上限、游戏计时和事件日志格式；不承诺特定供应商支持100K输入，真实供应商调用仍须另行核查。实现顺序：确认本方案→先写失败边界测试→改默认与狼人杀装配→无网络整局审计→类型/仓库/全量回归。

确认记录：2026-09-23 用户针对已提交的“输入上下文 100,000 UTF-8 字节 v1.1”明确回复“确认启用 100K 方案”，并要求接入 DeepSeek API 完成一局浏览器可见的实测。本次按上述范围实施；真实调用仍受已确认的人民币10元持久预留上限约束。方案文档原“本期不发起真实供应商调用”仅描述原定验证范围；此次额外实测由用户当前指令授权。
