# 需求：可复用的 AI 决策规则引擎

Status: draft；开发方案 v1 待确认（2026-09-23）。

## 目标与范围

框架统一运行 MOD 提供的决策规则集，使模型和脚本 Robot 在相同授权事实、合法选项和阶段期限下遵守可执行的策略约束。用户已确认方向：规则集的注册、管理、顺序和执行机制归底层框架；具体游戏的触发条件与规则效果归 MOD。此方向确认不等于下述接口和实施范围已获批准。

本次拟实施通用 SELECT 规则：规则集版本固定、启停、作用域、优先级、冲突检测、确定性概率判定、选项约束、提交重验及私有审计。适用于模型和脚本决策。具体协议与中性验收见[设计 v1](../../docs/specs/decision-rules-engine-v1.md)和[测试说明 v1](../../docs/testing/decision-rules-engine-v1.md)。狼人杀接入另见[MOD 需求 002](../../mods/werewolf/.agents/note/002-decision-rules.md)。

本版不包含管理 UI、用户运行中热改规则、通用条件 DSL、SPEAK 语义/身份声明强制、跨 MUD 与回合游戏的统一调度、真实模型付费运行或部署。游戏硬规则、行动超时默认及现有决策协议保持各自权威；策略规则不能扩大合法动作集合。

## 模块、接口与状态

- `packages/turn-based` 的纯规则执行器接收 MOD 在服务端注册的版本化规则集、当前授权决策快照及原始合法选项，返回受约束的选项集、命中记录和可选的确定动作。框架不导入 MOD，也不解析游戏角色名。
- MOD 用受信任代码提供触发谓词和选项效果；框架验证其输出引用原合法选项，不接受模型或公共事件提供的规则定义。宿主仅装配规则集，不从浏览器修改规则。
- 规则集由 `id + version` 标识，开局固化到房间配置；每次概率判定由稳定键 `room + seat + rule id/version + occurrence` 得出并持久化结果。重复调用、恢复与双宿主使用同一结果。规则执行记录仅进入内部审计。
- 排序键为级别、显式优先级、稳定规则 ID；同级互斥的强制规则为配置错误，不静默选择其中一条。概率命中后的强制效果与普通强制效果同样受冲突检测。偏好仅用于模型输入，不保证输出；首版不把偏好解释为强制。
- 游戏先生成合法选项，再执行策略规则；模型/脚本在有效候选中决策。提交时按同一房间版本与规则判定复核，最后由 MOD 再验游戏合法性。过期响应沿用现有拒绝机制，失败/超时仍按 MOD 已定义的阶段默认处理，不由策略规则重写裁判时间。

## 实施顺序与验收

待明确确认本方案及 MOD 002 后，先写中性失败行为测试，再实现框架纯执行与房间持久判定，随后接入决策准备/提交及 MOD，最后运行类型、仓库、单元和真实 PostgreSQL 并发恢复验证。未获得确认前不修改实现或可执行测试。

验收重点：不同 MOD 可注册不同规则且框架无题材词；策略只缩小合法集合；概率同局稳定且跨恢复一致；冲突明确失败；模型和脚本得到同一约束；旧响应不能越过新阶段；内部审计不进入公共/对手视角；未触发规则时行为与现状一致。具体用例见测试说明。
