# 024 模型对局 Token 用量记账

Status: implemented；方案 v1（2026-09-24）。

## 需求

用户要求模型账单按供应商成功响应返回的实际 input/output token 记账，按房间汇总；本项目不再换算人民币，费用控制由 API 端负责。同时要求解决当前宿主机模型请求的 `EACCES`。现有 10 元预留账本只是估算，250 次失败调用仍累计 9.986936 元预留；它不是供应商实付账单。

## 范围

本方案只修改狼人杀模型房间的用量统计与本地接入，不改变游戏决策、规则集、模型上下文、供应商计费或其他游戏的预算策略。具体设计见[Token 记账 v1](../../docs/specs/model-token-accounting-v1.md)，验收见[测试设计 v1](../../docs/testing/model-token-accounting-v1.md)。

## 模块、数据与状态

- `packages/core`现有 `model.call.finished.v1` 事件持续保存供应商 `usage`、`room_id`、`request_id`、模型名与是否模拟；不修改该事件格式。供应商成功返回即计入，即使输出后来未通过游戏校验；失败、尚未返回和脚本决策均不计入。
- `apps/server`不再为狼人杀模型房间装配 `BudgetedModelAdapter` 和 `ModelBudgetLedger`；启动不要求价格环境变量，不换算人民币。旧 `ww_model_budget` 表保留原数据但停止写入；本版不删除或清零。
- `WerewolfModelService`按 `room_id` 汇总真实、非模拟且已完成的模型事件，并通过仅本机可访问的只读用量接口返回输入、输出 token 与报告/未报告 usage 的成功调用数。以事件为单一事实源，不另写汇总表；重启和重复查询保持同一结果。
- 网络接入使用可访问 DeepSeek 的宿主机服务启动环境；密钥仍只存在服务端。此项为已批准的本地模型服务运行故障修复，不改公网权限边界。

不包含供应商账单对账、人民币金额、自动限额、Token 估算、历史失败调用的补记或公开旁观页展示。旧预留额不代表实际扣费，也不迁移成 Token。

## 验收

确认方案后先写失败行为测试，再移除狼人杀价格装配、实现按局查询与本机接口，更新本地运行说明；运行单元、类型、仓库与隔离 PostgreSQL 集成检查。真实模型调用只在用户授权的实际对局中验证，不由自动测试发起。边界用例见测试设计。

## 当前进展

先写行为测试并观察到用量接口 404、汇总模块缺失；随后实现按房间完成事件聚合与本机查询，撤掉狼人杀服务的预留适配器、价格变量及旧预算表迁移。旧表与 9.986936 元历史预留未清零、未更新。单元 118/118、隔离 PostgreSQL 完整套件 223/223、TypeScript、仓库检查与构建通过。

4318 已从允许外网的环境重启并恢复现有房间。当前房间首次真实 `model.call.finished.v1` 报告输入 3,332、输出 147 token，按局接口返回相同数值、`reportedCalls=1`，并有对应裁决事件；旧预留值仍为 9.986936 元。真实供应商账单金额未在本项目核对。

同日后续故障排查：用户新开房间后仍见AI无反应。发现旧版Docker `app` 容器仍在后台运行，虽无4318端口映射却与宿主机新服务连接同一PostgreSQL；它在新房间写入18次旧`MODEL_BUDGET_EXCEEDED`失败并给阶段留下失败决策。已只停止该旧`app`容器，保留PostgreSQL和宿主机服务；失败数随后保持18，成功模型完成事件由13增至26，4319代理能读取最新房间进度及公开上警发言。旧失败席位需按原阶段截止点结算，不倒改历史动作。

确认记录：用户审阅方案 v1 后回复“实施”，确认按完成事件汇总、仅本机查询接口、缺失 usage 单列不估算，并停用本项目 10 元预留限制。
