# 需求：关键交互中的私有判断与记忆传递

Status: implemented

## 需求

用户要求框架在每次关键交互中，允许模型一边返回受严格校验的主结果，一边更新当前交互主体的私有判断与记忆。下一次属于同一主体的交互能读取已提交的判断；附加记忆格式错误不能让原本合法的主结果失效。框架只负责授权、校验分流、存取与提交，不解释判断内容。

## 范围

方案 v1.1，**用户已确认并实施**。这是可选的通用 Harness 能力，由受信任宿主逐类交互启用。`Binding.privateMemoryUpdate` 的 `factKey` 标识当前 scope 内的记忆事实；纯函数 `parseUpdate(proposal, facts, previousPayload)` 独立验证附加输出并返回完整的新载荷，普通格式错误返回 `null`。宿主自行决定附加字段名称、内容结构、来源规则和长度上限；框架不内置题材术语、交互种类或判断算法。

宿主的输出 Schema 仍严格要求主结果，顶层仅额外容许一个可选、宽松 JSON 附加字段。框架先确认整份响应可解析且主结果符合原 Schema 与宿主业务校验；再独立检查附加内容。附加内容缺失、空值或内部格式错误时只放弃记忆更新，不触发模型纠正调用，也不阻断主结果。整份 JSON 无法解析、响应超限或主结果不合法时，继续走现有失败路径；受信任解析代码自身异常和数据库故障仍按基础设施错误处理。

在组装上下文时，框架仅从本次 `scopeId` 读取 `factKey` 且 `visibility='internal'` 的已提交记忆，存在时放在原有后部必需记忆区；不增加新的输入协议段，也不放进跨主体共享前缀。主结果进入当前有效版本的提交事务后，框架重读同 scope 的当前事实；有效附加更新以 `replace_fact` 写回该 scope，与主结果、请求终态原子提交。重复请求复取同一结果，超时、过期、冲突或主结果被拒绝时不产生有效记忆。未配置此能力的交互维持现状。

此版不建新数据库表，不额外调用模型，不向公开输出投影私有记忆，不跨 scope 复制记忆，不把历史观点提升为当前权威事实。具体内容格式、何种交互启用、私有记忆的生命周期由宿主定义。

权威接口与时序见[框架规格](../../docs/specs/framework.md#关键交互私有判断更新-v11已实施)，中性验收见[框架测试](../../docs/testing/framework.md#关键交互私有记忆-v11已实施)。

## 验收

- [x] 中性 Binding 的合法主结果与格式错误的附加输出同返时，主结果正常提交、旧记忆不变；合法附加输出与主结果同事务提交。
- [x] 同 scope 后续交互读取最新内部 fact；另一个 scope、共享上下文段及公开投影不能读取，首次无 fact 时照常运行。
- [x] 重复请求、超时、旧版本、业务拒绝与事务回滚都不能留下新有效记忆。
- [x] 原有主结果严格校验、完整 JSON 限制、错误分类与调用次数保持；未启用该能力的 Binding 行为不变。
