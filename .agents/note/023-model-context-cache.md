## v3 已实施（2026-09-26）：共享知识、私有职业指南与动态规则分段

用户要求模型输入按以下相对顺序：当前板子背景规则 → 当前板子的全部职业描述 → 狼人杀通用词汇（每词一篇，全员加载）→ 本人职业操作指南 → 当前命中的 ruleset。前三类对同板子所有模型席位相同，职业指南只给本人，ruleset按职业、阶段与条件匹配。公开历史仍可插在共享知识和本人指南之间，扩大跨席位可复用前缀。具体 MOD 内容、文件与授权见[狼人杀需求 008 v1.3](../../mods/werewolf/.agents/note/008-public-evidence-and-terms.md)；中性消息契约与验收见[缓存设计](../../docs/specs/model-context-cache-v2.md)、[缓存测试](../../docs/testing/model-context-cache-v2.md)。

拟扩展 `Prepared.promptParts`：有序 `sharedKnowledge`、当前席 `privateKnowledge`、本次匹配 `matchedGuidance`。通用 Harness 仅按受信任宿主给定顺序组装，不读取狼人杀文件，也不判断职业或匹配条件；MOD负责来源、排序、权限和规则版本。现有 `stableGuidance` 作为场景规则前置消息的语义与用户顺序冲突，v3 将它迁入本人指南之后的 `matchedGuidance`，不再把条件匹配的 guidance 放在全员共享知识之前。已实现的 v2.1 是历史基线，实施 v3 后同步更新规则配置、全部调用方和测试，不留两套当前消息布局。

具体顺序：通用固定协议 → 板子背景 → 全职业描述（稳定 ID 顺序）→ 全词条（稳定 ID 顺序）→ 同水位共享公开历史 → 本人职业指南 → 当次 ruleset guidance → 动态输出 Schema → 当前席位事实／选项／私有事件 → 记忆和输入。需要额外世界观时，仍遵守其授权与预算，具体插入点由框架文档裁定。本人的职业指南也是稳定文本，同职业、同板子后续请求可复用，但不得出现在其他职业或公共旁观数据中。规则集的硬约束仍由决策引擎执行，不仅靠模型提示。

本扩展改变通用上下文接口和消息布局。用户审阅 v3 及关联方案后回复“ok”；已按跨模块改动规则建立本地 Git 检查点，先观察失败测试再实施。消息组装、规则装配及缓存布局版本已迁移，部署和真实模型 KV 命中率仍待检验。

2026-09-26 实施确认：用户审阅狼人杀 v1.3、框架缓存 v3 及 SPEECH 命名方案后回复“ok”，确认按这三份方案实施。跨模块改动前已在 `main` 建立本地检查点 `4d49421`（`checkpoint: before layered werewolf knowledge integration`），包含当时已存在的工作区修改；仅通过暂存差异空白检查，未将检查点称为测试稳定版，未推送。

## 已确认扩展 v2.1（2026-09-26）：稳定指导前置

用户在狼人杀发言规则方案后确认“保障kv缓存的命中率，私有内容尽量靠后放置”。原有通用 guidance 只出现在动态 `CURRENT_FACTS`，无法把所有席位相同的发言规范做成共享前缀。v2.1 已在通用规则配置增加可选 `placement: stable`（仅限 `guidance`）；匹配后把此类规则按优先级放入独立 system 消息，位置为固定游戏规则之后、共享公开事实与动态 Schema 之前。未标记的角色专属 guidance 继续放后部私有当前事实。仅受信任 MOD 配置可标记稳定规则；框架不得从发言文本推测共享性或把角色、昵称名单、当前行动挪入稳定段。

框架 `Prepared.promptParts` 可选携带已匹配的稳定指导，`buildContext` 在固定游戏规则后输出；不改变规则匹配、作用席位、模型权限或事实权威性。排序、恢复与 token budget 沿现有机制，缓存命中仍为供应商尽力而为。中性验收：共同稳定指导字节一致、在公开历史/Schema/私有事实前；未标记规则保持私有后置；无命中规则时原消息布局不变。狼人杀接入及 200 字上限见[MOD 007](../../mods/werewolf/.agents/note/007-speech-output-rules.md)。定向单元、隔离 PostgreSQL 全仓 241/241、类型、仓库检查与前端构建均通过；真实供应商命中率未测试。
