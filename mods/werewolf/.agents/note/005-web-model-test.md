# 005 网页模型对局测试台

Status: in_progress；**v1 已确认，实施中**（2026-09-25）。确认依据：用户审阅网页 v1、日志 v2、缓存 v2 后明确回复“编码，并启动网页让我测试”。

## 需求

用户希望通过网页配置并启动真实模型对局，查看阶段流程与终局回放；每次成功或失败的模型 API 调用要能查日志，并观察当前不足 20% 的 KV 缓存命中情况。现有网页可配置十二座 Robot、种子并开局，能看旁观流程和终局历史；模型 profile 由 Robot 文件固定，网页无模型调用诊断；上次临时测试库清理后日志不可再查。接入设计见[网页测试台 v1](../../docs/web-model-test-v1.md)，底层日志和缓存分别见[框架 021](../../../../.agents/note/021-event-log.md)、[框架 023](../../../../.agents/note/023-model-context-cache.md)。

## 范围

本次拟实施：现有座位管理选择已配置的可用模型 profile 并冻结到新房间、显式开局；进行中看阶段和公开事件；终局复用现有对局历史和身份揭晓；新增测试口令保护的模型诊断面板，能筛选座位、阶段、成功/失败/未发出，查看请求、响应、错误码、延迟和实际 token/cache 数据；刷新与服务重启后可按房间 ID 继续查看。网页不编辑模型密钥/URL，不改规则、阶段计时、模型服务启动方式，不把私有请求放进公共历史。

## 接口、数据与状态

只展示服务端登记的 profile ID/显示名/可用状态；开局请求增加每座 `profileId`（脚本席为空），校验其与座位、Robot 类型、服务端配置匹配，房间持久化 profile 绑定并沿用开局幂等键；同 key 不同阵容或 profile 返回冲突。测试房间使用现有持久模型房间，普通时钟自动推进；开局后页面收藏房间 ID 并可手工输入 ID 恢复，避免仅靠浏览器 sessionStorage。阶段流程和回放仍来自游戏房间快照，诊断日志来自 `fw_event_log`，两者不是同一种事件。测试过程不删除房间或日志，用户以后显式清理。

网页展示“供应商已返回”“供应商调用失败”“已返回但裁判未接受”“尚未发出”“结果未知”五种状态，不将模型返回等同有效行动。私密日志和原始 context 只在本机诊断 API 与页面出现，普通旁观和终局公共回放继续按既有权限。确认后先写行为/边界测试，再接服务端配置和诊断投影、网页，最后真实对局验证。详细边界验收见[测试说明](../../docs/web-model-test-testing-v1.md)。
