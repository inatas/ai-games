# 008 公开证据链与狼人杀术语

Status: proposed

## 需求与确认依据

用户提出：同一回合无人对跳的预言家、女巫通常更可信；可信预言家报的好人可被多数玩家视为金水，可信女巫报的获救刀口可被视为银水，但银水可能是狼人自刀。随后用户确认将这类提炼内容作为后续判断和发言的可追溯上下文，并为模型补充固定名词与推理边界，要求本轮产出文档和 note。

本需求属于狼人杀 MOD。它使用框架现有稳定规则前缀、公开历史和席位私有事实分段；本轮不提出新的跨 MOD 框架协议。现有代码仅区分裁判事实与玩家发言，尚不自动提炼身份主张、同回合对跳或金水／银水证据。

## 方案 v1（文档稿，实施范围待审阅）

目标是让每席模型在后续发言和选择时看到**可追溯的公开线索**，并保留自行站边、怀疑和改变判断的空间。具体术语、来源、结构及验收见[游戏规则](../../docs/mvp-design.md)、[模型上下文](../../docs/model-integration-v1.md)和[游戏验收](../../docs/mvp-testing.md)。

1. 在狼人杀 MOD 的版本固定规则文本中增加简短术语表：金水、查杀、银水、对跳、无人对跳、狼人自刀。定义区分“真身份的实际结果”与“公开发言中的声称”。该文本随规则版本固定，放在共享公开历史和私有事实之前；不按座位或当前轮次变化。
2. 从**已经公开**的事件和发言构造公开证据条目，记录来源事件序号、发言人、目标、昼夜／回合、原始声称及提炼类型。发言事件本身只证明“某人说过”，绝不认证身份、查验或用药。只对明确、无歧义的公开语句提炼；未识别或歧义表述保留原文，不臆造条目。
3. 仅在相关回合的发言机会全部结束后，才可由公开身份主张形成“本回合未观察到对跳”的**条件性线索**；回合未结束时标记为待观察。之后出现对跳、翻牌或相反的权威公开结果，重建线索状态，不覆盖原始证据。无人对跳只提高该身份主张的可信度，不证明其为真。
4. 金水／银水是依赖来源玩家可信度的**玩家视角判断**，不写入裁判公开状态的实际阵营字段。真预言家实际查验为好人在本板型中就是好人；公开报验则仍是一条未经认证的主张。真女巫所报的获救刀口是被狼队选中的目标；即使报刀口可信，也不能推出目标是好人，因为允许狼人自刀。
5. 每次模型请求按该席当时可见的事件水位重建公开证据链，作为有区别标记的推断记录加入现有共享 `public_history`，不改变通用框架消息协议；本席私有已执行动作及结果仍只放后部私有上下文。给模型的证据条目包含来源序号和状态，不给其他席位额外私密信息。不写公共“可信度分数”或全体共享的站边结论；每席可基于相同公开证据形成不同判断。

本版建议在 MOD 内作确定性、保守的公开发言识别与投影，不增加独立抽取模型调用、数据库表、RAG／向量库、公共 UI 评分、强制站边或按关键词审判发言真假。具体识别语法与证据数据字段在实施审阅时以模型上下文文档为准；自然语言覆盖不足时原文仍在 `public_history`，不把“没识别到”说成“没人说过”。

### v1.2 增量：按板子维护知识库，与场景规则分离（待审阅）

用户明确知识库应由人配置，内容是对应板子的**标准玩法、公开职业说明和圈内通用术语**；它与按场景匹配的策略 `rules` 不同。v1.1 拟议的 `mods/werewolf/rules/game-knowledge.md` 因不能表达多板子归属而撤回，尚未创建。v1.2 拟使用 `mods/werewolf/knowledge/boards/<board-id>.md`，当前固定板子的文件名为 `12p-seer-witch-hunter-idiot.md`。一个板子对应一份完整、人工可读的 Markdown；新增板子时增加对应文件和板子 ID 映射，不按发言、投票、身份或阶段拆分加载。内容分“标准玩法”“公开职业”“通用术语与推理边界”，向该板子的所有模型席位提供同一固定文本。角色专属战术和仅本人可知的实际身份、查验、用药仍不进入知识库。

MOD 在新局确定板子 ID，服务启动时读取对应文件、校验非空并计算摘要；本局的板子 ID 与知识版本固定，拼入现有游戏规则后的稳定前缀，先于公开历史和私有事实。编辑文件后重启服务，仅后续新局采用新内容；运行中房间不热替换，重启恢复前需核对版本，不自动改写。`mods/werewolf/rules/ruleset.json` 继续作为**场景规则**入口，按当前决策的身份／场景匹配，负责策略指导、强制选项及 `speech.maxChars`。知识文件是模型解释文本，不执行裁判动作；实际身份、用药、计票与结算仍由 `src` 的裁判逻辑决定。若修改了玩法含义，须同步更新裁判及测试，不能仅编辑知识文件。文件不得包含当局座位、秘密、密钥或会变化的事实。具体内容结构与输入顺序见[模型接入文档](../../docs/model-integration-v1.md)。

本 MOD 的行动从 `kind:'speak'` 统一为 `kind:'speech'`，模型任务从 `SPEAK` 统一为 `SPEECH`；通用契约的所有者见[框架需求 029](../../../../.agents/note/029-speech-terminology.md)。不改变发言上限、阶段计时或已公开事件语义。旧运行中房间处理遵照框架 note。

### v1.3 修订：四层知识库及规则顺序（本次待确认范围）

用户纠正 v1.2 的单文件方案，指定四层独立的 Markdown 内容及先后顺序：

| 顺序 | 人工目录 | 加载范围 |
|---|---|---|
| 1 板子背景规则 | `knowledge/boards/12p-seer-witch-hunter-idiot.md` | 按当前板子 ID，所有席位 |
| 2 职业描述 | `knowledge/roles/{wolf,villager,seer,witch,hunter,idiot}.md` | 按板子实际包含的全部职业，各席相同、稳定排序 |
| 3 通用词汇 | `knowledge/terms/<term-id>.md`，首批金水、刀口、银水、查杀、对跳、退水、自刀 | 狼人杀 MOD 所有词条，全部席位、全部板子，稳定排序 |
| 4 职业操作指南 | `knowledge/guides/{wolf,villager,seer,witch,hunter,idiot}.md` | 仅本人真实职业的一篇，不提供其他职业指南 |

板子文件仅说明板型、阵营目标、公开流程与房规；职业描述说明该职业**公开可知**的能力及限制，不写“谁是该职业”；词条解释圈内话语及边界，不写当局事实；操作指南可给当前职业的玩法建议，但不包含其他角色的私有资料、实际查验、夜间操作或当局座位。人直接编辑 Markdown，不写 TS、条件表达式或规则执行代码。板子配置的职业集合从 MOD 创建对局所用的权威阵容读取，首次仅支持当前固定十二人预女猎白板；不在本次新增第二种可玩的板型。新增板子以后由该板子的权威阵容决定要加载哪些职业描述，不能靠手工列表和裁判阵容并行维护。

文件装载器在服务初始化／首次构造定义时将目录读入并固定快照：检查板子文件、全职业描述、本人指南与词条均非空，按稳定 ID 排序，拒绝缺失、重名、越界路径；所有词条逐篇统一加载。知识摘要覆盖文件 ID、顺序和内容，纳入房间定义版本；服务重启后编辑生效，运行中房间不热改。由于现有服务每次以定义版本恢复房间，部署前须检查正在运行的房间；版本不匹配时拒绝恢复，不自动删除或用新知识重解释旧局。无数据库表变更、知识检索服务或额外模型调用。构建产物需包含 Markdown 文件并能从本机与 Docker 同一路径读取。

职责和接口拟定：`server/knowledge-loader.ts` 只负责文件读取、校验和进程内快照；`src/knowledge.ts` 只负责依据受信任的板子 ID、权威阵容职业集合和本人真实职业，纯函数选出有序共享知识与一篇私有指南；`werewolfDefinition` 接收已冻结的知识快照并把板子 ID／摘要写入定义版本。当前板子 ID 固定为 `12p-seer-witch-hunter-idiot`，可在 `MatchOptions` 缺省使用该值；不接受未知板子 ID 或宣称另一阵容。模型服务恢复房间时从已存定义版本核对板子 ID／知识摘要，不能由浏览器 seat 参数决定本人指南。脚本与模型共用同一决策权限，但仅模型请求组装知识消息；旁观与公开事件不接收指南。纯游戏裁判仍不读取 Markdown，也不由 Markdown 驱动身份分配或行动合法性。

消息顺序及通用接口见[框架需求 023 v3](../../../../.agents/note/023-model-context-cache.md)：固定协议 → 板子背景 → 全职业描述 → 全词条 → 共享公开历史 → 本人职业指南 → **当次命中的 ruleset** → 动态 Schema 与本席事实。公开历史插在共享知识与私有指南之间，以保持同公开水位的跨席位前缀；知识四层及 ruleset 的相对顺序严格符合用户指定。`rules/ruleset.json` 继续按职业、进程与条件匹配；现有 `speech-language` 的 `placement: stable` 将迁出全员知识前缀，作为命中 SPEECH 时的规则放在本人指南之后。`require-option` 仍由规则引擎执行，不变成知识文本。

本次拟实施知识文件、装载与授权、通用分段、规则消息顺序及既有 `SPEECH` 命名统一；**此前 v1 的公开证据链提炼不在此次知识库实施范围**，保留为后续待审阅能力。知识文件不改变裁判判定，修改板子玩法仍需同步修改 MOD 规则和测试。

## 验收与实施顺序

- WW-E01：固定术语定义和事实边界在稳定规则前缀，跨席位字节一致；动态座位、事件与私有资料不进入此前缀。
- WW-E02：明确公开身份主张、报验、报刀口产生带来源的证据；含糊发言不生成未经证实的身份、查验或救人事实；原始发言保持可追溯。
- WW-E03：回合内未结束时不能宣称无人对跳；同回合结束后若确无可识别对跳才形成条件线索；出现对跳或后续公开反证时更新状态，旧来源仍保留。
- WW-E04：金水与银水均标记为依赖来源的判断；银水保留狼人自刀可能，不成为阵营真相；不同席位可形成不同站边。
- WW-E05：按席位授权与公开水位重建，重启和重复请求结果一致；未公开刀口、药、查验不泄漏给其他席位或旁观者。
- WW-E06：真实模型局抽样检查后续发言能引用来源并随新证据更新；自动测试不能替代此项。
- WW-E07：当前板子的人工知识文件在所有席位与所有场景中均进入相同稳定前缀；改动文件并重启后仅新局使用新摘要，运行中房间不热改；缺失或空白时拒绝新局启动。不同板子只装载各自文件，不串用术语或职业。
- WW-E08：`SPEECH` 任务、`{speech}` 输出和 `kind:'speech'` 裁判行动贯通五类发言场景；旧 `SPEAK`／`kind:'speak'` 不再作为当前协议值。
- WW-E09：当前板子六种职业描述全部进入所有席位；职业列表与实际板子阵容一致、按固定 ID 排序；本人指南只出现一篇，其他职业指南及其私有策略对本席不可见。
- WW-E10：所有词条逐篇、按固定 ID 顺序加载到每席；新增词条改摘要，不需修改场景匹配逻辑；词条、板子和公开职业内容均在公开历史及本人指南之前。
- WW-E11：同一板子不同职业的前三层知识和同水位公开历史字节相同；本人指南之后才出现命中 ruleset；SPEECH 专属 guidance 不进入 SELECT，也不提前进入共享前缀。
- WW-E12：内容缺失、空文件、重复 ID、版本不符及预算超限有明确错误；本机和 Docker 构建均携带文件；编辑后重启不热改旧局，且不产生数据库变化或额外模型调用。

若用户确认该具体实施范围，再先写失败的行为测试，实施 MOD 术语配置、证据提炼与上下文投影，运行定向回归、类型／仓库检查及真实模型抽样。文档稿确认不等于代码实施授权。
