# 006 警长竞选共用退水窗口

Status: implemented；开发方案 v1 已确认并实施（2026-09-26），网页真人新局待复核。

## 需求与现状

用户明确裁定：“警上全员发言结束，进入一个10秒的退水阶段，所有上警的人都应该在这个时段退水，然后锁定上警名单开始警长投票”。现行实现是发言后按候选人逐个退水，每人固定 20 秒；页面沿用“警长竞选”标签，造成重复且不清楚的等待。此规则裁定尚不等于对下面实现方案的确认。

游戏规则归[狼人杀设计](../../docs/mvp-design.md)，计时归[阶段时间](../../docs/phase-timing-v1.md)，默认动作归[行动截止](../../docs/action-deadlines-v1.md)，验收归[游戏测试契约](../../docs/mvp-testing.md)。这些既有架构文档维护统一正文，本 note 记录 feature 范围和开发进度。

## 范围

以下为已确认的实施范围 v1。

警上报名 → 逐人发言 → 全体候选人共用一个 10 秒退水窗口 → 锁定候选名单 → 未上警者警长投票 → 原有 PK 与结算。单候选报名继续直接当选，不增退水等待。第一爆跨夜恢复竞选时，为仍有资格的候选人重新开启一次共用窗口。

狼人杀 MOD 的 `election-withdrawal` phase key 保持，阶段 mode 改为现有框架的多人 `sealed`，`actors` 为窗口开始时全部合资格候选人，统一行动与阶段截止点。每人可提交一次 `{kind:'withdraw',withdraw:true|false}`；10 秒内未合法提交者由裁判按 `withdraw:false` 结算。即使全员提前提交，窗口仍到边界才结束，不重新计时；Robot 并发收到自己的任务。

窗口结束后一次性按稳定座位顺序处理全部选择，再根据最终候选人数判定：0 人警徽流失，1 人自动当选，至少 2 人进入投票。不能在批量处理的中途因暂时只剩 1 人提前宣布当选。原报名者即使退水，仍无警长票；投票开始后名单冻结。结算前个人退水选择不公开，结算时仍以既有 `sheriff-withdrawal` 事件披露退水者。

狼人可在原有退水阶段通过独立通道自爆；成功抢占使窗口内未结算选择失效，原单爆/双爆规则不变。迟到响应、超时兜底、服务恢复沿用框架当前阶段实例与持久截止点，不新增框架接口或数据库表。改变游戏定义版本；旧版进行中房间结束后才部署新定义，不为旧存档写迁移或兼容分支。

页面显示“警长退水”和一次共用倒计时，不显示独占操作席位；候选头像标记在窗口中保留，到结算公开退水后取消。若展示进度，只能展示汇总人数，不能提前泄露个人选择。历史继续使用既有公开退水事件。

本版不改其他 20 秒动作、上警发言和警长投票时长、夜间计时、模型协议或其他 MOD。
