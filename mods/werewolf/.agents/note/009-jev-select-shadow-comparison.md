# 009 JEV 与现有模型的 SELECT 旁路对比

Status: proposed

## 需求与归属

用户希望未来用 TypeSafe AI 的 JEV 快速处理 `SELECT`，`SPEECH` 仍由现有生成式模型完成。切换前先在真实狼人杀对局里，对每次模型 `SELECT` 按同一份已授权上下文额外调用 JEV，保存两方结果供人工比较。首版不得改变现有决策、规则执行、截止结算或发言。此能力只服务狼人杀 MOD，复用框架现有模型调用事件日志，不修改通用模型协议。

## 方案 v1（已确认实施）

设计正文见[模型接入](../../docs/model-integration-v1.md)，日志与故障边界见[模型诊断](../../docs/model-test-observability-v2.md)，验收见[诊断测试契约](../../docs/model-test-observability-testing-v2.md)。

本次仅实现狼人杀服务内部独立的后台比较器：读取已持久化的 `model.call.started.v1` 请求，识别模型席位的 `SELECT` 且只取首个尝试，以原始 `ModelRequest.messages` 顺序构造 JEV `state`，从合法 `selected` 枚举和当前行动选项构造 `choice.criteria`。向 TypeSafe 官方 `/v1/systemone` 调用 `jev-latest`，结果、概率、置信度、usage 和安全错误信息作为私有事件追加到现有 `fw_event_log`，以原 `request_id` 关联。单独的启用开关与密钥环境变量只在服务端；无密钥时服务不启动该比较器。每个 `(request_id, attempt=1)` 至多一组旁路事件；重启可补做未完成任务，但不重放已有终态；已开局的历史请求不追溯调用。

比较器不向 `RoomRuntime`、Harness 或裁判回传结果，不修改现有 `ModelAdapter`、DeepSeek 请求或 `SPEECH`；JEV 失败只记私有失败事件。首版日志用于人工对比，不在网页自动计算“谁更正确”或启用 JEV 决策。操作员可以通过已有房间事件详情查看两方原始结果；若需要专门的并排页面，另行审阅。

密钥仅放当前用户专用的 `~/.codex/ai-games-model.env`，由 Compose 注入后端；不写仓库、数据库、日志或网页。用户在本次会话提供了密钥，方案确认并实施时迁入该文件，操作过程不输出其内容。密钥已出现在会话中，之后可由用户在供应商端自行轮换。

## 范围与不包含

- 包含：官方 JEV API 适配、上下文转换、私有旁路日志、去重和重启恢复、本机启停配置、失败隔离与可对比查询。
- 不包含：JEV 实际控制游戏、`SPEECH` 双调用、通用框架改造、额外对局自动启动、自动质量判分、历史房间回填、对已有凭据和日志的清理。

## 验收与实施顺序

- [x] JS-01：同一 `SELECT` 的 JEV `state` 包含原模型请求的完整有序消息和同一合法选项集；不扩展本席权限。
- [x] JS-02：`SPEECH`、脚本 Robot、规则强制选项和非狼人杀调用均不触发 JEV。
- [x] JS-03：JEV 成功/无效响应/HTTP 失败和超时分别留下可关联的私有日志；成功记录选项、概率、置信度、实际 usage，日志不含密钥和错误原文。
- [ ] JS-04：JEV 失败或慢响应不在游戏决策链中；重复扫描不重复收费调用，孤儿调用不自动重试。真实运行中重启行为仍待新局复核。
- [ ] JS-05：真实网页新局的两方调用可按房间、席位、阶段和同一 `request_id` 对照，记录实际调用数量、延迟和 token；未实测不得标为通过。

确认后先写可失败的转换、过滤、日志与去重测试，再实现独立比较器和装配，运行定向/回归/类型/仓库检查，最后用本机真实新局验证。真实 API 调用需在实施后有意识地开启，不用 Mock 冒充。

## 方案 v1.2：choice 分布抽样与原始响应对照（工程已实施，真实旁路待复测）

2026-09-28 用户指出，JEV 的 choice 返回每个合法选项的概率；旁路对比应通过独立选择器按这些概率和置信度抽样，并同时保存原始分布与抽样结果。官方接口的三类是 `noul`、`choice`、`score` 问题类型，并非三个模型。本 MOD 的 009 旁路仍用 `choice`；`noul` 接管行动和 012 的 `score` 私有评分留待后续方案。用户审阅 v1.2 后明确回复“可以先完成select部分，009的方案”，并在澄清中选择“只完善 009 旁路”，随后再次强调不得直接用概率最高项作为最终模拟选择。v1.2 的置信度混合与抽样、原始日志及对照范围据此确认实施；v1.1 本机暂停状态维持。

本次仅修正狼人杀 JEV 旁路的数据解释、抽样和对照日志。仍不让 JEV 控制裁判，也不改变现有模型的 SELECT/SPEECH、私有上下文、启停开关、重试或费用边界。权威接口、确定性抽样、置信度策略与日志字段见[模型接入](../../docs/model-integration-v1.md#v12-choice-分布抽样与对照已实施本局实测)，验收见[诊断测试契约](../../docs/model-test-observability-testing-v2.md#v12-jev-choice-抽样与原始响应已实施本局实测)。

本次采用文档中的置信度混合策略 `q_i = c·p_i + (1-c)/N`。这是本游戏的抽样策略，不是 JEV 官方对 `confidence` 的规定。先写失败的纯选择器与日志/恢复测试，再改旁路工作器；真实 API 新局对照只在用户决定重新启用旁路后运行。

工程结果：新增 `server/jev-choice-selector.ts`，按固定 request ID 产生一次可复现的抽样值；`server/jev-shadow.ts` 在原 `fw_event_log` 成功事件中保存完整供应商 JSON、原始概率、置信度、归一化及抽样概率、抽样值与 `sampledSelected`；`server/jev-comparison.ts` 与模型调用详情从同一请求各次尝试中读取已提交的原模型选择并给出对照。最高概率 `choice` 始终单独保留，不作为模拟最终选择。原始响应不含凭据，JEV 开关仍保持关闭；012 的逐玩家 `score` 未接入。

测试先行：新选择器和对照单元测试先因模块缺失失败；扩充的旁路日志与调用详情数据库测试先因新字段缺失失败。随后定向单元 4/4、隔离 PostgreSQL 定向 6/6、全仓单元 169/169、`npm run check`、`npm run check:repo` 和 `npm run build` 均通过。尝试运行隔离 PostgreSQL 全量回归时，容器命令连续两次因自动权限审查超时而未启动；不能记为通过。真实 JEV API 新局未运行，当前本机服务仍是上一个镜像，需在重新开启旁路前部署本版。

## 方案 v1.1：暂停本地 JEV 旁路（已确认实施）

### 已确认对照入口的界面缺陷修正（2026-09-29）

用户反馈模型诊断页找不到 `SELECT`，也看不到私密调用详情。本局 `c0cdb8b7-5c86-4183-bc10-938d66f7837b` 的调用摘要已有 43 条，包含 `SELECT` 阶段；警长投票调用详情已有原模型、JEV 事件和 `comparison`。现有网页未标交互类型，详情仅在点击记录后追加于长列表末尾。这属于已确认 JS-05、JS-09 对照范围内的实现缺陷。

修正范围：摘要按请求输出 Schema 标识交互类型，并支持服务端 `SELECT` / `SPEECH` 筛选；每条记录明确提示可查看私密详情，点击后详情显示在列表前，突出对照摘要，同时保留完整原始事件 JSON。旧 Schema 无法识别时标“未知”，不根据阶段名猜测。筛选只改变诊断读取，不改变模型、JEV、日志或游戏状态。验收：本局筛出 SELECT 且打开详情后可见原模型与 JEV 对照；SPEECH 不混入 SELECT；100 条分页边界按服务端筛选工作。先补失败测试，再实现和检查。

修正结果：类型检查先因新增断言和第六查询参数缺失而失败；实现后宿主 `npm run check`、`npm run check:repo` 均通过。基于当前运行镜像离线叠加构建网页通过，隔离 PostgreSQL 行为测试 2/2 通过。本机服务已替换为 `diagnostics-select` 镜像，健康 200，原房间继续运行。实局查询得到 30 条 SELECT、16 条 SPEECH；SELECT 详情含 JEV 对照及原始事件。浏览器刷新后实见类型筛选、SELECT 列表和私密详情对照（原模型 `option-2`、JEV 最高权重 `option-6`、抽样 `option-2`、原始概率 37.0%）。本机 `.local/compose.active.yaml` 固定该镜像供快速启动脚本使用；该文件不入库、不含凭据。
