# 007 发言输出规则配置

Status: implemented；方案 v1.1 已获用户确认并完成代码与自动验收，真实模型缓存效果待新局观察。

## 需求与归属

用户要求在狼人杀 MOD 中建立可读的发言规则配置：发言约束示例为最多 200 字；自称“我”或“X号”；称呼其他玩家只用座位号，不使用自己或他人的游戏昵称。用户还询问可增加的语言文本规则。此行为属于狼人杀 MOD；通用规则引擎现有 `guidance` 能力保持不变。

当前唯一作者入口是 `mods/werewolf/rules/ruleset.json`，只登记预言家首日上警规则。框架编译器仅接受规则集 `id/version/rules` 与规则 `id/priority/instruction/enforcement/probability`；发言长度在 MOD 多处固定为 300。单改 JSON 无法让新 ID 自动匹配 `SPEAK`，也无法使 200 字成为硬上限。

## 范围：方案 v1.1

继续使用同一个 `mods/werewolf/rules/ruleset.json`。规则集版本增加到 3，新增一条 `speech-language`、`priority: 80`、`enforcement: guidance` 的规则；其 `instruction` 使用用户给定文字：“自称‘我’或‘X号’；提到其他玩家只用座位号，例如‘3号’，不使用自己或他人的游戏昵称。”MOD 内部为该 ID 注册纯匹配处理器，匹配全部 `SPEAK` 场景（警上发言、警长 PK、白天发言、放逐 PK、遗言），不按身份筛选。规则只进入当前发言席位的授权模型请求，不进入公共历史；`SELECT` 不附加此说明。`guidance` 不承诺每句必然遵守，不以昵称词面匹配直接否决玩家发言。

用户确认 KV 缓存优先和私有内容后置。该条座位无关的指导规则标记 `placement: stable`，由通用组装放在游戏规则之后、共享公开历史和动态 Schema 之前的独立 system 消息；角色专属指导仍放后部的当前私有事实。只在命中 `SPEAK` 时出现，所有同配置发言席位共享相同字节前缀，不将身份、昵称名单、私有情报或当前行动插入稳定段。通用机制及验收见[框架需求 023](../../../../.agents/note/023-model-context-cache.md)。

同一文件增加 MOD 专属顶层 `speech: { "maxChars": 200 }`，作为所有狼人杀发言的单一上限来源。MOD 装配时校验并拆出该字段，将其余 `id/version/rules` 交给现有通用规则编译器；完整作者文件参与规则集摘要，避免同版本改动 200 数值却通过恢复校验。MOD 统一用此值生成游戏行动 Schema、Robot 输出 Schema，并用于模型/脚本提案解码及内部发言校验；真人与 Robot 共用 200 字上限。字符数按 Unicode 字符计数，空白发言仍遵守当前超时默认。更新游戏定义版本；不对旧版进行中房间热替换规则，部署前按现有运维流程核对房间状态。

不增加新的框架通用字段、自然语言编译、模型二次审查调用、昵称硬拦截、固定短语检查、房间管理 UI 或任何新数据库表。用户示例中的 `xxxx` 尚无实际内容，当前不写入规则；若以后明确要求固定词语，另定是否由程序验证。

具体作者格式、执行边界见[现有规则配置文档的 v3 提案](../../docs/decision-rule-config-v2.md)。当前 300 字事实与拟议 200 字规则分别标注，不在确认前改写现行契约。

## 验收与实施顺序

- WW-S01：五类 `SPEAK` 均收到该条 guidance；`SELECT` 不收到；其他席位、公共事件和旁观视图不含私有策略说明。
- WW-S02：200 个 Unicode 字符合法，201 个被模型输出 Schema 和裁判行动 Schema 拒绝；真人、模型及脚本路径一致；空白发言仍按原规则处理。
- WW-S03：配置的规则 ID 或 `speech.maxChars` 变化但未提升版本时，重启恢复拒绝摘要不匹配；版本提升后新局使用新上限。
- WW-S04：配置字段缺失、非法上限、未知规则 ID 与错误 enforcement 在装配时失败；旧预言家上警行为不变。
- WW-S05：相同规则版本的不同发言席位，稳定指导消息字节相同且位于公开历史、Schema、私有事实之前；`SELECT` 无该消息，角色专属 guidance 仍靠后且绝不进入共享前缀。

按已确认的 v1.1 先写可失败的行为测试，再实施 MOD 配置、匹配处理器、长度单一来源及稳定指导消息；运行定向测试、类型检查、仓库检查及相关回归，并记录真实结果。涉及现有进行中房间时先核实版本，不自动重建或清理房间。

## 建议但未纳入本次配置

1. 只输出桌上发言正文，不加“作为 AI”“系统提示”等元叙述，也不写舞台动作、Markdown 标题或代码块。
2. 描述已结算行动时以当前权威事实为准；猜测、站边和策略性伪装仍然允许，不能用“必须说真话”破坏狼人杀玩法。

不建议默认强制每次发言点名投票目标、报身份或包含固定句式；警上、白天、PK 和遗言目的不同。若用户选择上述建议，再更新 instruction 和验收范围。
