# 016 狼队内部沟通与计划确认

Status: proposed

## 需求

用户明确共同战术应来自狼队内部沟通，不是四名狼人各自大胆或服务器安排剧本。2026-10-08 又指出现实中通常由一两名意见领袖组织行动，不应每夜机械地让全体提议、全体单独确认。

## 范围

本 note 补齐四项工作方式的调用、输入、输出、时序和失败边界；接口字段与状态的唯一正文仍在[队内组织设计](../../docs/model-integration-v1.md#阶段三狼队内部协商016-v11已实施)。MOD J2 已确认，以下是当前新局工程行为；根032已于2026-10-09获用户“实施”确认，工程接入完成。

### 1. 通常新增一次：一名狼人提出刀口与分工

“新增一次”是相对于当前每狼已有的夜间刀人决策，只增加一个组织交互，不包括原狼刀 SELECT，不包括网络重试。它不是让一名机器人替全队玩完整夜晚。

进入夜晚后，冻结本夜实际存活狼人名单，按本局已保存的种子顺序确定主提议者和补位者。主提议者存活时连续负责，出局后递补。该职责给一次优先组织机会，不授予强制其他人行动的权力，也不能写成全队已经选举了领袖。首版的默认顺序是实施建议；模型主动争取或队内推举另行扩展。

全队共用一个 45 秒组织窗口。首先只向主提议者发出私密 SPEECH 请求，其他狼此时不被要求各写一份提议。主提议者收到：本局板子／职业／术语、本人狼人操作指南、当前公共事实和公开发言／票型、本人合法获知的狼队与夜间结果、先前已发布的团队记录，以及本人判断和战术计划。本人私有信息仍放在公共缓存前缀之后；不能读取其他狼的个人记忆、女巫药量或未授权技能结果。

请求的任务是提出一份可参考的当夜方案：一个明确刀口或空刀、本人和队友的白天职责、适用与退出条件。它不要求安排四人的全部台词，也不要求每名队友都承担新角色。

例如存活狼为 1、3、5、9 号，1 号实际提出：

> 我悍跳预言家，3号倒钩，5号冲锋，9号先不跳身份。今晚刀7号。如果真预言家已经出局，取消悍跳，改看票型归票。

同次模型输出包含合法队内发言和可选结构化提议。发言校验仍最多 200 字；提议单独校验目标、分工席位和长度。合法主发言中的非法提议只丢弃提议，不丢弃发言、不为附加格式错误单独补问。如果没有有效结构化提议，不从自然语言猜出一个权威方案；原文仍作为这名狼人实际说过的话保留。

有效提交立即以实际来源及版本在存活狼队内发布。7 号仅是拟议刀口，尚未下刀；“我悍跳”是 1 号的打法意向，“3号倒钩”是对 3 号的建议。没有收到 3 号真实回应前，不能写成其已接受，更不能写成全队确认。

普通有效刀口发布后不再调用补位者“再看一遍”。组织窗口结束时冻结最终提议／同意水位，再进入原夜间技能阶段。固定窗口是公共计时要求，早返回并不意味着继续把剩余时间填满模型调用。

### 2. 队友在原有狼刀 SELECT 中回应，白天各自发挥

组织窗口结束后，每名存活狼仍各执行原有一次狼刀 SELECT。其上下文在私有后部增加本夜已发布的最终提议、目标同意状态和实际来源；原合法目标列表与原公开／私人事实继续提供。所有狼，包括主提议者和补位者，都需要提交自己的真实刀票。

每个狼刀请求使用同一冻结的团队水位。各狼并行选择，当前密封刀票和附加回应须等原狼刀窗口结束后才按授权统一发布，不能让后返回的人窥见早返回的队友刀票。这不是在四个 SELECT 之间插入四次来回讨论。

回应分两件事记录：

| 内容 | 何时知道 | 能证明什么 |
|---|---|---|
| 实际刀票是否和提议一致 | 狼刀合法提交并结束密封窗口后 | 这个人本夜选择了同一个刀口；不证明认可所有白天分工。 |
| 对本人白天分工的接受／调整／拒绝 | 同次 SELECT 可选附加团队回应，结束窗口后发布 | 这个人实际表达了何种意向；不证明其白天已经照做。 |
| 后续白天打法 | 本人后续交互及真实公开发言／投票 | 实际做了什么；不以计划冒充执行。 |

例如 3 号可以选择刀 7，同时附加“接受倒钩”；5 号也可以选择刀 7，却附加“冲锋容易暴露，我准备弱站边”。两人的刀口都一致，但分工态度不同。9 号可以选择其他普通合法目标，并说明自己的意见。没有附加回应时只记录刀票，不补写“已同意分工”。

附加回应有计划版本、分工态度和短说明，格式错误只忽略该回应；合法刀票照常接受。若模型在同次交互更新 015 的本人战术计划，两者独立校验；它只能更新本人意向，不能覆盖他人的回应或团队正文。

原裁判按实际刀票的最高票／平票逻辑结算。即便全员刀 7，也只记录刀口一致，不叫所有分工均获共识；原最终狼刀事件才证明刀口锁定，夜间结算才证明死亡／获救。

白天不额外开团队通信请求。本人普通 SPEECH／SELECT 的私有后部仍可看到已发布方案、回应及执行结果，并续读 015 的本人计划。模型结合新发言、对跳、票型等调整扮演和选择；公开历史保留，改计划不抹去先前说辞。某狼不同意或未照做不阻断其合法行动，下一夜主提议者可以看到真实偏差再调整。

### 3. 主提议失败才按需补位；团队自刀征得本人同意

这里的“失败”不是首次 HTTP 失败就立即切另一个人。主提议者的同一逻辑请求先使用现有有界重试／主输出纠正，最多三次总供应商尝试；终止后才决定是否补位。不能让原请求仍重试时同时让补位者另起一份方案。

| 主提议结果 | 下一步 |
|---|---|
| 有效普通刀口或明确空刀 | 保留方案，不额外请补位者复核。空刀也是有效意向。 |
| 调用终止失败／主输出未合法提交／没有有效结构化提议 | 有补位者、名额和剩余时间才补位一次；否则无有效方案，进入原狼刀。 |
| 提议刀本人且同次明确接受风险 | 本人同意有效，不重复问自己。 |
| 提议刀队友 | 只向被刀目标按需问一次接受／拒绝，绑定具体计划版本。 |
| 目标明确拒绝自刀，或自提本人未明确同意 | 该自刀不可用；时间足够时补位提出普通刀口／空刀，不重新询问其他自刀目标。 |
| 目标调用失败／无合法同意／到期 | 不算接受；如果仍在窗口内且有时间，可补位普通刀口／空刀，否则回到原狼刀。 |

补位者收到自己的授权上下文、主提议者已经提交的原文／计划及真实拒绝反馈；网络失败只作为调用状态记录，不能伪造成主提议者说过的话。补位者不读主提议者私人记忆。它可提出自己的替代方案；有新有效方案才替代旧版，否则旧原文仍在、无效自刀仍不可用。不会回调主提议者或增加第二名补位者。

自刀例子：1 号提议刀 9、让 9 号之后利用银水说辞。先额外调用 9 号一次，告诉其原提议、风险、计划版本，以及合法的接受／拒绝选项。9 号明确接受，只代表愿意承担该自刀风险，不代表女巫会救、不代表其他狼已同意刀 9。其他狼仍在原狼刀 SELECT 自主选择是否采用。

9 号拒绝时，不能继续把刀 9 提议作为可执行团队自刀，不能由 1 号替答“他愿意”；有时间才请补位者提出普通刀口。9 号返回不合法选择、断网或超时都按未获同意处理，不能用默认动作制造接受。版本换了，旧同意不自动迁移。

Robot 选项约束排除未获目标明确同意的狼人队友刀口，原裁判允许狼刀狼的基础规则保持。自己在原狼刀 SELECT 实际选择自刀可以表达本人同意，但不追溯开放其他并行请求；队友只能使用组织窗口内已发布的明确同意。目标不合法则原同意不能绕过当前合法性。

### 4. 最多三个新增交互，共享截止，不要求走完

三个是全队每夜的条件名额，而不是每席三个，也不是规定每夜都发生三步。最多一个主提议、一个补位、一个自刀目标同意。没有触发条件就不占用后两种调用；没有补位者、无需问目标或时间不足也不调。单狼自提本人且明确同意仍只一次新增交互。

| 分支 | 新增逻辑交互 | 顺序 |
|---|---:|---|
| 有效普通刀口／空刀 | 1 | 主提议。 |
| 主提议者自己明确自刀 | 1 | 主提议及本人同意在同次输出。 |
| 有效队友自刀、目标接受 | 2 | 主提议 → 目标同意。 |
| 主提议终止失败，补位普通刀口 | 最多 2 | 主提议 → 补位。 |
| 主提议终止失败，补位提议队友自刀 | 最多 3 | 主提议 → 补位 → 目标同意。 |
| 主提议队友自刀、目标拒绝，补位普通刀口 | 最多 3 | 主提议 → 目标回应 → 补位。 |
| 任一步达到窗口截止 | 截止前已发生的次数 | 停止新增请求，进入原狼刀；不补齐后续名额。 |

同一逻辑交互的网络重试／格式纠正共用最多三次供应商尝试，不另算一个补位。因而新增协商理论上限是三次逻辑交互、九次供应商尝试；45 秒截止可能先到，并不保证九次能全部执行。原狼刀、预言家、女巫等模型请求不在“新增三次”内，仍按原机制和各自截止执行。

若本夜四名存活狼都为模型，普通成功分支是 1 次组织＋原 4 次狼刀，共 5 个逻辑交互；队友自刀被接受时是 2＋4，共 6 个；同时发生补位和目标同意时最多 3＋4，共 7 个。这里只统计狼队，不含预言家、女巫及网络重试，不能据此宣称整夜只有五次 API 请求。脚本席和未派发请求不制造模型费用；实际 token 按每次真实供应商响应记账。

45 秒从组织窗口开始计时，不在切换到补位／目标时重置。模型排队、调用、重试等待和保存均消耗同一时间；须按实际模型超时配置检查，剩余时间允许至少一次供应商尝试及提交余量时才开始下一次，否则跳过。重试仍至少等待 1 秒／3 秒再加 jitter，等待或调用越过截止时取消，不用额外延长夜晚来挽救计划。

例如主提议普通刀口很快成功：后续不再调用，等待窗口结束再进入原技能。另一个例子是主提议失败耗尽大半窗口，补位也没赶上：本夜没有有效团队方案，各狼继续正常选择普通合法刀口。这是未完成协商的兜底，不能记成完成三步或全队同意。

截止冻结团队状态，后续狼刀请求不接收迟到的新版本或目标接受。迟到成功响应只留下真实模型日志和供应商 usage，不成为新提议／同意，不回填已开始的狼刀输入。取消不能保证供应商不计费，所以次数、原响应和实际 token 都保留，失败无 usage 时不捏造 token。

## 落地职责、私有事实与恢复

MOD 阶段状态负责组织者、窗口、分支、版本及真实队内事件；模型调度负责按条件准入并持久化调用名额；输入组装负责授权上下文与附加输出说明；动作／记忆解析负责分别校验主行动、团队回应及 015 更新。接口归[队内组织设计](../../docs/model-integration-v1.md#阶段三狼队内部协商016-v11已实施)，框架不足时另建根层方案。

计划、目标同意、各狼票、夜间结算是四类不同记录。全队共享的只是本席获授权的已发布团队信息，个人证据判断和战术记忆仍仅本席可读。015 的引用不是共同状态的第二份正文，也不拥有确认或覆盖他人行动的能力。

新消息只发当夜存活狼人；死狼既往授权记录可以保留，新夜不再收到新消息。普通公共历史／回放不出现私密正文，现有受权模型诊断保存原请求／响应、类型、来源、版本、尝试次数、处置结果和真实 usage。公共缓存前缀相同，团队信息及本人记忆放在后部。

每个调用分支在派发前登记稳定请求 ID 与名额，恢复沿用同一组织者、原期限、已用名额、版本和已提交记录；不靠重启重新获得三次调用。已合法提交不重复计票，晚到／旧 epoch 不写下一阶段。模型等待不持数据库锁，提交时短事务重验阶段、权限及版本。崩溃后无法确定供应商是否已收到的请求按既有调用恢复机制处理，不承诺外部 API 恰好一次或凭空返回结果。

## 本轮建议参数与审阅重点

- 通常全队新增 1 个主提议交互；按需最多另加 1 个补位、1 个自刀目标同意。全队每夜新增最多 3 个逻辑交互，不要求用满、不随狼数倍增。
- 每交互网络重试与格式纠正共用最多 3 次供应商尝试，新增协商最多 9 次尝试；每次仍 800 输出 token。原狼刀模型决策保持，实际费用只记供应商 usage。
- 新增一个共享 45 秒窗口，原技能 60 秒＋用药／等待 30 秒保持，总夜长拟为 135 秒；所有额外请求共用截止，不保证走满流程，也不延时补问。
- 协商 SELECT 不走 JEV 旁路，普通狼刀 SELECT 保持。公共界面不暴露狼数／私密正文，死狼不收到新消息；private_information 后部加载授权团队记录，保持公共 KV 前缀。
- 模型等待不持锁，提交短事务重验版本与期限；恢复续用组织者、计数及已提交记录，不重抽、不重调、不重复同意。

不包含白天无限私聊、死狼指挥、窥读他席记忆、自动强制统一刀口、独立评分模型、无限辩论或终局私密回放页面。自主推举／主动争夺领袖留后续扩展。
