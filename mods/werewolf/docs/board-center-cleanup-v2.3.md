# 牌桌中央记录修订 v2.3（已确认实施）

归属：[狼人杀需求001](../.agents/note/001-ai-spectator-mvp.md)。本版按用户2026-09-24提出的中央牌桌修订编写，取代[对局历史合并面板v2.2](board-history-replay-v2.md)中“中央全部保持原样”的限制；v2.2已实现的历史浮层和赛后揭晓继续保留。用户已在方案提交后回复“实施”，确认本版范围。

## 目标和边界

1. 中央公开记录按结算顺序展示警长竞选票型。常规投票和警长PK每一轮各显示一张票型卡，列出各候选人的得票、投票者和弃票/未投；平票、当选或警徽流失依已公开的结算结果显示。保留目前独立的“某号当选警长／警徽流失”公开结果卡；单候选自动当选或无投票时不伪造票型。旧对局若缺少`sheriff-votes`事件，仅显示既有结果，不从赛后私密逐票反推。
2. 中央不再渲染`speech`、`sheriff-speech`、`last-words`事件对应的整张占位卡，包括“已发言／已完成竞选发言／已留遗言 · 内容见历史”和未发言/未留遗言的同类卡。所有实际非空发言和遗言仍按原顺序留在“对局历史”；当前说话人的即时气泡不变。
3. 其他中央公开记录、放逐票型、过场播报、历史浮层、房间时钟和游戏行动均不改。中央不会出现逐张警长选票或私密夜间行动。中央的尺寸、位置、木纹与深青美术保持现状。

## 接口、数据和实现位置

裁判已有在每轮警长投票完全结算后发出的公开`sheriff-votes`事件，数据包含`ballots/totals/winner/tied/runoff/sheriff`；不增加或修改裁判事件、HTTP接口、快照结构和存档。前端`mods/werewolf/web/room.tsx`的中央事件投影改为过滤三类发言占位事件、保留`sheriff-votes`；`mods/werewolf/web/live-scene.tsx`的票型展示按事件类型区分“警长竞选／警长PK／放逐投票”标题和结算用语，复用现有票向摘要与样式。仅用公开`game.events`，不读取终局`replay`或席位私密视角。无事务、幂等、恢复或部署变化。

## 验收与实施顺序

确认后先写可失败的前端投影/票型行为测试：含发言、遗言、已结算警长票型和放逐票型的公开事件，只在中央留下两种票型及其他公开记录；警长PK、平票、弃票、单候选无票型和旧局无汇总分别显示准确；局中没有私密逐票或夜间行动。之后实施并跑类型、仓库、单元、构建检查；在浏览器检查已有终局与新生成的无模型对局，确认中央不再有“内容见历史”、新局警长票型可见，历史浮层发言仍在。旧终局房间不具备新汇总事件，不能用来验收新票型。无需付费模型调用。

本版已确认实施，没有其他待裁定的规则问题。实施结果：中央使用公开事件投影剔除三类发言/遗言占位卡，已结算警长汇总复用现有票型卡呈现；历史浮层和中央其他记录不变。定向14项测试通过，类型检查/全量单元受到同时进行的模型上下文缓存改动失败影响；仓库检查与构建通过。旧终局房间浏览器证实中央无“内容见历史”、历史浮层仍有发言；加速无模型Demo种子0证实公开快照包含有投票的`sheriff-votes`，种子42单候选局未伪造票型。新局警长卡未在实际浏览器等完整计时目视。
