# 狼人杀事实上下文与遗言一致性 v1.3 测试设计

状态：FC-01～FC-10 的事实投影范围已确认并实施，FC-11 遗言保护待确认。关联[设计](witch-claim-consistency-v1.md)。

| 用例 | 预期 |
|---|---|
| FC-01 000013 独立复现 | 9 号已执行 `medicine: pass` 且结算夜死；私有操作历史只记录已执行 `pass`，死亡是当前结果；预结算审计 `decision` 不进入事实上下文 |
| FC-02 发言记录 | 所有席位按可见顺序看到各人的公开发言、竞选发言和遗言；字段表示“某人说了什么”，其中身份/技能主张不作为裁判事实 |
| FC-03 公开逐人投票 | 警长票、放逐票结算并公布后，所有席位看到每位投票人的实际目标或弃票/缺票，且计票结果一致 |
| FC-04 投票窗口未结束 | 已提交但尚未公开的单人投票目标不出现在其他席位 `public_history`；赛后可见的 `sheriff-ballot` 不提前公开 |
| FC-05 狼刀被救 | 狼方最终刀 5 号；夜死公告后 5 号存活。本方历史呈现已结算刀口、“刀未造成死亡/5 号存活”，并依据当前唯一的救助机制标明被解药救下；其他席位看不到私有刀口；不凭模型自述决定结果 |
| FC-06 刀口待结算 | 狼方刀口已决、日出尚未结算时，可作为授权当前情报，结果标记待结算，不进入已结算操作历史，不声称 5 号死亡或获救 |
| FC-07 过程投票与最终刀口 | 已计票的 `wolf-choices` 如需呈现，只归为狼方投票；最终刀口取 `wolf-knife`，两者不混同；刀口本身不等于夜死 |
| FC-08 权限与来源 | 本方/本人只见已授权的角色与已执行动作；另一阵营私密行动、模型候选、调用失败及预结算 `decision` 不进入事实区，原框架审计保留 |
| FC-09 当前事实优先 | 历史行动与当前结算状态相冲突时，历史行动仍可追溯，但效果以当前状态描述；结果不明时标明未知，不补造因果或施救者身份 |
| FC-10 恢复与稳定性 | 房间重启后，同一席位、同一阶段实例的事实投影一致；不生成新裁判事件，不改变已存 000013 历史 |
| FC-11 遗言保护（可选） | 若确认提交前保护，“我用解药自救”等明确假断言不进入公开历史；否定、引用、推测不误拦截；最多重写一次，失败或超时使用中性遗言 |

已先为事实上下文写行为测试并记录旧行为失败，再实现白名单投影、动作结果配对与权限检查。定向测试 11 项、全仓单元测试 123 项、`npm run check`、`npm run check:repo` 通过。2026-09-25 用独立临时 PostgreSQL、12 名真实 DeepSeek Robot 和加速等待的模拟时钟跑完一局：第 5 夜狼人获胜，134 次调用开始、132 次成功响应、2 次失败；实际请求的 134 份事实上下文均不含预结算 `decision`，公开发言均标为玩家说法。两次失败的原因未保留，供应商 token 汇总也未保留，不能据此评估费用或失败来源；本机摘要 `.local/live-facts-game-summary.json`。FC-11 尚未编写可执行测试或实现。
