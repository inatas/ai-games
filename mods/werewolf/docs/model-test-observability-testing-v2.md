# 模型测试与调用日志 v2 验收说明（已实施，待网页实局复核）

关联[设计](model-test-observability-v2.md)。用户已确认实施；相关路由和持久数据库测试已通过，网页实局复核仍待用户执行。

| ID | 场景 | 通过标准 |
|---|---|---|
| ML-01 | HTTP 2xx 且有效输出 | started、finished、judged 关联同 request/attempt；网页分别展示供应商成功和动作是否提交，实际 usage/延迟可查 |
| ML-02 | 非 2xx、断网、超时、取消 | 每次已发调用有 started + failed；安全错误类别及 HTTP 状态可查，原始错误体和密钥不入日志；未知 token 为 null |
| ML-03 | 无效 JSON/Schema 与纠正 | 首次仍是“已返回但无效”，纠正调用另算 attempt；最终裁判状态单列，不能记作网络失败或动作生效 |
| ML-04 | 未发出与未知结果 | context/budget 拒绝不生成 started；崩溃只有 started 时恢复为 orphaned；前端显示“未发出”或“结果未知” |
| ML-05 | 持久对局与刷新/重启 | 用户网页启动的房间终局后仍可按 ID 加载流程、回放、完整调用日志；服务重启后同一结果可读，测试不自动清理 |
| ML-06 | 查询与隔离 | 摘要有游标、条数上限和座位/结果筛选；一个房间不可查另一个房间；缺失/错误测试口令返回 403，经 Docker 发布端口携正确口令可读；公开快照无原始上下文 |
| ML-07 | 用量汇总 | 只加总实际供应商报告；失败无 usage 不计 token；缓存字段完整才参与分子/分母，未报告数量保留；重试分别计 |
| ML-08 | 隐私和边界 | 输出中无 Key、Authorization、连接串、异常原文；公开旁观不能在终局前看到他席私密消息或夜间结果 |
| ML-09 | 真实模型网页整局 | 在开发持久库从网页配置、启动、看阶段和终局回放，保存房间 ID、开始/成功/失败数量、错误码、token 与 cache 汇总作为实际证据；未运行不写通过 |

实施验证顺序：先使 ML-01～08 行为测试失败；代码修改后跑定向、类型、仓库检查与数据库集成；再执行 ML-09。真实调用失败不删日志或以脚本结果代替。生产库不作为测试库。

## JEV SELECT 旁路验收（v1 历史实现；本机当前暂停）

| ID | 场景 | 通过标准 |
|---|---|---|
| JS-01 | 原 SELECT 上下文转换 | `state.messages` 与原 `model.call.started.v1.details.modelRequest.messages` 同序同内容；criteria 与原合法 ID、动作值一一对应；私有信息只来自该席已授权请求 |
| JS-02 | 筛选与零侵入 | 只调用真实模型的狼人杀 SELECT 首次尝试；SPEECH、脚本、规则强制选项及其他 MOD 零 JEV 调用；原行动、发言、时限、结算与关闭旁路时一致 |
| JS-03 | 成功与失败日志 | started 先落库；成功保存有效 choice、概率、置信度、实际版本与 usage；HTTP/超时/无效响应分别保存脱敏失败；跳过项不被记成已发送 |
| JS-04 | 幂等与恢复 | 同源 request 首次尝试至多一次 JEV 网络调用；重启只补未领取项，已领取但无终态标记未知；旧历史房间不追溯调用 |
| JS-05 | 本机真实对局 | 网页新局中按房间、席位、阶段、request ID 对照两家 SELECT 和原裁判提交结果，记录实际成功/失败数、延迟、input/output token；不以模拟接口冒充真实验证 |

v1.1 暂停验收：服务已重启，容器内 `JEV_SHADOW_ENABLED=false`；健康和网页均返回 HTTP 200；JEV 日志水位保持 3676，没有新增旁路事件。重启前运行中的狼人杀房间为 0，故房间恢复未实测。没有额外开启付费对局，后续真实 SELECT 的 DeepSeek 提交及零 JEV 调用待下一局核对。既有 JEV 事件与历史房间保留。

确认后先写 JS-01～04 的失败测试，再实现并验证；JS-05 需用户或开发者实际开启带独立密钥的新对局后回填。
