# 首个白天死讯播报与模型事实区分 v1.1（已确认实施）

归属：[狼人杀需求001](../.agents/note/001-ai-spectator-mvp.md)。2026-09-23真实DeepSeek对局的首夜，狼队刀口为12号、女巫救人，警长竞选后权威公开事件 `night-deaths.seats=[]`，即平安夜。2号狼人第一次普通发言的授权输入同时含私密刀口12号、公开平安夜和12号仍存活的座位；输出却把刀口当夜死。旁观页面另有漏播路径：弹层期间、轮询跨多个房间修订或转终局时，`nextPresentation` 会消费事件序号却不排队死讯。这里区分模型叙事错误与页面播报错误，不改裁判的救人结算。

## 目标与范围

- 第1夜仍按已确认规则先完成警长竞选，再公布昨夜实际死讯或平安夜；第2夜起在转白天时公布。实际死亡集合只由裁判的公开 `night-deaths` 事件决定，狼人私密 `wolf-knife` 是刀口目标，不能推断目标已死。若有毒杀或多死，公开名单保持现有规则；不得公开药品、刀口或死因给公共旁观。
- 让当前实时旁观者可靠看到本日公告；弹层打开不暂停游戏，关闭时如仍是本日且对局进行中，应补显示尚未看过的本日公告。跨日、首次加载旧房间和终局不自动重播陈旧演出；公共记录始终保留公告。重复轮询、重复事件、刷新和断线恢复不得多播。
- 模型六区仍保持原结构。`game_state`加入从最新**已公开** `night-deaths` 派生的 `last_announced_night`（夜次、死亡座位数组、平安夜布尔值）；未公布时为 `null`。`private_information`保留现有授权刀口；狼人提示明确“刀口是攻击目标，不是死亡结果，已公开死讯和当前存活状态优先”。仍允许玩家有意欺骗；本期不靠文本关键词裁判发言真假，不增模型调用。
- 不修改已结束房间的结果、旧事件内容、游戏规则、死亡原因、权限、普通行动默认、夜间60+30秒、模型计费或通用Harness六区协议。新字段只属于MOD题材上下文，不反向进入框架。

## 已确认的播报时序

用户将本次范围限定为**首个白天**的夜间死亡播报，并明确要求落实模型上下文的两类事实。沿用已确认v4过场：天亮动画先出现，上警竞选结束、`night-deaths`公开后播报实际死讯或“昨夜平安夜”；画面播报3秒，服务端对局和倒计时继续运行。基于事件序号而非修订差值捕捉当日死讯；弹层期间保留待播，关闭后如仍处首日且对局进行中则显示。首次打开已过播报时点的旧房间、跨日或终局不重播陈旧演出，公开记录仍可查。第2夜起的既有播报行为保持，本次只避免共用前端游标逻辑使其倒退。

此前方案A的“服务端独立3秒阶段”不在本次确认范围；如以后要求公告阻断下一行动，需另设计通用运行时计时契约并单独确认。

## 接口、数据、权限与验收

页面只使用现有公开 `DemoSnapshot.events` 和前端 `PresentationCursor`；待播状态以当前房间、本日和公开事件序号为键，不把私密死亡原因带入公共页面。`nextPresentation` 在弹层遮挡期间只保留当前房间的待播公开序号，不补昼夜装饰过场；轮询跳过多次修订时仍识别本日死讯。公告不改变房间数据、事务、幂等或恢复语义。上下文 `game_state.last_announced_night` 从最近一条**已公开** `night-deaths` 派生，包含 `night`、`deaths`、`peaceful`；未公布任何夜死前为 `null`。`rules` 明确说明 `game_state/public_history` 是任意平民都可看到的公共事实，`self/private_information` 是当前席位身份额外知道的事实；狼刀事件是目标，不代表实际死亡。模型可以策略性声称假信息，但提示不能把私密行动当作已公开结算。脚本与模型决策收到同一MOD授权结构；事件日志继续记录实际请求，便于逐字段核对。纯公共旁观请求不得取得刀口；本人狼视角仍可得到私密刀口。

确认后先写可失败测试：

1. 首夜救人：竞选前公开播报/模型公共摘要均为空；竞选后事件为平安夜，狼人上下文同时有私密刀口12和公开无人死亡，12号仍活；其他身份不能看到私密刀口。
2. 普通夜死、毒杀、多死及全空：公告与公开事件一一对应；药品、刀口与死亡原因不由公共播报泄漏。
3. 首日快照跨越多个修订、弹层跨过公告、重复轮询、切换房间、刷新、跨日及终局：首日公告不漏不重，陈旧公告不抢终局；倒计时在查看历史时持续。
4. 服务端阶段、竞选先于公告、夜间90秒与下一位行动时序不变；本轮仅修复页面演出和MOD决策上下文。
5. 本地隔离数据库和浏览器用确定性脚本重放首夜救人，核对“平安夜”视觉与下一次模型输入；不需要再付费跑整局。类型、仓库、单元/相关集成与构建检查均通过后回填真实证据。

确认记录：2026-09-23用户在收到v1问题定位及A/B选择后，明确要求“修复首个白天的夜间死亡播报”，并指定模型上下文的公共平民事实与身份额外事实两层。本v1.1按既有非暂停过场实施首日页面播报和MOD六区上下文，不包含新系统阶段。

实施验证：先新增首日平安夜跨多次修订/历史弹层及狼刀公私事实的行为测试，运行时两例均失败；修复后定向8/8、单元110/110、`npm run check`、`npm run check:repo`和`npm run build`通过。页面现在只用本日公开事件生成死讯；历史弹层暂时隐藏并保留待播项，关闭后继续显示，不暂停对局。模型上下文在现有六区内增加最新公开夜死摘要，规则说明公开事实与本人私密事实边界。浏览器中已核对先前结束的实测房间公开记录：首日竞选后为“昨夜平安夜”；旧终局房间不触发新过场。此次未新开一局并实时目视首日过场；本机Docker访问被拒，未运行需数据库的整套集成测试或新的付费模型调用。
