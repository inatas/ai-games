# 狼人杀开发方案 v3（2026-09-21，已确认执行）

归属：[需求001](../.agents/note/001-ai-spectator-mvp.md)。游戏规则唯一正文为[规则v2](mvp-design.md)。用户在具体版本和范围提交审阅后回复“确认执行”；确认记录和本地检查点见需求001。本方案不修改已确认的游戏裁定。

## 本次目标与范围

允许以现有提前实现的六个MOD模块和39组测试为待验收基线，经核对修正后接入[框架抢占v2](../../../docs/specs/turn-based-interrupts.md)，使狼人能在允许阶段内独立发起自爆，且普通模型迟到输出不会污染对局。保留现有代码不表示追溯批准之前越过开发门禁的行为。

本次包含规则符合性复核、MOD适配、并发/隐私/幂等/恢复测试；不包含HTTP、竖版UI、应用自动开局、生产调度、部署和真实模型付费对局。现有文件清单、检查点与历史证据见需求001。

## 模块与接口

- rules、settlement、election、views仍分别拥有规则计算、死亡链、竞选和白名单投影；发现规则偏差时先补失败测试。不得在框架添加狼人杀分支。
- match拥有唯一游戏阶段与资格判断。普通decideMatch和独立explodeMatch必须共用当前状态资格，不能只靠前端或模型提示限制自爆。结算链清空前不返回终局。
- definition在允许自爆阶段提供Phase.interrupt的actors、严格Schema及策略key。动作只允许pass或explode，seat来自框架绑定而非模型任意指定；禁止额外字段。validateInterrupt重验当前阶段、角色、存活/未公布夜死资格；resolveInterrupt对pass不改变游戏，对explode调用整局规则并返回Transition和新增事件。
- 允许阶段按规则v2的自爆时机清单映射；夜间、死讯公布、计票、遗言、警徽处理不发布抢占资格。未公布夜死狼仍依已确认规则有资格，不能仅用alive过滤。名单收齐后若需要保留可自爆间隙，必须表达为可被框架调度的状态，不能藏在一次同步调用内部而宣称支持插队。
- 普通动作和抢占按框架提交顺序生效；MOD修订号只校验游戏推进，框架epoch负责拒绝冻结在旧事实上的请求。公开已提交事实不撤销；旧提案不得自动应用于新阶段。

## 数据、授权与恢复

保持JSON可序列化Match状态，保存游戏、竞选名单/首爆夜号、结算队列、阶段、修订号和随机状态；不另建MOD表或第二套请求队列。pendingJobs、双scope、epoch、租约及数据库事务由框架持有，MOD回调同步纯计算且不调用模型/网络。

两条模型通道使用同一席位的授权actorView和事件，不共享其他席位历史。自爆资格名单不能进入旁观DTO。正常结束才reveal；blocked/aborted不揭密。吃毒狼自爆改变其出局原因但不退药，其他夜死和后续链条继续；警长自爆直接流失警徽。

抢占提交及其状态、事件、有效记忆在框架同一事务完成；崩溃后加载同一持久Match继续，已提交请求重放不重复自爆、开枪或公布死亡。JSON往返测试仅验证序列化，恢复验收必须使用真实PostgreSQL和重新创建的Runtime实例。

## 验收与执行顺序

1. 用户明确确认019 v2及001开发方案v3范围后，记录确认依据并建立包含当前修改的本地Git检查点。
2. 对现有规则和测试做符合性复核；仅在方案范围内修正，先记录对应行为测试失败。核对WW用例与测试证据，不把39组测试等同全部用例验收。
3. 按019完成中性框架TB-09～14的测试先行实现，保留TB-01～08回归。
4. 在MOD本地先写WW-73、WW-77～80失败测试，再实现抢占映射；使用可控制等待/返回时序的ScriptedModel，不用真实网络时延制造竞态。
5. 使用显式TEST_DATABASE_URL与独立随机schema验证模型等待、自爆提交、旧响应到达、Runtime重建与请求重放。框架事务证据由TB用例承担，MOD测试验证具体规则与隐私。
6. 运行类型检查、仓库检查、单元及相关真实数据库集成回归，分别记录失败、通过与未运行项。本次不以真实LLM游戏表现作为完成条件。

具体新增验收说明见[WW-77～80](mvp-testing.md#开发方案v3接入验收)。当前无新增待裁定的游戏规则；若复核发现设计与裁定冲突而无法据现有规则判断，仅提交该差异，不擅自改规则。

## 实施结果

普通和自爆通道均已接入RoomDefinition，版本升级为3.seed.sheriff。现有规则模块已按确认裁定复核；注册名单收齐即持久进入竞选speech阶段，第一条发言尚未提交时同样可抢占，故不增加固定自爆询问窗口。单候选按已确认规则直接当选。

真实PostgreSQL验证等待发言时抢占、旧输出无有效记忆、Runtime重建后整局结束，以及跨夜双爆和猎人开枪后恢复死亡链。测试使用ScriptedModel与64k输入/128k窗口；默认8k预算在后期遗言触发CONTEXT_TOO_LARGE，未取消预算保护。实际模型接入必须按可用窗口配置预算，长局可能仍因预算暂停；上下文压缩不属于本次范围。详细证据见需求001。
