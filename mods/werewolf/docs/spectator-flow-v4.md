# 观战流程与演出 v4

状态：已实施并验证（用户回复“ok go”）。所属需求001；2026-09-22用户提出五项调整。本次优先完成公共观战流程，此前建议的私密视角切换不纳入本版。当前运行代码为v4，替代v3的局中暂停/单步语义。

## 展示与交互

1. 中央人物跟随实际发言者，上警、PK、放逐讨论、遗言均适用。点击头像只打开资料/个人标记，不改变中央发言者。座位气泡、姓名牌、头像高亮使用同一个speakerSeat。非发言阶段（报名、投票、方向、开枪、移交警徽）清空人物；改用相应阶段提示，避免把行动者误当发言者。夜间清空人物、姓名和座位气泡。
2. 统一称为“用户Avatar”，包括中央人物展示与席位头像，与狼人、预言家、女巫等游戏身份完全独立。用户明确授权直接使用三张图：[粉发Avatar](prototypes/user-avatar-pink-reference.png)、[棕发Avatar](prototypes/user-avatar-brown-reference.png)、[蓝衣Avatar](prototypes/user-avatar-blue-reference.png)。原图已归档；实施时提取人物展示区域，不把截图中的11/1/5号、昵称牌或旧背景当作本局数据，号码与姓名由当前发言者动态绘制。素材按用户/席位稳定配置，可在12席临时复用，换身份不换Avatar；夜间隐藏中央Avatar。直接使用用户提供的形象，不重新生成替代形象。
3. 对局开始后自动持续运行，移除暂停、暂停演示、单步及倍率。查看历史、资料、投票、设置或打开重开确认框不暂停。开始与确认重开仍为显式操作；取消重开不影响原局。播放/暂停若以后加入，只属于独立终局复盘游标，不能操作原局；本版保留已有终局记录查阅，不扩展完整可播放复盘。
4. 昼夜过场沿用木纹、手绘村庄与低饱和颜色。入夜为暗幕/月亮/云层与“天黑了，请闭眼”；天亮为太阳/云层与“天亮了，请睁眼”。建议各2秒，淡入淡出，减少动效模式使用静态短提示。过场不阻塞服务端、不重置阶段时限。
5. 夜间只展示流程提示：前60秒“狼人、预言家行动中”，后30秒“女巫行动中”；不展示行动座位、选择、角色是否存活或是否提交。角色已死仍保留相同提示和固定夜长。
6. 夜间出局公布时显示墓地/木牌出局公告，列出当晚所有已公布死者的头像和座位号，建议3秒后自动收起，可关闭；平安夜用“昨夜平安夜”简短提示。墓碑样式参考codex-clipboard-0c8ae7ee-aafb-4fa0-865b-6d494e30b14f.png。公共旁观不区分刀杀/毒杀，不增加隐藏角色标签。遗言资格来自既有规则，不能一律写“没有出局发言”。首夜天亮动画先播，警长竞选后收到night-deaths再播出局公告；不得在天亮时预告名单。公告不改变已经运行的游戏时钟，公开记录永久保留结果。
7. 每次放逐投票结算后，在主记录直接展示“被投者 ← 投票者”的汇总。示例：6 ← 1、2、3、4、5、8、9、12；5 ← 6；12 ← 7；弃票 ← 10、11。按得票高低排列，平票按座位号稳定排序；标出警长1.5票、加权总票数、当轮最高票/平票/无人出局。PK前的平票不能标为最终放逐。删除重复的查看详情入口，直接查阅公开记录内的票型汇总；每一天及PK轮次分别展示，不覆盖历史。未投与弃票如存在分别展示。参考两张投票截图0f3bcee2、a4cc9440。

## 模块、接口与状态

- MOD的DemoRooms负责持续单速时钟和合法策略；改为由服务宿主定时驱动到期步骤，GET只读，不能依赖网页是否轮询推进。打开弹层、断开页面或切换后台都不停止原局；保留本地内存及闲置会话清理，不新增数据库持久化。
- 服务宿主负责定时驱动及关闭时清理计时器。每个会话到期动作同步串行提交，游戏状态、随机状态、时间与修订一起更新；失败不重复提交，失败状态明确反馈。重开创建新会话，旧会话按既有回收边界处理。
- 移除实时step/control暂停接口及其UI调用方，更新HTTP验收；内部测试用注入时钟推进，不为浏览器保留隐藏暂停入口。创建后直接运行。
- 扩展公开DTO：speakerSeat只在发言阶段有效；nightSegment仅为固定流程窗口（shared/medicine/null）；公开events保留sequence、day、period作为演出与投票分组依据。nightSegment不从角色存活推断。现有actor可以继续表达公开行动者，但不能作为立绘依据。
- React拆分中央发言者展示、昼夜演出、出局公告、投票汇总组件。发言历史继续按天筛选且在局中持续更新，不因新发言强制跳动用户阅读位置。关闭浮层后显示当前现场，不补播过时动画；结果仍可在公开记录查看。
- 演出仅消费已公开事件，按sequence去重，重新渲染/轮询/重连不重复播放。首屏载入已有局时显示当前状态，不重放所有旧动画。多个待展示事件按发生顺序播放；过时装饰过场可跳过，公告保留在记录中。终局优先显示终局状态。
- 素材位于 `mods/werewolf/web/public/werewolf`；映射和组件归 `mods/werewolf/web`；MOD文档、规则与验收归 `mods/werewolf/docs`。通用回合框架不引入题材演出。无私密视角权限变化、模型或RTC接入。

## 验收说明（确认后再编写可执行测试）

- V4-01：不同座位依次发言、上警/PK/遗言时人物、姓名、气泡一致；点击其他头像不抢走发言展示。所有非发言阶段和夜间无人物残留。
- V4-02：实时页面无暂停/单步/倍率；打开任何浮层、停止轮询再恢复后，时间及实际游戏仍前进。GET不推进游戏；旧控制接口不再接受暂停。重复定时触发不能重复行动/发言/结算。
- V4-03：固定夜间60＋30秒且双方都提交也不提前天亮；夜间提示不因角色死亡而改变。首夜死讯在竞选后公告，墓碑名单与公开事件一致；平安夜、多死者、终局均正确。
- V4-04：过场在日夜转换仅一次；刷新、重复事件、弹层遮挡、减少动效和网络恢复均不重播陈旧公告、不改变游戏时钟。
- V4-05：汇总与原始投票一一对应，包含弃票/未投、警长1.5票、普通平票和PK；示例6号8票等仅用于测试，不混入真实对局。
- V4-06：整局自动走到终局，历史含全部实际固定短句，出局连锁结束才判胜负；桌面及手机目视验收，无控制台错误。

## 实施顺序

确认本版范围和上述默认表现后，先保存当前v3检查点；先写计时、角色投影、事件去重和投票汇总的失败行为测试，再实现服务与DTO，随后接入展示和演出素材，完成真实整局与移动端验证。更新当前接口/设计文档，保留v3验收为历史，不继续把局中暂停作为当前契约。

### v4实施细节补充

- 公开事件采用独立连续序号，避免私密夜间动作数量由序号空隙泄漏；终局完整私密记录只进入replay，已有公开事件与历史发言序号保持稳定。
- 同标签页sessionStorage保存当前会话和种子，刷新读取原局；不属于服务端持久恢复。历史浮层显示现场阶段和剩余秒数，打开期间照常轮询。
- 用户Avatar直接使用所提供PNG，CSS按轮廓裁切隐藏旧号码与昵称，圆头像与中央人物一致；日月、云层、木牌与乌鸦以CSS/SVG实现。原图清晰度保持其低分辨率限制。
