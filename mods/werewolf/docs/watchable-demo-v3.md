# 无模型完整观战演示 v3

状态：待确认开发方案。所属需求001。目标是使用现有UI观看实际固定/随机策略对局全过程，历史发言来自本局，而不是静态样例。

## 已明确范围

- 狼人刀人和预言家查验共享60秒；前段完成并锁定刀口后进入女巫30秒。夜间只结算一次，原死亡公告、竞选、自爆和连锁规则继续遵守。
- 沿用现有播放/暂停、单步、1×/2×/4×及重开，不增加一套控制界面。
- 本轮不接模型/RTC/数据库。演示仍为本地内存会话，重启后重开，不宣称生产持久恢复或真实模型超时已经完成。

## 模块与行为设计

1. `mods/werewolf/src/match.ts`及对应规则视图：将夜间前段统一收集狼刀与查验，按行动者提供不同合法动作与可见信息，全部完成或截止后锁定并结算前段，再交女巫用药。查验结果只给本人，刀口只按规则给女巫，不把行动收集顺序当成独立计时阶段。
2. MOD演示策略：固定/随机选择仍通过合法动作校验；模板发言只读取该席的actorView与已公开发言，不读取全场真实身份。以公开事实组织质疑/回应，狼可按预设策略伪装身份；标为“规则策略演示”，不声称模型推理。上警、PK、普通发言和合法遗言均产出本局文字，暂遵守现有300字符上限，不顺带扩大发言协议。
3. `DemoRooms`增加演示逻辑时钟、阶段剩余时间、播放状态和速度。服务端计算进度，1×/2×/4×只是演示逻辑时间倍率，不改变种子、行动选择或票型。以注入时钟验收，无需测试真的等待数分钟。不同速率/单步下相同种子得到相同游戏事件。
4. 单步：自动暂停，完成一个可观看步骤——公开阶段为一名玩家发言/一次结果或连锁动作，夜间为前段整体或女巫整体，不向旁观者逐个暴露夜间私密行动。单步允许快进演示等待，不能重复提交或跨过尚未结算的链条。
5. 策略可提前完成动作，公开发言至少保留短阅读间隔；倒计时是动作预算，不强迫每次模板发言等150秒。建议夜间公开固定逻辑90秒以避免存活信息的时间泄漏；无角色的窗口保留公开等待。固定夜长为本方案待确认选择，不冒充已裁定。
6. 保留当前演示的暂停阅读语义：打开历史等弹层暂停演示逻辑时钟，关闭恢复原状态。此为用户本机演示控制，不扩大为生产多人对局暂停权。

## 接口与数据

- 扩展`apps/shared/werewolf.ts`的DemoSnapshot：`playback {playing,speed}`、`timing {remainingMs,budgetMs}`、`speeches [{sequence,day,phase,seat,text}]`。只含公开发言，sequence稳定递增；阶段保留PK及遗言语义，不依赖前端猜测。
- 现有创建/读取/step路由继续承担会话操作，新增同源控制请求处理播放、暂停与倍率。控制和step请求包含revision与唯一commandId；重复命令返回已提交结果，不再次推进，冲突重新读取。同一会话仅一个更新提交点，游戏状态、策略随机数、时钟和发言记录一起成功更新。禁止未知字段/非法倍率/越权阶段动作。
- UI倒计时按服务端快照展示并刷新；历史浮层改读本局speeches，按天阶段筛选，不合并或漏掉同人多次发言。保留静态初始原型，仅真实游戏中不使用示例替代空数据。
- 本轮的超时演示可以用测试注入“不提交”复现默认动作；查验超时随机合法目标等尚待裁定项在确认前不能作为已定游戏规则实现。
