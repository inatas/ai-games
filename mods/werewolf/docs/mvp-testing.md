# 狼人杀MVP验收用例（规则v2追加裁定）

依据[设计与规则v2](mvp-design.md)。规则来源为用户指定的LAL预女猎白页面；规则细节已由用户2026-09-21确认。**原39组MOD测试经获准复核后继续通过；新增3组抢占单元和3组真实PostgreSQL整局/恢复测试。尚无HTTP或真实LLM证据。**

用法：先取得对应开发方案的明确确认，再写可执行行为测试并记录失败，随后实现并记录实际证据；不同验证方式不得互相替代。五项规则交叉边界已确认；框架抢占接口和MOD适配已完成；应用宿主接入待后续方案，见[实施状态](mvp-design.md#实施状态)。

## 阵容与开局

- WW-01：12席固定阵容为4狼、4民、预言家／女巫／猎人／白痴各1；每席绑定独立模型配置与独立scope，相同适配器也不共享私有历史。
- WW-02：依次入座期间保持waiting；第12席就绪后原子开局并完成身份分配。
- WW-03：身份分配不调用LLM；相同输入可复现，不同对局分布符合预期比例。

## 放逐投票与平票

- WW-04：最高票≥2人同票进入PK，仅平票者再发言一轮。
- WW-05：PK阶段其余存活玩家的可选投票目标仅限PK台上的人。
- WW-06：PK重投仍平票时本轮无人出局，且直接进入黑夜。
- WW-07：允许弃票；报票结果将“出X票”“弃票”“未举牌”三类分开呈现，弃票不并入零票。
- WW-56：放逐投票公开座位级明细票型（谁投了谁），旁观响应与AI上下文均可获得。
- WW-08：白痴被放逐时翻牌免死，当轮不出局；翻牌后可继续发言。
- WW-09：白痴翻牌后不可投票，且不再是其他玩家的合法投票目标（提交该目标被规则拒绝）。
- WW-59：翻牌白痴仍计为存活神职：其存活时“神职全灭”条件不成立，狼人不能据此获胜。
- WW-10：白痴翻牌不产生遗言；夜间被刀或毒时按普通神职死亡处理（不涉及翻牌，翻牌仅在被放逐时触发）。

## 狼人夜间行动

- WW-11：活狼各提交一个目标或空刀，排除空刀后按实际座位目标最高票决定刀口。
- WW-12：实际目标同票时随机抽选；两票空刀、一票5号、一票6号必须从5、6号抽选，不能选空刀；三票空刀、一票5号则刀5号。
- WW-13：允许自刀；全部活狼空刀时无狼刀死亡，但若有女巫毒杀仍公布该死亡，只有无夜死才报平安夜。
- WW-14：允许阶段内狼人可随时插队自爆，不必轮到自己；不得退化为发言前固定询问窗口。当前发言/投票被中断，陈旧输出不得随后生效。
- WW-15：夜间阶段不接受自爆（无该动作）。
- WW-16：双爆局竞选首爆不吞徽，跨夜续选再爆按WW-60～70处理；不可用竞选任意自爆立即吞徽代替。

## 女巫

- WW-17：解药、毒药同夜最多使用一瓶，提交同夜双开被规则拒绝。
- WW-18：解药未使用时，女巫私有上下文包含“今夜倒牌的是X”；使用解药后不再获得刀口信息。
- WW-19：女巫不可自救，选择自救被规则拒绝（含全程各夜）。
- WW-20：药品全局各一瓶，用尽后对应动作不可用；解药未用而女巫出局时药品作废。
- WW-21：女巫救起的目标当夜不出局；被毒目标死亡。

## 预言家

- WW-22：查验结果只返回“好人／狼人”，响应与AI上下文中不出现具体神民身份。
- WW-23：连续两夜查验同一人时第二次提交被规则拒绝。
- WW-24：金水／查杀与真实阵营一致（好人／狼人）。

## 猎人

- WW-25：猎人被狼刀出局时可开枪；被白天放逐（含PK出局）时可开枪。
- WW-26：猎人被毒死不可开枪；同夜中刀加中毒按毒死处理，不得生成枪动作。
- WW-27：开枪目标按实际死亡结算，继续处理目标遗言及其他应有链条，全部结束后再判胜负。
- WW-28：猎人选择不开枪时对局正常继续。

## 遗言

- WW-29：首夜死亡者有遗言；第2夜及之后夜间死亡者无遗言。
- WW-30：白天被放逐者有遗言；自爆狼无遗言；白痴翻牌不给遗言且继续发言。
- WW-31：猎人开枪带走的目标按各自死亡时段补遗言（猎人夜晚被刀死、白天被放逐两种情形均验证）。
- WW-58：猎人白天被放逐时先遗言→开枪→目标应有遗言，补齐其他应有链条后判胜负，未终局才进夜；不开枪也须完成其他应有链条。

## 警长与双爆吞警徽

- WW-32：第一天白天在放逐投票前进行警长竞选；上警者依次发言，未上警者投票。
- WW-33：仅投票开始前允许退水；开始后候选名单固定，中途退水被拒绝，不作已得票作废重计。退水者不参与警长票。
- WW-77（需求006）：全部警上发言结束后只出现一次 `election-withdrawal` 阶段，所有候选人同时可行动，共用10秒截止点；页面明确显示“警长退水”和一次倒计时。
- WW-78（需求006）：全员提前提交仍在统一边界结算；未提交者到期默认保持竞选；迟到结果不得改名单。
- WW-79（需求006）：相同退水选择按不同到达顺序得到同一候选名单；最终为0/1/多人分别流失警徽、自动当选、进入投票，不得在批量结算中途宣布当选。
- WW-80（需求006）：退水原报名者不获得警长票；投票开始后候选名单锁定，后续退水被拒绝。
- WW-81（需求006）：退水窗口内自爆中断未结算选择；首爆跨夜续选只重开一个共用窗口，第二爆仍按既有吞徽规则。
- WW-82（需求006）：重启和重复截止扫描沿用持久截止点且只结算一次，过期Robot输出不能覆盖默认动作或新阶段。
- WW-83（需求006）：窗口中保留候选头像标记且不显示独占席位、不公开个人选择；结算后按公开退水事件取消对应标记。
- WW-84（需求006）：单候选直接当选、警长投票和PK、首夜死讯以及其他20秒阶段保持原有规则；用户网页新局复核完整流程。
- WW-34：警长票权为1.5票，仅适用于放逐投票；不实现1票/2票变体。
- WW-35：警长选举平票时平票者再发言并重投；再次平票则警徽流失、无警长继续，不无限重选。
- WW-57：竞选只公开当选结果（当选者或警徽流失），不公开竞选票明细。
- WW-36：警长非自爆出局可指定活人接警徽；警长本人自爆直接警徽流失，不允许移交。
- WW-37：竞选阶段内两次自爆的分次判定见WW-60～WW-70；首爆不吞徽、次爆才吞徽。
- WW-38：已选出警长后，非警长狼人自爆不影响警徽；警长本人自爆按WW-67流失。
- WW-39：警徽流发言（几验几、警徽给谁）作为普通公开发言展示，框架不解析、不校验其真实性。

## 胜负条件

- WW-40：全部链条结束后，仅好人获胜条件成立（狼人全灭、未屠边）时好人获胜。
- WW-41：全部链条结束后，仅狼人获胜条件成立（平民或神职全灭、狼人未全灭）时狼人获胜；翻牌白痴计存活神职。
- WW-42：应有遗言、猎人开枪及连带出局/遗言、警徽处理等所有链条结束后才判胜负；双方条件同时成立则平局，终局不进入下一阶段。

## 信息边界

- WW-43：逐席捕获实际模型输入，狼人上下文含队友身份与狼队刀口记录；平民上下文不含任何身份、刀口、查验或药品信息。
- WW-44：女巫／预言家上下文只含自身角色的私有结果；单一角色的私有信息不出现在其他席位输入中。
- WW-45：旁观响应（HTTP与浏览器可见数据）在对局中不含身份、刀口、查验、用药、狼队交流；仅含公共阶段、存活状态、公开发言、公开票型与已公开结果。
- WW-46：正常结束后揭晓身份与完整隐藏行动记录；blocked/aborted/暂停不揭密。

## 界面与集成

- WW-47：竖版布局左右各6席、固定座位号，中央当前发言可读，下方公开记录；桌面居中，窄屏及低高度屏可滚动阅读。
- WW-48：页面只读，无麦克风、礼物、红包、邀请、设置、输入框或操作按钮；头像与装饰不暗示隐藏身份。
- WW-49：对局中公共进度不暴露具体神职调用及座位，仅展示“夜间行动”类公共阶段。
- WW-50：重启、重复提交、模型失败不造成重复行动或部分结算；失败房间无有效记忆与新游戏事实。
- WW-51：整局以真实模型跑通并记录证据；Docker镜像构建与既有回归单独记录，不以Mock冒充真实模型或真实PostgreSQL。

## 自爆与双爆吞警徽（跨夜机制）

可自爆时机：放逐轮流发言、PK发言、警上发言、退水发言、上警报名与发言之间的间隙，以及既有允许的普通放逐投票和首爆次日警长投票。允许阶段内可随时插队。
不可自爆：报夜死讯时、计票/唱票时、遗言中、移交警徽时、夜间。

- WW-52：多人夜死时从死亡者中随机选锚点，再沿当日方向取下一位存活者；单死者直接作锚点，平安夜随机选存活起点。随机结果须可持久化恢复。
- WW-53：有警长时由警长以独立动作决定顺时针／逆时针，方向对该轮全部发言生效；无警长时固定逆时针（座位号递减方向）。
- WW-54：非竞选允许阶段内非警长狼人自爆立即中断发言/投票；先补报未公开夜死，本轮出局连锁结算后未终局则进夜，不影响警徽。
- WW-55：自爆狼无遗言；自爆后当晚仍正常进入夜间行动。
- WW-60：竞选首日警上报名/上警发言阶段狼自爆为“第一爆”：不吞警徽、保存上警名单跨夜、公布昨夜死讯后直接天黑。
- WW-61：第一爆后的次白天继续竞选并进入退水环节，上警名单与未上警者状态与首日一致。
- WW-62：次白天退水环节有狼自爆→警徽流失、公布死讯、天黑，本局无警长。
- WW-63：次白天警上投票平票进入PK发言，PK阶段狼自爆→警徽流失。
- WW-64：第一爆后当天再无人自爆（退水与投票正常走完）时警长照常选出，不因曾发生一爆而吞徽。
- WW-65：仅一名上警者或仅剩一名候选人时自动当选；无候选，或需要投票却零有效票、无合资格投票者、重投仍平时警徽流失。
- WW-66：已选出警长后非警长狼人自爆不影响既有警徽，本轮出局连锁结算后未终局则进夜。
- WW-67：警长本人自爆立即警徽流失，无移交动作；此规则覆盖旧版允许指定活人接徽的用例。
- WW-68：不可自爆时机的提交被规则拒绝：报夜死讯阶段、计票/唱票阶段、遗言中、移交警徽时、夜间。
- WW-69：双爆局房规下不出现“单爆即吞徽”；单爆局房规则任一爆即吞徽（房规开关分别验证）。
- WW-70：未公布昨夜夜死的狼人仍可参与警上流程并在允许阶段插队自爆；吃毒狼自爆按自爆出局，毒药仍消耗，其他夜死正常结算，自爆狼无遗言。
- WW-71：每席每轮一次发言，单次发言超过配置的200字被Schema拒绝；模型层最多要求重出一次，仍超长则该决策失败。

发言输出规则 v3 的验收 WW-S01～WW-S05 见[需求 007](../.agents/note/007-speech-output-rules.md)。覆盖所有发言场景、真人与 Robot、配置版本恢复及共用指导前缀/私有 guidance 隔离。

## 公开证据链 v2（已确认）

以下用例对应[需求 008](../.agents/note/008-public-evidence-and-terms.md)。WW-E01 与 WW-E07～E12 所属的知识库范围已有实施证据；WW-E02～E05 的自动行为测试已通过，WW-E06 真实模型效果仍待验收。

- WW-E01：跨席捕获模型消息，金水／查杀／银水／对跳／自刀等固定定义的字节和顺序一致，位于公开历史与私有资料之前；动态座位和角色秘密不得插入此前缀。
- WW-E02：3号明确自称预言家并报7号金水、8号明确自称女巫并说救2号时，原文保留且提炼为带来源序号、原文摘录、发言者和目标的`claim`；实际身份、查验和用药不因此变成公共事实。否定、引述、假设、疑问、模糊及冲突说法仅留原文；孤立“7号金水”不能推断发言者亲自查验。
- WW-E03：同一发言窗口两名不同玩家明确自称预言家时，第二条公开后才形成有双来源的`counterclaim`；窗口未闭合、自爆中断或存在无法归类的身份相关发言时不产出“未识别到对跳”。正常闭合且可完整观察时才可按窗口与水位给出**有限观察**，不能写成无人说过或真实身份认证；后续公开对跳追加关系，不改旧发言。
- WW-E04：3号报7号金水不改变7号真实阵营；8号报2号银水不证明2号为好人，狼自刀样例仍可报银水。证据不带公共可信度分数，不强制各模型站同一边，也不修改裁判状态。
- WW-E05：警长／放逐的单人密封票在结算前不出现；`sheriff-votes`／`exile-votes` 公布后原事件的`ballots`完整保留谁投谁、弃票、轮次与票重，PK各轮不混合；不生成第二份独立票表。相同公开事件和阶段水位在不同模型席位、任务类型、重试与重启后得到相同公共历史；私有刀口、用药、查验及`after-game`事件不进入其他席位或公共旁观。
- WW-E06：从一局真实模型日志抽样检查后续发言能引用正确来源并区分声称与裁判票型；记录未识别自然语言与模型错误归因。自动测试和模拟模型不能替代真实模型行为评价，本项不设“所有自然语言均可识别”的承诺。
- WW-E07：当前板子的背景文件只加载一篇；板子 ID／内容改变后仅新局使用新摘要，运行中房间不热改；缺失或空白时拒绝新局启动。
- WW-E08：五类发言任务统一`SPEECH`、输出`{speech}`、裁判行动`kind:'speech'`；脚本、模型、默认动作、日志、事件和旁观展示一致，旧命名不再作为当前协议值。框架验收见[根需求 029](../../../.agents/note/029-speech-terminology.md)。
- WW-E09：权威阵容含六种职业，六篇公开描述按固定 ID 顺序进入每个席位；本人指南恰好一篇，其他职业指南不进入该席请求或公共 DTO。
- WW-E10：`knowledge/terms`的每篇词条均按固定 ID 顺序进入所有席位，不按身份、当前阶段或板子过滤；新增词条后重启，新局知识摘要变化。
- WW-E11：同板子、同公开水位的不同职业，板子＋全职业＋全词条＋公开历史字节相同；其后才是本人指南与当前命中 ruleset。只在 SPEECH 命中的发言指导不进入 SELECT，也不抢在共享知识之前。
- WW-E12：缺失、空白、重复 ID、非法文件路径、版本不符、必需 token 预算超限均显式报错；本机和 Docker 构建均能读取 MD；不创建数据库表、不追加模型调用或默默删减词条。

## 公开状态共享段 v4（待确认）

以下为[模型接入方案 v4](model-integration-v1.md#公开状态共享段-v4待确认)的待审行为用例，尚未生成或运行可执行测试；通用组装用例见[MC4](../../../docs/testing/model-context-cache-v2.md#v4-公开状态共享段待确认)。

- WW-C4-01：同一冻结水位的平民、狼人、女巫、预言家分别构造任务；`public_history` 和 `game_state` 及其实际消息字节相同，身份、人设、队友、查验、刀口、药量、私有事件和技能资格只在授权个人段。直接从含 `self` 的角色视图构造共享段应被测试发现，不得靠当前对象展开碰巧不泄漏。
- WW-C4-02：首夜刀口已定但未公告、女巫救人而平安夜、夜死公告发布三个时点，`game_state.players`、`last_announced_night` 与旁观可见状态一致；公告前不出现实际死亡，公告后与公开历史中的裁判事件一致。发言中的“我救了 2 号”只留在历史主张，不进入当前裁判状态。
