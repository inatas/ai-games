# 狼人杀网页模型测试台 v1（待确认）

关联[需求 005](../.agents/note/005-web-model-test.md)、[框架日志设计](../../../docs/specs/model-test-observability-v2.md)和[验收说明](web-model-test-testing-v1.md)。本页仅列 MOD 界面与接入，不复制底层日志协议。

## 页面流程

1. 在现有“座位管理”中选择 12 个不同 Robot，设定种子；模型席可从服务端公布的可用 profile 中选一个，脚本席不显示 profile。默认沿用 Robot 当前配置。页面展示 profile 名和模型名，不显示 URL/Key。配置草稿可在刷新后恢复，但新局始终需要点击“开始游戏”。
2. 开局请求带阵容、每席 profile 与幂等 requestId；服务端校验并冻结到持久房间。页面显示房间 ID，可复制；刷新和服务重启后按 ID 回到这一局。使用现有固定阶段计时，无暂停、快进、额外调用或预算估算。
3. 对局进行中沿用牌桌和对局历史，展示阶段、当前席位、剩余时间、已公开发言及结算票型。终局沿用现有身份/夜间行动揭晓与合并历史浮层，不从模型技术日志拼游戏回放。
4. 在同一页面新增“模型诊断”入口，操作者输入服务端测试口令后可打开。顶部显示调用开始/成功/失败/结果未知数量、实际 input/output token、已报告缓存命中率与未报告调用数；列表按时间排序，支持座位、阶段、结果筛选。每条显示请求 ID/attempt、模型 profile、耗时、错误码、HTTP 状态与 Schema/裁判状态。详情才显示实际 messages 和原始返回，并显著标为私密诊断。口令只在当前标签页内存保存，刷新后重新输入。

## 开局接口

`GET /api/werewolf/model/profiles` 只返回已配置且可用的 `id/label/model`，不返回环境变量名、URL 或密钥，须携带测试口令。现有 `POST /api/werewolf/model/start` 增加可选 `profileIds: (string|null)[12]`，与 `userIds` 按座位对应；未提供时沿用 Robot 文件默认 profile。脚本席对应 null，模型席必须填服务端登记的 profile ID。服务端针对每个 profile 构建一个可用适配器，并把选择写入当前房间席位的 `modelProfile` 字段；重启仍按冻结绑定恢复，不能用后来更改的默认 Robot 文件重选。`requestId` 的阵容签名同时包含 seed、userIds 和 profileIds；同 key 不同配置返回冲突，不复用旧局。服务器配置改变使房间所需 profile 不再可用时，房间显式报不可用并保留原日志，不自动切脚本。

## 权限和状态

普通牌桌快照、对局历史与终局回放仍使用原有投影，诊断和席位私有视角需要测试口令。失败 API 不等于行动成功；若阶段截止采用默认动作，流程中显示真实裁判结果，诊断中显示调用失败及默认原因。服务端没有配置模型 profile 时页面说明不可用而不是把模型席悄悄切脚本。旧房间可以展示已有日志和回放；缺失新错误字段标为未记录。

本版不修改牌桌中心视觉设计、不新增日志驱动回放、不做远程管理员、密钥编辑、可变倍速或历史临时库恢复。实现顺序先服务端 profile 校验/持久绑定及诊断摘要，再网页界面与真实模型验收。
