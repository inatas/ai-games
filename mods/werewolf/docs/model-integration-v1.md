# 狼人杀模型接入开发方案 v1.6

状态：开发方案持续完善；前述四项设计判断、人格配置模式及多模型席位均已由用户确认写入文档；具体参数与其余未决项不因本次确认自动获批。v1.5将SELECT候选数组改为“以selected为准、候选仅作日志”的用户最新裁定，取代v1.4的“按权重随机计算”提案；v1.6进一步裁定候选使用宽松校验，并把“非法selected等同于没有合法输入、按超时默认结算”纳入首版实施范围。相关章节仍待确认，未获确认前不实施。本轮无实现代码、迁移或真实模型调用。所属需求001。

## 已确认设计汇总（v1.3）

用户要求将此前四个问题的确认一并写入，以下作为本方案当前设计依据：

1. **超时默认属于游戏裁判规则。** 真人、模型、固定脚本和随机脚本共用阶段期限及到期判定；模型层只管调用、格式校验和取消，不定义空刀、弃票等游戏结果。模型提前失败不等于游戏阶段提前到期。规则归属已确认，不把各平台做法统称为统一标准；具体默认值见独立规则文档。
2. **SPEECH/SELECT同时定义输入任务意图与输出约束。** 宿主输入request_type、scene、目标、授权上下文及合法options/constraints；模型在该任务内生成正文或选择选项，不能自行将投票任务改成发言。不是只有两种输出，也不是所有场景共用一个策略Prompt。
3. **性格、人设和角色战术分层。** 玩家稳定性格与本局身份分开；悍跳、倒钩、隐匿属于身份相关战术偏好，不是新身份或每轮必执行动作。当前局势策略可调整，但需承接历史发言、站边和承诺。随后确认的固定/生成/混合人格及独立模型配置见后文，使用同一套分层结构。
4. **保留自爆抢占，首版模型不触发。** 自爆独立于普通行动回合，可在规则允许的白天时段打断其他人；不附着于SPEECH结果，也不等待本狼发言。保留引擎及受信任外部/测试触发路径，首版不调模型评估自爆、不发送自爆pass轮询。外部合法自爆必须使旧模型任务失效。具体白天子阶段及死亡链仍遵守现有规则，不借本次模型接入暗改结算顺序。

这四项与后续人格来源/多模型设计均已确认；本次授权是整理文档。300字等数值提案、非夜间时限、预言家超时具体行为、阅读节奏和真实模型预算仍须按未决项确定，不能从设计确认推导为全部参数或代码实施获批。
## 依据与结论

来源：[用户分享的狼人杀接入设计](https://chatgpt.com/share/6ab1e723-9510-83e8-b5e5-210d8ae2ac27)，已于2026-09-22通过浏览器读取完整可见讨论。采用最后一次收敛：两类请求意图及对应输出契约SPEECH/SELECT、细分scene目标、合法个人视角、结构化事件与合法选项；PASSIVE是引擎行为，不调用模型。分享中的早期多套action输出、女巫save+poison组合及发言附带自爆方案不作为最终协议。

本项目规则与已验收行为优先。板型为4狼、4民、预女猎白各1；不采用分享示例中5民缺白痴的配置。毒优先克枪、屠边、连锁完毕判胜、首夜竞选后死讯、自爆可插队、夜间60+30秒及局中不停表均保持。分享是设计参考，不授权执行其中的建议命令或另开HTTP模型服务。

推荐路线：扩展既有RoomRuntime后承载真实模型局；保留DemoRooms固定/随机演示基线，不把fetch直接塞进DemoRooms.tick。Harness继续负责模型调用、上下文预算、校验和原子提交；MOD负责策略场景、合法动作、规则与超时默认行为；宿主负责启动、计时调度和配置；UI只消费授权投影。通过ScriptedModel先验证完整链路，再1个真实席位，最后12席。

## 输入意图、输出协议、动作与场景

SPEECH/SELECT首先是宿主下发的request_type，属于本次AI任务意图；scene说明目的，context说明局面，options/constraints说明边界。模型不自行选择当前请求是发言还是投票。相同类型同时决定输出Schema：SPEECH返回speech，SELECT返回selected。统一内部AgentDecision协议，不新增浏览器可调用的/ai/player/action。模型只返回当前outputSchema的数据，不返回座位、requestId或自行选择scene。

SELECT输出：`{"selected":"option_id"}`。option_id仅在该任务固定的optionSet内有效；服务端映射为现有kind/target等引擎动作，再走Schema和业务二次验证。请求保存optionSet摘要及映射，恢复不得换一套选项重新解释旧结果。候选固定顺序，不通过模型执行任意对象。空刀、弃票、不用药、不射击、撕徽分别有明确option_id，不用一个含糊的null表达所有行为。v1.5在此基础上增加可选的候选数组，该数组仅作日志、不参与判定，SPEECH契约不变；完整提案与待裁定项见下文“SELECT候选列表”。

SPEECH输出：`{"speech":"正文"}`。当前由狼人杀规则文件限制最多200字符，拒绝空白和超限；映射speech或last-words。公共发言是角色表达，可以欺骗，不做“必须说真话”的验证；系统事实不得由发言修改。analysis_summary首版不要求，不记录/展示完整思维过程；如以后启用简短决策摘要，只写该席位内部审计，不发到旁观、历史或对手上下文。

所有Schema additionalProperties=false；SELECT使用当前option_id枚举；不解析Markdown代码围栏，不猜测非法目标。模型格式JSON/Schema错误沿用Harness最多一次纠正，业务非法不自动换目标。Provider不支持Schema枚举时仍在本地严格校验。

### 六区内容与统一决策入口（2026-09-23增量，待确认）

六区是每次行动的授权输入结构，不是另一个绕过Harness的prompt。MOD从当前席位的`actorView`生成`rules/game_state/self/private_information/public_history/current_action`；游戏决策入口同时给脚本和模型Robot同一份授权任务与合法选项。脚本就地选择，模型经Harness组装与校验，最终都返回引擎可验证的提案；无有效提案统一由本MOD的截止规则处理。通用契约见[Robot运行时v2增量](../../../docs/specs/robot-model-runtime-v1.md)。

`public_history`必须支持按事件水位读取公开发言原文及顺序，保留遗言、上警、PK、放逐发言的阶段标签；投票为`from/to/round/weight/result`结构，不能只保留“某人得票最高”。将公开身份主张与本局真实身份分开，并从本人已提交发言提取可追溯承诺。近期和与本次行动直接相关的记录列为必需，更早原文可选择带来源摘要。具体必需窗口与预算仍需裁定和长局测试；不能保证把所有历史原文无限放入模型窗口。夜间未公布死讯、未结算密封选择及他人私有信息不进入六区。

## SELECT候选列表（v1.5：仅日志，待确认）

用户2026-09-22先提出SELECT增加候选与概率数组、由游戏按分布判定；随后改为最新策略：**以`selected`为准**。模型`selected`与游戏逻辑矛盾时**不执行**，等同于玩家在游戏中提交一个非法输入；`candidates`候选列表**只作为日志供参考**，不参与判定。本节以最新裁定为准，先前的“按权重随机计算”作废，不并行保留两套语义。本节仍为待确认提案，不包含实现。

### 输出协议（提案）

SELECT输出为`{"selected":"option_id","candidates":[{"optionId":"12","weight":60},{"optionId":"8","weight":30}]}`：

- `selected`必需且是唯一权威值；Schema校验、`option_id → kind/target`映射及业务二次验证与v1.3完全一致。引擎只执行`selected`，与其他任何字段无关。
- `candidates`可选，纯日志信息：不参与判定、不改变游戏状态、不触发抽样，也不得因它改选、重试或补正目标。
- 元素为`{optionId, weight}`；`weight`为0—100整数、按相对权重解释，不要求合计为100（用户示例60+30=90成立）。字段命名与取值范围待裁定。
- `optionId`沿用optionSet标识（座位场景即座位号，动作场景即“救/不救”等既有option_id），不新增第二套命名。**用户裁定（2026-09-22）**：候选采用宽松校验，只需为数组、元素含字符串optionId与整数权重即可，不强制限定在optionSet内。理由是只读日志字段不应具备让一次合法`selected`变成格式错误的能力。
- 用户原话为“json二维数组”（如`[["12",60],["8",30]]`）；建议按对象数组落Schema，如确认必须使用二维数组则仅替换编码，不影响其余契约。
- `additionalProperties=false`继续适用；`candidates`缺省时Schema与v1.3兼容。SPEECH输出与请求不变。

### 判定与执行（提案）

- **用户裁定（2026-09-22，最新）**：以`selected`为准；`selected`与游戏逻辑矛盾时不执行，等同于玩家提交非法输入；`candidates`只作日志参考。此裁定取代同日早些时候的“通过`candidates`随机计算结果”。
- 引擎只执行`selected`：不做抽样、不消费随机数、不因候选列表改选目标，因此不存在“只抽一次”的幂等约束；`proposal`原文与`selected`继续按现有方式持久化，Harness无需任何改造。
- 候选、权重以及`selected`被拒绝时的原因码（`MODEL_INVALID_OUTPUT`／`RULE_REJECTED`）只进内部审计，不进入公共旁观DTO、历史或对手上下文；夜间不得因异常提示泄漏角色生死或人数。
- 由于候选不执行，`WITCH_ACTION`等场景不再需要多候选白名单：即使模型在日志里同时列出救人与毒人，也只是可观测的困惑信号，不会产生同夜双药。
- 该能力属MOD侧协议与解码，不新增框架公共能力；若以后要推广到其他游戏，再按019 v3单独评估。

### 非法selected的处理（提案，待确认）

引擎已把合法目标集合写进请求Schema，例如放逐投票只枚举存活且未翻牌座位加弃票（`src/match.ts`），女巫为不用药/救人/毒人三选一的`oneOf`；因此“投票给已出局座位号”在请求阶段就不在enum内，属于格式错误而非业务错误。按“非法输入即不执行”的语义，建议处置链如下：

| 情况 | 处理 | 依据 |
|---|---|---|
| `selected`不在optionSet内 | Schema拒绝，触发Harness最多一次纠正；仍非法则`MODEL_INVALID_OUTPUT` | 现有枚举Schema与最多一次纠正 |
| `selected`在optionSet内但提交时已不合法（局面在阶段内变化） | 业务校验拒绝`RULE_REJECTED` | 已确认“业务非法不自动换目标” |
| 被拒绝之后 | 该席本次没有合法动作：不执行、不换目标、不二次调用模型、不从候选补正 | 用户2026-09-22裁定 |
| 提交前阶段或epoch已变化 | 按`PHASE_CONFLICT`失效 | phaseInstance/decisionEpoch |
| `candidates`内容异常 | 只影响日志，不改变判定；可选记录`CANDIDATES_IGNORED`审计标记 | 候选仅日志且宽松校验 |
| 该席最终没有合法动作 | 与超时、断线、人类弃权走同一路径：阶段不提前结束，到期由裁判按该场景默认结算（投票→弃票、狼刀→空刀、女巫→不用药、猎人→不开枪等） | [行动截止与默认结算](action-deadlines-v1.md) |

**用户裁定（2026-09-22）**：输入非法属于游戏判定逻辑，与模型无关；模型产出的数据不能用时，直接以“该席没有合法游戏输入”处理，等同于超时默认结算，不新增模型专属的失败分支。

执行细节：默认结算在**该阶段截止点**应用，不在判定失败的那一刻立即应用。理由与既有裁定一致——模型提前失败不等于游戏阶段提前到期；密封与夜间阶段若立即结算，会通过时长或事件泄漏该席角色生死与人数（例如女巫是否还活着）。阶段固定时长与公共提示不变。

范围影响：当前已实现的v2运行时在决策failed/rejected时直接把房间置为`blocked`，并不等待期限执行默认结算；`fallbackDecision/timerPolicy`属v3提案且默认保持原阻塞行为。按本次裁定，“非法选中即无合法输入、截止点默认结算”属于首版必须落地的能力，需随v3在本MOD接入时一起实现，不再留作后续。

### 待裁定

1. 权重字段命名（weight/probability/probabilityPercent）、取值范围（0—100或0—1000）、是否允许只有一个元素，以及是否要求与`selected`一致。建议不要求一致，日志应如实记录模型输出。
2. 二维数组还是对象数组（对象数组更易扩展与校验）。

已裁定并移出本清单：候选采用宽松校验、仅作日志（见“输出协议”）；非法`selected`按“没有合法输入”处理并在阶段截止点默认结算（见“非法selected的处理”）。

当前只有固定十二人预女猎白板，职业 ID 是 `wolf/villager/seer/witch/hunter/idiot`；知识装载器从创建该局所依据的权威阵容取得职业集合，不另写与裁判可能漂移的手工名单。不同板子的背景文件可不同，未来板子增加时使用其阵容选职业描述；不在本次开发第二套可玩的板子。通用词条无板子筛选，新增一篇 Markdown 后重启即可统一加载。公开职业描述可讲能力与限制，不能写实际持牌座位；本人操作指南不能扩展模型的游戏权限。板子、职业、词条和指南由人手工编辑，均非 TS 代码、RAG 搜索结果或动态行动规则。

知识装载时逐文件校验非空、ID 唯一及合法路径，按 ID 固定排序，计算有序内容摘要并固定在新局定义版本。服务重启后编辑生效，不热改运行中房间；若恢复的房间版本与当前文件不符，显式拒绝，不删除房间或用新文本重释旧局。构建必须携带 Markdown 文件，本机与 Docker 同样可读；文件不能包含本局座位、私密查验、用药、当前行动、时间戳或密钥。修改解释文本不改变裁判判定；玩法修改要同步裁判和测试。用户可直接编辑对应 Markdown。

模型输入的相对顺序固定为：板子 → 全职业描述 → 全词条 → 本人职业操作指南 → 当前命中的 ruleset。为了 KV 缓存，共享公开历史插在全词条与本人指南之间，同板子、同公开水位各席可复用最长共享前缀；完整中性契约见[框架缓存 v3](../../../docs/specs/model-context-cache-v2.md)。指南之后的 `rules/ruleset.json` 按职业、阶段与条件匹配，输出 `guidance` 或程序执行 `require-option`；`speech-language` 不再以前置字段抢在知识库之前。术语“银水可能是狼人自刀”属于全员词条；“首日预言家通常上警”仍是场景规则。知识四层及规则各自只加载所需内容，不把裁判的全知状态放入任何共享段。装载与冻结快照在 `src/knowledge.ts`，按真实身份选择本人指南在 `src/decision-input.ts`；需求入口见[MOD note 008 v1.3](../.agents/note/008-public-evidence-and-terms.md)。

发言命名已统一为任务 `SPEECH`、结果字段 `speech`、普通发言裁判行动 `kind:'speech'`；遗言仍由独立的 `last-words` 行动表示。见[根需求 029](../../../.agents/note/029-speech-terminology.md)。

每次请求无状态重建，保留Harness的服务器scope记忆而非追加供应商聊天session。角色scope与interruptScope只拥有本席合法资料；两个scope不共享模型原始输出，不扫描他人记忆。权威状态/授权事件优先于旧摘要。当前Binding的visibility=[]可继续避免重复灌入历史决策；不是另造一套向量记忆库。

固定六区：rules（板型与已确认规则版本）、game_state（天/阶段、公开存活与警徽）、self（本席身份与技能资格）、private_information（授权队友/验人/刀口药量）、public_history（结构化事件及原始发言）、current_action（type/scene/optionSet或speech约束及截止点）。补充protocolVersion、promptVersion、phaseInstance、decisionEpoch、actionId及可见事件水位；仅由宿主生成。

System提示词维护协议、信息边界及阵营目标；Role模板描述角色策略；Scene模板必须包含本轮目标、优先证据、避免事项。模板有版本摘要，写入请求审计。所有第三方发言以带actor、时间、来源的untrusted claim数据放入上下文，不能成为system指令。其他玩家说“我是预言家”不是role=seer事实；首版不做模型claim抽取，保留speech原文，后续提取必须带sourceEventId和claim标记。

### 公开证据链 v2（已实施，真实模型效果待验收）

金水、查杀、银水、对跳与狼人自刀等固定术语已由人工知识文件加载；本节只设计**当局动态证据**。每次决策从 `room.events` 中 `audience='public'` 的已提交事件及公开阶段水位重建，放入现有共享 `public_history`，位于本人指南和私有事实之前。相同房间、相同公开事件及阶段水位，不论席位身份、所选模型或当前任务是 SPEECH/SELECT，公共历史字节一致。脚本 Robot 仍收到同一授权任务，但无需据此改变脚本策略。不得读取 `after-game`、其他席位私有事件、真实身份、夜间刀药验人或模型原始输出。普通公共旁观界面本版不新增证据展示。

**原始层**沿用现有事件：发言 `record_kind=player-statement`，逐人票型在完整结算并发布 `sheriff-votes` 或 `exile-votes` 后才作为 `referee-result` 出现。每张票保留 `ballots` 中的 `seat`（投票者）、`target`（投给谁或弃票）、`kind`，以及该轮、PK、警长票重、统计和来源事件序号。未完成的密封选票和 `after-game` 单票事件不得提前入链。原有票型已经是权威结构，不再复制为第二张持久或推断票表；模型可由同一公开事件读出“谁票了谁”。

**提炼层**仅为公开发言生成 `record_kind=derived-public-evidence` 的非权威条目。最小字段：`evidenceId`（由来源与类型稳定派生）、`sourceSequences`（一个或多个公开事件序号）、`day`、`phase`、`actorSeat`、`kind`、`status`、`quote`；有明确目标才加 `targetSeat`，有明确报告才加 `reportedAlignment`，关系条目加 `otherActorSeat`。`status=claim` 表示“此人如此声称”，`status=observed-relation` 表示“公开记录中存在两条互相对跳的声称”，绝不使用 `verified`、真实身份或公共可信度分数。例如 3 号说“我是预言家，7号是我查验的金水”，可产生“3号自称预言家”和“3号声称查验7号为好人”两个条目；8号说“我是女巫，昨夜我救了2号”，只产生其自称与救人声称，不确认实际刀口或用药。7号实际阵营、2号是否银水由各席自行判断；银水不能排除狼自刀。

识别器采用版本固定、确定性的**明确句式白名单**：本人直接肯定声明身份（如“我是预言家／女巫”）、本人直接报某座位的查验结果或救人行为（如“我查验7号是好人／狼人”“我给7号发金水／查杀”“昨夜我救了2号”）。仅孤立出现“7号金水”可保留为该玩家的公开评价，不推定他亲自验人；否定、疑问、引用他人说法、假设、将来时、无法定位座位或同一语句相互矛盾时只保留原文，不提炼成确证。白名单及优先级随 MOD 规则版本固定；不使用另一次模型调用去提取，覆盖不到的自然语言仍完整留在原始发言。原始发言作为不可信数据传给模型，提炼文本不能执行指令。

同一白天的同一发言窗口内，两个不同座位明确自称同一身份时，在第二条声明公开后派生 `kind=counterclaim`，引用双方序号；不裁定谁真谁假。窗口以阶段类别、天数及竞选/放逐轮次标识：普通上警发言、警上 PK、普通放逐发言、放逐 PK 各是独立窗口，单人遗言不用于“无人对跳”推断。仅在该窗口正常转入退水／投票／下一阶段、相关发言机会均已关闭后，才可派生 `kind=no-extracted-counterclaim`，明确写“截至本窗口结束，未识别到其他明确同身份声明”，附 `windowId` 与 `observedThroughPhaseInstance`。窗口未结束、被自爆打断或存在含身份关键词却无法可靠归类的发言时不产生该条目；后续公开声明或翻牌产生新条目，不修改旧来源。一个窗口的无已识别对跳不证明无人说过、也不证明声称身份为真。

提炼是 `src/public-evidence.ts` 的纯函数，由 `src/decision-input.ts` 在组装公共历史时调用；不建数据库表、不写房间事件、不触发模型或改变裁判；按事件顺序及公开阶段边界排序，稳定重建使同一水位的重试、恢复一致。新增推断只能在其来源全部公开后进入模型上下文，不能追溯插入旧请求已见的前缀。识别器版本纳入狼人杀房间定义版本并用于恢复核对；部署前核查运行中模型房间，旧版运行中房间不得被新识别器悄悄改写上下文，无须清理已结束记录。同步更新模型服务的定义版本识别。必要事实和结构化票型不静默截断，沿用现有输入预算超限处理。私有查验、狼刀和药品继续仅在获授权席位的后部私有区；模型不能获得人工标记、终局真相或他人记忆。验收见[WW-E02～E06](mvp-testing.md)，需求入口见[008](../.agents/note/008-public-evidence-and-terms.md)。

预算：必需规则、自身授权事实、合法选项、结构化投票/死亡/警徽/查验不能静默截断；当前轮发言完整，前一轮关键证据优先。首版先测全量授权上下文，超预算明确失败并走已确认兜底，不能随意截掉前一天。长局压缩作为后续阶段：按该席视角生成有事件来源的摘要，旧正文留库、关键原文保留；摘要不能替代事实。模型窗口/token预算以所选profile为准，本轮不猜供应商最新规格。

### 每席个人判断 v1（已实施，真实模型待验收）

需求入口为[MOD 012](../.agents/note/012-personal-evidence-memory.md)，通用附加输出与内部 fact 机制见[根需求 031](../../../.agents/note/031-decision-private-memory-update.md)。这是 008 已实施的**共享公开证据**之上的本席策略记忆，不改变 `public_history`、裁判状态或知识库。

**输入**仍使用现有六区、四层知识及后部 `REQUIRED_MEMORY`，不增加第七区、不把个人判断插入共享 KV 前缀。框架仅按本次普通行动的角色 `scopeId` 取 `factKey='werewolf.personal-evidence.v1'`、`visibility='internal'` 的最新 fact。该 fact 的 `payload` 是本席当前判断集合，来源仅为已公开事件与本席授权的私有事件；同房其他席、其他房间和 interrupt scope 不可读。当前事实与已执行结果优先于旧判断；模型应在新证据出现后修正或撤回旧判断。

**输出**在原行动对象旁增加可选 `personal_evidence_update`。模型提示要求在每次 SPEECH/SELECT 都给出更新；无变动可给 `{ "upserts": [], "removeKeys": [] }`。实例（仅示意字段，不宣称 3 号真实身份）：

```json
{
  "selected": "vote-3",
  "personal_evidence_update": {
    "upserts": [{
      "topicKey": "role:3:seer",
      "judgment": "暂时更相信3号是预言家，但尚未得到裁判证实",
      "basis": [{ "visibility": "public", "sequence": 18 }]
    }],
    "removeKeys": []
  }
}
```

SPEECH 时同一字段与 `speech` 并列。`speech` 必须满足现有非空与 200 字上限，`selected` 必须属于本次合法选项；附加字段不参与行动解码。原顶层 Schema 仍只允许行动字段与该可选字段，附加字段本身在模型响应 Schema 中宽松接收 JSON，由 MOD 另行严格验证：`upserts` 0～2、`removeKeys` 0～4；每个 `topicKey` 长度 1～64 且仅含小写字母、数字、冒号、点和连字符；`judgment` 1～100 字；`basis` 1～3 个 `{visibility:'public'|'private',sequence:正整数}`。来源必须在本次冻结的公开历史或本席私有事件中，不能引用 `after-game`、未结算操作或他人私有事件；移除项只能指向已有判断 key，同次不得重复或既增又删。合并后最多 24 条，超限整份附加更新作废，不截断。`judgment` 是观点，不能被程序提升为身份或阵营真相。允许观点彼此不同，不设全局可信度分数。

收到**可解析、大小合规的 JSON 且行动合法**后，MOD 对附加字段作独立校验；字段缺失、`null`、类型错误、无效来源、超限或相互冲突时，忽略全部附加更新，合法行动照常提交，不为判断单独重试或触发格式纠正。完整 JSON 无法解析、`speech`/`selected` 不合法或游戏业务拒绝仍走原有严格决策流程。合格更新在当前行动提交事务中与本席旧 fact 按 `topicKey` 合并，用内部 `replace_fact` 保存；重复请求、阶段过期、抢占或默认动作不能生成新判断。脚本 Robot 和强制规则动作不增加此输出。模型原始响应继续按现有私有调用审计保存；新判断不进入公共事件、旁观、回放或对手上下文。不增加模型调用；为容纳 200 字发言和有界更新，狼人杀模型的 `outputBudget/maxOutputTokens` 由 500 提至 800，额外输出 token 依真实供应商 usage 记账，原行动截止时间不延长。

## 期限、并发与抢占

夜间固定90秒，前60秒狼人与预言家共享一个截止点，同时登记各席任务；后30秒女巫窗口，狼刀封盘后才构造上下文。即使技能角色死亡或提前返回，公共时间和提示不变。可在私有暂存区收集早到结果，到固定边界才公开允许的信息；不得因执行完成速度泄漏角色是否存活。

当前阶段数值以[狼人杀计时表](phase-timing-v1.md#计时表)为准；模型与脚本使用同一裁判截止，不另设模型时限。排队、调用、一次格式纠正、校验和提交均计入原行动截止点。`network` 错误按下述有界策略重试，恰好到期判迟到。短调用失败可以内部标记等待默认动作，不能提前公布“某神职失败”。默认结算见[行动截止规则](action-deadlines-v1.md)。

网络重试 v1.1 见[狼人杀需求010](../.agents/note/010-model-network-retry.md)与[框架需求030](../../../.agents/note/030-bounded-model-network-retry.md)。狼人杀模型服务启用框架的每决策最多 3 次实际 HTTP 调用策略：首次调用后，仅 `network` 错误可依次重试最多两次；3 次总额度也覆盖最多一次格式纠正。第一次重试在前次失败事件持久化后等待至少 1 秒，第二次重试在其前次失败事件持久化后等待至少 3 秒；每次额外随机等待 0–500 毫秒，本地调用不与前一次重叠。退避后剩余行动时间至少 10 秒才准许该次重试；调用时限为 `min(45 秒, 剩余行动时间 - 5 秒提交余量, 剩余 Harness 总时限)`，时限不为正则不重试。同一 profile 同时最多 2 个重试，10 秒内连续 3 次网络失败则熔断 15 秒，仅放行 1 个探测调用。熔断阻止同 profile 新增调用，已经在途的响应仍可在原截止前提交；熔断不延长截止、不改默认动作、不跨模型 profile 切换。

自爆是独立于普通发言/选择的游戏抢占事件，不能塞进SPEECH输出或只在本狼回合检查。未来模型可在新公开信息到达时异步评估是否抢占，但这需要额外延迟、成本和竞态设计。按用户本轮取舍：首版modelSelfDestruct=false，不启动模型自爆评估，不向普通SELECT加入自爆选项，不轮询或生成pass模型请求；保留引擎acceptInterrupt和受信任宿主/测试的自爆提交路径，不新增普通观众自爆按钮。发生外部合法自爆时，仍使正在生成的旧模型输出失效并按游戏链条进入夜间。

用户表述白天任意时刻自爆，意图是可以插队打断别人，不等自己发言；当前具体可用子阶段仍由规则层校验。本轮不顺带扩展到已禁止的猎人结算/遗言等链条，若需覆盖这些子阶段，应另行裁定。白天即时抢占能力保留，不因关闭模型触发而被删除。
多人密封阶段按席并行登记与执行，终局结算按phase.actors固定顺序，结果不能因网络返回先后改变随机抽选。并行普通提交不能逐个提升全局失效epoch而杀死同伴；只在换阶段、抢占/失效时更新全局epoch，单席任务以actionId/版本防重。Provider并发限额需能容纳夜间5个普通任务；做不到则在开局配置时提示，不偷偷延长60秒。

## 游戏截止与默认结算

统一规则正文见[行动截止与默认结算](action-deadlines-v1.md)。模型只在期限内产出候选动作；超时、缺席、断线、无有效输入的最终处理由游戏裁判决定，适用于人类与所有AI/脚本参与者。提前模型失败不等于游戏时间已经到期。格式纠正次数、网络请求取消和供应商错误归模型层；空刀/弃票/不用药/跳过发言归游戏规则层。

正常结果、超时结算及抢占由同一actionId终态与房间短事务裁决，只能一次有效提交。旧模型成功/失败不能覆盖新阶段。空合法选项、规则错误或数据库错误应blocked，不伪装成合法默认。具体默认值的确认归游戏规则文档，不在模型方案中重复维护。
## 发言UI与可读节奏

不再使用Demo currentSpeech预填固定句子。模型生成中显示当前发言座位与“正在组织发言”，未校验片段不写历史、不广播；完整合法SPEECH提交后，只由已提交事件填充中央纸纹气泡和历史。切换旁观视角不触发新模型调用。

用户随后明确：提前返回的模型结果原则上不缩短任何流程。每席发言、遗言、猎人等都走满已确认的阶段倒计时；只有该席主动触发明确的“跳过本回合”操作才能提前结束，当前纯Robot局没有此操作。模型已提交的发言在本席剩余时间内显示，全文在历史保留。夜间固定60+30秒，女巫死亡时第60秒封盘狼人与预言家行动，再等30秒才进入白天。

首版不做token流式广播、RTC、倍速或可播放复盘。保存seed不能复现真实模型输出，复盘依据已提交事件；审计保存profile、实际返回model、prompt版本、上下文/选项摘要、耗时、用量、纠正次数和默认原因，不把私密内容发到公共DTO。

## 配置、装配与安全边界

模型局由apps/server受信任配置装配RoomRuntime/Store/MOD；每席modelProfile可为scripted或真实profile，密钥只从服务端环境读取。浏览器只能选白名单profile名，不提交baseUrl、Key、scopeId或任意Prompt。沿用既有适配器，不为狼人杀复制HTTP客户端。profile定义到适配器的装配、Robot用户与席位的绑定，以及路由/调用/上下文/输出四段的通用契约见[Robot模型席位运行时v1](../../../docs/specs/robot-model-runtime-v1.md)；本文只拥有狼人杀场景、合法选项与SELECT/SPEECH契约。

为真实模型局提供独立路由前缀，与/api/werewolf/demo保留清晰分隔；页面选择无模型/模型局并显示请求预算和局状态，私密调试座位切换仅local host开放。真实供应商、profile、并发和局请求预算在首次付费运行前确认，本轮不读取密钥、不调用付费服务。

按房间保存期限、选项、待处理任务、展示状态及事件；模型等待期间不持锁。启动先恢复房间，已提交请求重取，不重新请求模型；未过期任务按lease/requestId恢复，已过期一次兜底；关闭时取消调用，不删除持久事实。旧内存演示不迁入持久局。框架文档保持题材中性，真实数据库验证使用独立测试schema，不从启动脚本自动清库。

## 玩家性格、人设与角色策略（v1.2设计已确认）

性格属于玩家Agent，身份属于本局分配；同一性格可以抽到狼、民或神职。倒钩/悍跳属于狼人战术倾向，不等同于通用性格，也不是新的游戏角色。配置分为以下三层，具体字段和数值是待实现验证的协议建议：

1. persona：稳定性格，包含riskTolerance、assertiveness、deceptionWillingness、teamOrientation四个0—1倾向，以及speechStyle（简洁/温和/强势等）。不是模型隐藏推理链。
2. roleStrategy：当前身份下的策略偏好。狼人可配置preferredTactics=[counterclaim, busTeammate, blendIn]及权重，表达悍跳/倒钩/隐匿倾向；预言家与女巫使用各自策略维度，不能把狼战术直接套给所有身份。
3. matchPlan：本局已经采用的身份主张、公开站边和可追溯承诺。首版从自己的已提交发言/行动重建，不要求额外一轮模型写计划；后续结构化计划更新只能进入本席私有记忆。

示例两个独立的persona配置：
- 谨慎隐匿型：riskTolerance=0.25、assertiveness=0.3；拿狼时偏blendIn/busTeammate，发言克制，少主动悍跳。
- 强势进攻型：riskTolerance=0.8、assertiveness=0.85；拿狼时偏counterclaim，主动争警徽、给出明确票向。

战术是倾向而非每回合硬指令。倒钩狼不能无条件投队友，悍跳狼不必每局第一轮跳预言家；合法动作和阵营胜利目标优先，局势证据可以改变策略。不同狼人可有相同或不同persona，不能保证只靠Prompt就稳定呈现差异，因此需要多种子对比验收。

服务端AgentProfile保存人格配置、roleStrategy与独立的决策模型profile及人格生成模型profile；固定配置和开局生成使用同一份已解析人格结构，开局固化进房间配置/审计，同局不因重启随机换人格。不在公共UI、对手上下文或选座列表展示策略标签，防止标签泄露身份；本地管理员配置与普通座位旁观权限分开。首版用受信任配置文件，不新增复杂人格编辑器。

输入在self/agent区加入本人persona与roleStrategy；提示词按system规则→persona→role→scene→当前授权事实组合，并声明persona不得覆盖合法选项。建议请求示意：

```json
{
  "request_type": "SPEECH",
  "scene": "SHERIFF_CAMPAIGN_SPEECH",
  "intent": {"goal": "争取警徽并回应竞争者", "audience": "public"},
  "agent": {"persona_id": "cautious-v1", "role_strategy_id": "wolf-blend-v1"},
  "context": {"self": {"seat": 2, "role": "wolf"}, "public_history": []},
  "constraints": {"max_chars": 300}
}
```

上述为简略说明，实际请求包含完整授权上下文；输出仍仅为speech。SELECT同样在输入明确request_type与scene，再附options，模型返回selected。意图由宿主发起，不由模型把投票请求改成发言。

新增验收WM-12：同局恢复人格版本一致；同样合法局面下，两种persona输入有明确差异、合法候选相同；不能凭人格获取额外秘密。真实多局评估悍跳率、上警率、站边/倒钩行为和发言风格，不以单次输出宣称人格效果通过。
## 人格来源与开局准备（用户已确认）

支持三种模式：

| 模式 | 用户长期配置 | 本局处理 |
|---|---|---|
| fixed 固定 | 保存性格、人设及版本 | 加载配置快照，不调用人格生成模型 |
| generated 每局生成 | 保存生成约束、生成模型及预设兜底 | 开局前生成本局性格与人设，校验后保存 |
| hybrid 固定性格＋本局设定 | 保存稳定性格与允许变化的范围 | 核心性格保持，生成本局表达风格或身份相关战术倾向 |

人设描述“这个人是谁、如何表达”，性格影响决策偏好，战术回答本局怎样行动；三者不能合并成固定整局行动脚本。生成的配置不授予额外技能，不改变游戏事实，也不得覆盖系统规则。混合模式禁止生成结果改写固定核心性格。

实现顺序已确认：先完成固定配置，再加入开局生成；两者消费相同的resolved persona结构，不为生成模式复制一套运行逻辑。首版由受信任服务端配置，不额外扩展人格编辑UI。

开局顺序：加载玩家配置 → 生成/加载基础性格与人设 → 分配游戏身份 → 按本人身份生成或应用战术倾向 → 全席准备完成 → 启动首夜倒计时。身份相关生成只得到本人获准知道的信息，不得到其他人的隐藏身份；基础人格生成不需要整局真实状态。

生成必须有Schema校验和独立准备期限；失败、非法输出或准备超时使用已配置的预设人格，不无限重试或阻塞开局。混合模式兜底仍保留固定核心性格。这是开局配置兜底，不属于行动截止裁判规则，具体准备时限与预算作为配置在实施前确定。

人格准备状态和结果持久化，以房间/玩家/生成步骤为幂等键；已成功的结果在重试、刷新和服务恢复时复用，不重新生成或改变人格。游戏倒计时只在全席准备完成后启动一次；生成及校验不消耗首夜60＋30秒窗口。

保存resolved persona内容、来源模式、配置版本、生成模型profile、模板版本及生成/兜底结果；真实供应商返回的model、用量和耗时另入内部审计。保存实际结果而非只存seed，不能声称真实模型生成可由随机种子完全重现。局势策略仍可随合法新信息变化，但必须承接已有发言和行动。

## 每席独立模型（用户已确认）

同一局允许不同AI玩家使用不同供应商或不同型号，也允许多个席位共享同一个模型。复用现有RoomRuntime模型注册表和Seat.modelProfile；当前已有按席路由基础，但配置装配、联调和多供应商验收仍需开发，不能将设计确认写成已经运行。

三类配置独立：

| 配置 | 职责 |
|---|---|
| persona配置 | fixed/generated/hybrid、固定内容、生成约束及兜底 |
| decisionModelProfile | 本席实际游戏行动与发言使用的模型，装配到Seat.modelProfile |
| personaModelProfile | 开局生成性格/人设/战术倾向时使用的模型，可全局共用或逐席指定；固定模式无需调用 |

同一人格可以更换决策模型进行对比；同一模型可配置不同人格。首版每席一个决策profile同时承担SPEECH和SELECT，不额外引入每场景动态换模型或自动跨供应商降级。局内profile配置固化，恢复不能悄悄替换模型。

模型差异不得改变信息权限、合法选项、游戏期限与默认判定。不同profile分别配置接入格式、上下文/输出预算、并发限制与费用控制；同一供应商共享并发配额时统一调度，不以不同profile名称绕过限流。人格生成费用和对局决策费用分别统计，并受整局总预算约束。

密钥只在服务端环境；公开页面或对手输入不展示敏感配置及人格战术标签。首次真实调用仍需确定具体profile、并发与费用上限。本次“确认，写入docs”不表示授权付费调用、改代码或部署。

## JEV SELECT 旁路比较（v1 历史实现；本机当前暂停）

关联[狼人杀需求 009](../.agents/note/009-jev-select-shadow-comparison.md)。此版只做对照，不把 JEV 输出用于行动。原模型的 SELECT、SPEECH、规则强制选项、默认动作和裁判流程均按现状运行。这次的比较器只属于狼人杀 MOD。

服务内独立后台比较器以私有 `fw_event_log` 中已持久化的 `model.call.started.v1` 为输入；只处理 `mod_id=werewolf`、真实模型、首个 attempt、输出 Schema 为 `selected` 枚举的普通 SELECT。脚本、SPEECH、强制选项不进入候选。比较器不在原模型的等待链、游戏事务或阶段倒计时中等待 JEV，亦不向游戏写任何提案。比较任务在源请求日志落库后尽快执行；因此“同步”指同一决策点的并行观测，不保证两家 API 同毫秒发出或返回。

JEV 请求使用[TypeSafe 官方 OpenAPI](https://api.typesafe.ai/docs)的 `POST https://api.typesafe.ai/v1/systemone`：

```json
{
  "model": "jev-latest",
  "state": { "messages": [{ "role": "system", "content": "..." }] },
  "questions": {
    "selected": {
      "type": "choice",
      "instructions": "根据给定规则、事实和本人身份，在当前合法选项中选择最合适的一项。",
      "criteria": { "option-0": "当前行动中 option-0 对应的动作", "option-1": "当前行动中 option-1 对应的动作" }
    }
  }
}
```

`state.messages` 是原始 DeepSeek `ModelRequest.messages` 的有序内容副本，不取裁判全状态，也不从日志外补充其他席位信息；保留知识、公开历史、本人指南、命中规则、输出 Schema、当前事实及记忆的原顺序。`criteria` 的键只允许使用原请求 `outputSchema.properties.selected.enum` 的 ID，值由原请求当前行动 `options` 中同 ID 的值生成可读描述。发送前校验两集合一致、选项数在 1～255 之间；不满足就记录“未发出”原因，不猜选项。JEV 实际返回的 `answers.selected.choice` 仅作为观测值，即使不同于原模型或不是合法 ID，也绝不提交。`jev-latest` 的实际返回模型版本须入日志，供日后比较时识别版本漂移。

服务端使用独立开关 `JEV_SHADOW_ENABLED` 和环境密钥 `JEV_API_KEY`，密钥与现有模型凭据一起由当前用户专用文件注入，不能写入仓库、浏览器、请求体或日志。比较器按启用后新产生的源调用工作；启动时持久保存启用水位以防扫描历史旧对局。重启后只补处理尚未领取的合格源请求；已领取但没有结束日志的任务标为结果未知，不自动再次收费调用。停止服务应等待短时在途比较。若 JEV 网络失败，原模型照常工作，旁路错误留私有日志。首版不改原模型 token 账本；JEV usage 在私有调用详情中单独记录，不能混入 DeepSeek 用量。

### v1.2 choice 分布抽样与对照（已实施，本局实测）

关联[需求 009](../.agents/note/009-jev-select-shadow-comparison.md)。[TypeSafe 官方 OpenAPI](https://api.typesafe.ai/openapi.json)列出 `noul`（是/否概率）、`choice`（选项分布）和 `score`（分数分布）三种**问题类型**。当前普通 SELECT 的合法选项是互斥的一项选择，继续发送一个 `choice` 问题。`answers.selected.choice` 是供应商给出的最高概率选项；`answers.selected.probabilities` 是每个选项的概率，合计约为 1；`confidence` 是供应商对该最高概率选项的确信程度，数值 0～1。它不是另一个选项，也不能逐项乘进概率后再归一化（共同乘数会抵消）。

旁路新增纯选择器：只接受与本次合法选项 ID **完全一致**的概率表、有限且非负的数值、正的总和及 0～1 的置信度。先按总和归一化为 `p_i`；把 `confidence=c` 用作本 MOD 的保守混合系数，得到 `q_i = c·p_i + (1-c)/N`（`N` 为合法选项数），再从 `[0,1)` 的一次随机抽样中按稳定的合法选项顺序累计 `q_i`，产出 `sampledSelected`。这一混合是本游戏提出的策略，**并非** JEV API 语义；应在本方案获确认后固定策略版本和随机种子/抽样值。`c=1` 时按原概率抽样，`c=0` 时均匀抽样；单一合法选项直接选该项。响应无效时只记错误，不改用最高概率 `choice` 或均匀抽样伪造结果。

JEV 成功事件保留当前 `choice`、`confidence`、`probabilities`、实际模型版本、usage 和延迟，并新增完整的供应商响应 JSON（限已有 64 KiB 响应上限）、选择器版本、归一化概率、混合后的概率、随机种子/抽样值和 `sampledSelected`。原始字段不被改写。随机输入必须随源 `request_id` 固定并持久化，扫描重放或查询比较时不再抽一次。任何字段均仅进本 MOD 的私有审计事件，不进公开牌局、其他席位上下文或模型提示。

比较同一 `request_id` 下现有模型的**最终有效 SELECT**、JEV 的最高概率 `choice` 和 `sampledSelected`，并展示现有模型所选项在 JEV 原始分布中的概率。现有模型尚未提交或失败时记录对应状态，不把失败默认动作算成模型选择。因为旁路可能先于原模型结束，对照从两方持久日志关联读取，不能在 JEV 返回时假定原结果已存在。随机一致/不一致只是一次抽样现象；判断两个模型倾向差异以完整分布和原选择所在概率为主。旧 v1 事件保留原样，标记无抽样版本，不追补随机结果。

2026-09-29 用户明确要求当前局启用 009 旁路并忽略已发生请求；本机已部署 v1.2 且 `JEV_SHADOW_ENABLED=true`。服务重启时先写入新启用水位，再扫描后续 SELECT；这不改变 DeepSeek 的实际行动。本局水位 4337 后已有 12 次真实 JEV SELECT 成功返回，全部保存完整原始响应、概率与抽样结果，水位前没有补调。

### 阶段三：狼队内部协商（016 v1.1，联合实施中）

#### 组织者与窗口

首版用本局已有种子生成并保存存活狼人顺序，第一位为主提议者、第二位为补位者；主提议者存活时延续，出局后递补，不随重试重抽。这里只分配提议顺序，不宣称经过选举或由裁判挑选最佳玩家。自主推举留后续扩展；单狼自己提议。

每夜原技能前拟增加一个固定 45 秒私密组织窗口，原 60 秒技能＋30 秒用药／等待保持，总夜长拟为 135 秒。成功早返、无提议、单狼、失败均不改变公共时长。只有存活狼人接收新消息，公共页面不显示狼人数和内部步骤，死狼不能继续组织。

#### 按需提议和补位

新增组织请求和原狼刀是先后两个阶段：组织窗口内只按条件调用主提议、目标同意或补位；窗口结束冻结团队版本后，才同时创建各存活狼原有的狼刀请求。组织请求不替代任何人的原刀票，也不偷看正在密封提交的刀票。

通常只调用主提议者一次：私密 SPEECH 最多 200 字，可附 team_proposal:{knifeTarget,assignments,conditions,selfKnifeConsent}。knifeTarget 为当前存活目标或 null（空刀）；assignments 为 0～4 条不同存活狼的 {seat,tactic,claimedRole,instruction}，标签 1～24 字、职业 ID 或 null、建议 1～80 字；conditions 为 0～120 字，描述分工适用与退出条件；selfKnifeConsent 为布尔值，只能表达提议者对刀本人明确同意，不能替其他目标接受。

合法提交立即在队内发布，其他狼不用各写一份提议。主发言非法、未接受或过期时不发布附加提议；合法发言中的无效提议只丢弃提议，不单独重试、不从原文猜测一个权威计划。空刀 null 是有效方案，不触发补位。主请求经过已有有界尝试终止失败、无有效提议或未获自刀同意时，剩余时间足够才调用补位者一次；不在主请求尚未终止时并行另起补位。补位者读自己的授权信息及已经发布的原文／拒绝，不读主提议者记忆；未提交的失败响应不充当队内发言。

一次补位后不再回调主提议者、不追加另一名补位者。因自刀拒绝、无合法同意或失败而补位时只允许普通刀口／空刀，避免再次征求其他自刀目标。同意超时到共同截止时不再补位；在截止前终止失败且有提交余量时才可能补位。合法替代方案提交才将旧版 superseded；原文／拒绝仍保留，没有有效替代则不冒充已形成新计划。

只保留一个当前提议版本，旧版及实际来源留存。状态包含 night、planId、version、status、organizer、participants、sourceSequences、payload、consent、adoptions；status 为 proposed／superseded／expired。同意和采用分别记录，不写虚假的全队 confirmed。

#### 自刀同意及原狼刀回应

普通刀口不额外调用全员确认。所有狼包括组织者，在原狼刀 SELECT 中读取组织截止时同水位的提议／目标同意，自主选择跟随、其他合法目标或空刀。当前刀票和附加回应保持 sealed，到原狼刀窗口结束后才按席位授权发布；早返回者不影响其他进行中的输入。

同次 SELECT 可附 team_response:{planId,version,assignmentStance,note}，字段必填、禁止未知字段：planId／version 只引用本次可见未过期版本；assignmentStance 为 accept／adjust／reject，描述本人分工态度，note 为 0～100 字简短说明。仅该狼有被指派的分工时保存分工态度，不能替队友接受；没有分工不补造任务。字段缺失、非法或引用不可见版本时只忽略附加回应，合法刀票照常提交，015 的个人更新另行校验，不为这些附加错误单独重试。

实际 selected 映射出来的刀口才决定刀口采用记录，不由附加文字改写。刀口与提议相同仅证明采用了刀口；assignmentStance 只证明表达了分工意向；两者均不认证白天已执行。无附加回应时分工态度记 unspecified；沉默、默认、失败和过期不算接受。记录 explicit-model／explicit-script／default 来源，兜底票即使巧合相同也不冒充主动认可。全员实际票型一致只叫刀口一致，不表示全部分工获全员同意。

白天不新增协商调用，本人每次普通交互续读后部团队记录及 015 个人记忆，悍跳、冲锋、倒钩、身份说辞和归票可因新公开事实调整；缺少调整理由可记录偏差，但不拒绝合法行动。对外只发表该席实际生成并通过校验的发言，服务器不复制领袖台词。下一夜组织者可见授权的先前提议、回应和真实执行记录，不窥读其他人的个人计划。

提议刀队友时，在组织窗口内额外调用被刀狼人一次接受／拒绝 SELECT，绑定 planId／version；缺席、失败、超时视为未获同意。提议者刀本人时，可以同一次有效提议中的 selfKnifeConsent:true 明确同意，省去重复询问。本人同意不认证女巫会救或全队接受。

机器人选项约束排除未明确同意的狼人队友刀口；自己实际选择自刀可以表达本人同意，但不追溯开放其他已结束请求。其他狼采用自刀只读取组织窗口已发布同意，避免并行顺序影响。目标不合法、绑定版本被替代或无有效同意时，不执行该自刀提议，继续普通合法狼刀决策。原裁判最高票／平票规则保留，没有团队方案也继续游戏。

真实刀口／获救／死亡仍依原动作及授权结算记录。刀口只用于当夜，白天分工可参考至下一夜开启；新夜旧提议过期。失效说明不能泄漏未公开死亡或技能结果。

#### 成本、失败、权限及恢复

新增调用按需发生：通常主提议者 1 个逻辑交互；异常时最多补位 1 个；涉及队友自刀时最多目标同意 1 个。每夜全队新增上限 3 个，不按狼人数倍增，不要求用满。主提议失败后补位提出自刀可用剩余同意名额；已经被拒绝则补位不得再问另一个自刀目标。

每交互最多 3 次总供应商尝试，网络重试／格式纠正共享，新增协商最多 9 次尝试；45 秒截止更早则停止。输出仍最多 800 token，提示要求简短提议和分工，不为多段附加输出上调额度。原狼刀模型决策仍在，通常净增 1 个交互，不能声称规则省去了原 W 个调用。脚本生成的提议不制造供应商调用；未有有效方案不新增第三轮。

补位／同意调用须满足现有剩余时间准入，重试仍用原 1 秒／3 秒加 jitter；不为凑次数延长窗口。超时进入原阶段，不把失败伪装为接受。协商 SELECT 按 scene 排除 JEV 旁路，普通狼刀 SELECT 保持。

自提本人时 selfKnifeConsent:true 且 knifeTarget 恰为本人，才形成同版本人明确同意；true 却刀其他人无效，不能代理。自己未明确同意视为不可用自刀，可按名额／时间补位普通刀口。目标同意请求只发被刀者，其他席不额外调用；失败后不切换另一个被刀目标继续询问。

三类新增名额全队每夜各最多一个，未使用不补调，原狼刀不计入三类名额；名额派发前持久登记，供应商尝试另计，重试不重新占补位名额。典型分支为 primary；primary→consent；primary→backup；primary→backup→consent；primary→consent→backup。已拒绝或同意失败后的 backup 禁止再提队友自刀。主提议者存活延续不意味着复用上一夜刀口；只有本夜实际提交的版本有效。

deadline 为组织阶段开始时确定的同一个值，排队、API、重试等待、提交均消耗它。每次派发／重试须按实际模型超时配置检查一次供应商尝试时间及提交余量，具体值在实施时核实调度配置，不暗中延长阶段；不足时记录 skipped-deadline，不发送 HTTP 请求。三次尝试和三种名额都是上限，不承诺 45 秒能全部跑完。组织到期冻结提议／同意，终止未完成请求，再开始原技能期限；晚到响应只进调用日志，不能改变已发出的狼刀上下文。

原主行动、提议附加、同意、团队回应、015 个人更新各自注明接受／忽略／拒绝原因。日志关联 roomId、night、seatId、phaseInstance、requestId、slot、planId/version、providerAttempt、deadline、status、usage 及原请求／响应；未派发的跳过也记录原因但无供应商 token。同意及票型是动作事实，拟议对白不认证真实身份；结算后授权结果才提供刀口死亡／被救信息。

MOD 的阶段推进负责分支、组织者、封闭水位和授权事件；server 调度负责逻辑名额／尝试准入和模型日志；decision-input 提供分场景输入／输出说明；MOD 输出解析独立处理主行动与各附加字段，记忆组合交给 015。实现时须按真实代码入口对应这些职责，公共接口不足另建根层方案，不将狼队状态机放进通用框架。

计划及 slot 状态、原期限、已发布事件、接受来源须持久保存，事务只覆盖状态检查和提交，不等待模型。恢复不能释放已用名额以重新获得三次；无法确认外部 API 是否已收到的崩溃窗口按既有模型请求恢复机制处理，仍计已占名额，不能承诺供应商恰好一次或通过重启无限补调。

team_history／team_plan 放在 private_information 后部，只含本席获权的已发布信息；公共缓存前缀保持一致。不读他席个人记忆，不在公开回放展示私密正文。受权模型诊断保存原请求／响应、错误、附加处置及真实 usage；成功但过期仍记调用，失败不编造 token。

提交以 requestId／phaseInstance／decisionEpoch／planId 版本重验，短事务保存状态和授权事件，模型等待不持锁。恢复沿用原期限、组织者顺序、调用计数和已提交记录，不重抽、不补调已完成请求、不重记同意。授权／数据库异常沿用真实错误处理。优先复用既有阶段、授权事件与规则引擎，公共接口不足另建根层中性方案。
