# 阶段时间限制建议 v1.3

状态：夜间狼人和预言家共享60秒、随后女巫30秒已由用户明确裁定，其余时间与超时默认动作待确认；本轮仅整理规则建议，不批准实现。以下为本项目建议值，不是网易官方时限。

## 计时口径建议

1. 表内为最大等待时间，不要求每人耗满；公开发言合法提交即结束。多人封闭选择共享截止点，除退水外全部完成可提前结束。退水固定到10秒边界统一结算，不因全员提前提交而提前结束；见[需求006](../.agents/note/006-shared-sheriff-withdrawal.md)。
2. 计时从该玩家获得行动权/多人阶段正式开始时算起，包含排队、模型生成、校验和重试，不在重试或刷新后重新给满时长。多人阶段需调度并发或有公平的预算分配，不能让排在后面的AI只拿到剩余几秒。
3. 单次模型请求建议最多45秒，且不超过该动作剩余时间减3秒；最多重试一次，重试仍共用原截止点。剩余时间不足则直接进入默认动作。模型返回不合法也适用同一预算，不无限纠错。发言完整合法提交后才作为正式公开记录，未完成片段不拼成伪造发言。
4. 发言超时只加系统标识“本次发言超时，已跳过”，不生成冒充该AI的分析；该事件放在对应天/阶段，区别于角色真正说出的话。
5. 夜间先由狼人刀人与预言家查验共享60秒、同一截止点；狼刀结算锁定后，女巫获取刀口并有后续30秒用药窗口。夜间合计上限90秒，不是60+60+30。前段提交早不等于给后段偷加时间。公共页面只显示夜间统一进度，不暴露具体角色动作或完成状态；是否早于上限公开天亮的隐私策略仍需在开发方案中明确。
6. 服务器判定截止时间，前端仅展示。恰好到期按超时处理；迟到结果丢弃。同一行动只提交一次，不能既接受模型输出又执行默认动作。自爆、正常提交、超时由服务端串行裁决，自爆成功后原发言/投票结果不能写回。
7. 多次超时不会自动取消座位、直接判负或揭露身份。模型失败可用合法默认动作继续；数据库或状态提交失败则停止推进并恢复，不能假装默认动作已经成功。
8. “打开历史发言就暂停”的当前原型行为不能直接沿用为真实计时规则。建议真实计时局打开浮层仍继续；暂停按钮仅给调试模式，暂停时冻结剩余时间。重启后按持久截止点补一次兜底，不补发迟到模型结果；具体恢复机制待开发设计确认。

## 现有实现差距与后续说明

当前Phase没有游戏截止时间字段；运行层已有模型任务/租约机制，但不等同于表内游戏超时兜底。当前预言家行动要求合法非空目标，因此“不查验”不是现成合法动作；本建议采用合法目标随机，用户也可以裁定新增放弃查验。当前发言schema最多300字符，与长篇AI发言方向需后续一起确认上限，不能把150秒理解为已经支持无限文本。

时间值及默认动作确认后，另行形成开发方案：通用计时/恢复能力归第二层中性文档，狼人杀阶段映射和默认动作归本MOD。测试需覆盖截止前后、重复超时、迟到返回、自爆竞争、进程恢复、私密夜间时长及连锁结算。此文不修改代码、数据库或浏览器。

所有数字仍是上限；提前完成可推进的原则与夜间固定窗口例外继续待确认。单次模型请求45秒及最多一次重试建议暂不变，短阶段始终受剩余时间约束。查验随机/跳过、夜间能否提前结束、真实局历史浮层不暂停三项仍待裁定，未开始开发。

## v1.2用户裁定（已被v1.3替代）

用户明确指出“这3个时间，应该是共享75秒，每个角色各做各的操作”。因此夜间总窗口为75秒，非三个角色独立时限相加。先前助手提出165秒/225秒为错误理解，不再采用。

当前实现的wolves→witch→seer是内部顺序状态机，后续开发须调整为共享窗口收集，不能以现有代码顺序反推玩法。女巫救药依赖刀口的信息发布/刀口锁定时机仍需在共享窗口方案中明确，不擅自改成盲救，也不另加75秒；本次只确认时间规则，不实现并行状态机。

用户明确要求：狼人刀人与预言家查验共享60秒；女巫用药在狼人行动结束后30秒。该裁定替代共享75秒的旧方案，夜间为60+30结构，合计上限90秒。观看控制直接复用现有单步、1×、2×、4×，不新增速度选择界面。
