# 旁观视角切换 v1

状态：用户回复go next确认实施；已实现并完成本地验证。需求归属001。

## 已确认范围

默认公共旁观。左下角“◉ 公共旁观 ▾”打开木纹视角选择浮层，包含公共旁观和12席头像/号码，选择前不显示身份。选中后显示“◉ N号视角 ▾”，上方展示小头像和本人身份，席位角标为“视角”而非“我”。点击席位仍用于资料和个人标记。中央Avatar与正文始终跟随当前发言者，夜间无中央人物。切换、阅读历史和弹层不影响时钟。

仅限当前本地无模型Demo，允许任意席位调试；不实现正式账号权限、玩家接管、模型或RTC。死亡座位可选，不提升为全知。终局公开身份及既有复盘保留。

## 实施方案

1. mods/werewolf的DemoRooms.get新增可选viewer（null或1—12），默认null。先生成原公共快照，再附加所选视角的独立perspective字段；公共events、speeches、speakerSeat及计时保持原语义，不混入私密事件。
2. 复用views.ts/projectGame的self投影及框架既有按受众过滤事件能力。perspective白名单为seat、role、wolves、inspections、medicine、knife与已公布的授权死亡标记；不返回完整Match、随机状态、密封中的选择、别人的私密事件或未公布死亡标记。狼刀需要补充服务端明确结算结果，不能在客户端按狼票重新抽签。
3. GET /api/werewolf/demo/:id增加可选seat查询参数，严格校验1—12整数，省略为公共。创建仍返回公共。`mods/werewolf/shared/werewolf.ts`定义联合类型：public或seat；每次响应标明当前视角。没有修改操作接口、数据库或框架通用协议。
4. 女巫授权刀口完全沿用现有条件：女巫阶段、本人存活且解药仍在时显示；字段缺失显示“当前不可见”，null才表示空刀。药量显示剩余/已用，不凭阶段猜测刀口。查验仅显示已获得的好/狼及对应席位。狼人只看到结算后的狼刀与队友。
5. 死因标记必须先确认该玩家已公开出局，再增加该视角有权知道的狼刀/毒杀原因。同夜刀毒重合按既有规则优先级处理。自己的用药记录不是提前标记目标死亡的依据；救活、自爆或死亡连锁不能误标夜亡。
6. room.tsx区分选择视角和点击资料的selected状态。切换时立即清空旧私密展示，等待匹配新视角的响应；请求使用AbortController或代次校验，迟到响应不得覆盖新视角。读请求不推进、不暂停游戏。重开和刷新默认公共旁观，避免残留座位身份。
7. 视角信息区位于左下角旁观按钮上方，历史入口上移避让；开局前选择入口禁用；采用现有木纹与纸纹，不使用大面积纯色。信息多时从该区展开详情，不遮挡中央发言或改变头像点击行为。浮层可键盘选择和关闭。回到公共旁观清除所有私密角标、资料身份和信息区；个人手工标记仍保留且明确为个人推断。

## 行为验收与实施顺序

先写失败的Demo/HTTP权限行为测试，再实现投影及接口，最后实现UI并进行浏览器验证。

- PV-01：无seat与公共模式不返回self、队友、查验、刀口、药量或私密死因；非法seat返回400，不影响对局。
- PV-02：狼人只看自身身份、队友、已结算狼刀；查验和药量不出现在响应。
- PV-03：预言家仅获得已发生的查验，好/狼不泄漏具体神职；未查验不显示。
- PV-04：女巫药量与真实状态一致；只有授权窗口返回刀口，空刀与不可见明确区分。
- PV-05：首夜警长竞选前，任何视角的公开死亡标记均不提前出现；公开后授权死因正确，救活或自爆不误标。
- PV-06：死亡视角不获得新授权信息；终局仍可使用原公开复盘。
- PV-07：快速座位A→B→公共，延迟A/B响应不能恢复任何旧私密内容；切换前后同局时间持续推进。
- PV-08：中央说话人不随视角改变；头像点击保持资料/标记；历史、长文气泡与视角弹层均不停表。
- PV-09：重开、刷新及会话过期回到公共视角；手机尺寸下入口互不重叠，长身份信息可展开，背景纹理可见。

验证使用固定种子、注入时钟和延迟响应，禁止为验收新增暂停或越权生产接口。运行相关测试、类型检查、生产构建及本地浏览器实测。无需数据库迁移。
