# 青溪角色属性设计 v1（未来提案，未确认、未实现）

> 本文不是当前版本规则。当前版本继续使用既有 `silver`、`virtue`、`skill` 等字段；本文提出的四维资质、气血/内力/精神和派生公式不得用于实现、测试或产品说明，除非另有需求确认。

## 目标与参考

让角色形成可解释的体质、武学与成长差异，服务当前探索、拜师、任务和回合战斗。具体武侠属性与公式归青溪MOD，platform与game-systems提供身份、事务及可选游戏机制。

参考[北大侠客行天赋说明](https://wiki.pkuxkx.net/wiki/newbie/gift)与[帮助FAQ](https://wiki.pkuxkx.net/wiki/help/faq)。参考四维资质、先天与后天区分、技能成长思路；不同侠客行分支及历史版本规则不一致，以下数值是青溪设计建议，不是原作公式。常见武侠游戏的气血、内力、武功、声望等概念按当前玩法选取。

## 属性分层

| 层 | 字段 | 作用 |
|---|---|---|
| 身份 | 姓名、性别、门派、师父 | 展示与关系；性别不决定战斗强弱 |
| 基础资质 | 臂力strength、根骨constitution、身法dexterity、悟性intelligence | 决定不同成长倾向 |
| 当前资源 | 气血hp、内力qi、精神spirit | 分别服务承伤、招式、学习 |
| 成长 | 累计经验experience、可用潜能potential、各项技能等级 | 经验决定修习进度门槛；潜能用于学习；技能决定实际能力 |
| 江湖记录 | 银两silver、侠义virtue、门派与个人关系 | 经济与剧情条件；侠义不直接增加伤害 |
| 派生能力 | 气血/内力/精神上限、攻击、防护、身法减伤 | 服务端统一计算，页面说明来源 |

一期不加入无消费场景的福缘、容貌、灵性、饥渴、负重、经脉、暴击和穿透。声望与侠义语义不同；有公共事迹系统后再加入独立声望。精神只消耗于修习，不因聊天、行走或在线时间减少。

## 资质与选择

四维初始合计80，每项16～24，均衡为20/20/20/20。一期用四种预设选择，减少新手误配：均衡(20,20,20,20)、刚健(24,24,16,16)、灵巧(20,18,24,18)、颖悟(16,20,20,24)，顺序均为臂力/根骨/身法/悟性。

所有角色初始均衡。在第一次修习或战斗前，可通过独立动作set_aptitude选择预设；首次修习或战斗锁定，普通set_profile不得改数值。不迁移旧档；后续洗点需单独设计。界面展示选择后的上限与学习消耗预览。

一期先天资质固定，后天成长由技能直接进入派生公式，不额外存储第二套可变四维。未来需要后天四维展示时由技能推导，避免技能和属性两次累计。

## 基础技能与成长

保留两门派的吐纳法/采息术与青松剑式/点穴手。补充公共基本拳脚、基本轻功、读书识字，均可在武馆学习；门派技能仍需入门。一期技能上限仍为3，每次升级消耗潜能2；不同时扩大等级刻度和重做奖励经济。

经验为累计阅历，不消费；修习目标1/2/3级分别要求经验0/5/10，另需满足门派、前置技能和资源条件。现有师门任务奖励经验5、潜能4，双人护送经验5、潜能2保持。增加寻药完成奖励经验5、潜能2，提供入门前的基础成长来源。

修习消耗精神=max(1, 5-floor(悟性/8)-floor(读书识字等级/2))，按升级前等级计算；潜能成本不受悟性减免，防止悟性成为长期收益必选项。读书识字提高精神上限和学习续航。

实施此待确认方案时直接删除skill字段，不提供旧技能回填或只读兼容。切磋资格改为基本拳脚或本门招式达到1级。拜师成功附赠基本拳脚1级；奇遇GUIDANCE改为潜能+2，结果说明同步更新。

新角色按当前规则初始化；不补发旧档技能或奖励。统一青松门join_school与apprenticeship的资格与AI态度入口，避免直接加入绕过侠义要求；百草门保留本门规则。

## 派生数值与回合规则

以下是待验证的青溪一期数值。内功等级N为本门基础内功等级，未入门为0；拳脚B、轻功D、读书L、招式S为对应已学等级，缺省0。

| 能力 | 候选公式 |
|---|---|
| 气血上限 | 30 + 2×(根骨-20) + 4×N |
| 内力上限 | 10 + floor((根骨-20)/2) + 3×N |
| 精神上限 | 20 + (悟性-20) + 2×L |
| 普通攻击原始伤害 | max(1, 2 + max(B,S) + floor((臂力-20)/4)) |
| 本门招式原始伤害 | max(2, 4 + 2×S + floor((臂力-20)/4))，每次内力2 |
| 根骨防护 | max(0, floor((根骨-20)/4)) |
| 身法减伤 | clamp(floor((身法-20)/4)+floor(D/2),0,2) |
| 最终承伤 | max(1, 对手原始伤害-根骨防护-身法减伤) |

恶徒仍为气血12、原始伤害3、防护0。玩家先攻击，敌人存活才反击。身法一期通过确定性减伤体现“避开要害”，UI不称为闪避概率；暂不增加随机命中、攻速或先手规则。玩家与NPC可复用青溪公式，敌人属性由MOD配置，个人任务敌人归属不变。

示例：均衡未入门普通攻击2，承伤3，气血30；刚健未入门普通攻击3，承伤2，气血38；灵巧未入门普通攻击2，承伤2，气血26；颖悟精神24，基础修习消耗2，对比均衡消耗3。这只是初始差异，非平衡已通过的结论。

上限变化时保留当前值并裁剪到新上限，不按比例补满，避免反复操作获得恢复。必须使用同一派生函数生成资格、UI、模型事实和结算。

## 恢复与失败

新增rest（休息）动作，只能在村口、茶馆、武馆且无active师门战斗任务时执行，一次回满气血、内力和精神；没有奖励，不增加属性上限。每次通过现有幂等事务登记。初期免费恢复确保角色不因资源耗尽永久卡死。

师门交付与战败恢复均使用派生上限，替换硬编码30/10；战败仍回村口、扣银两1且不为负，任务敌人恢复。精神耗尽不妨碍战斗、交付、移动或返回安全地点。休息不结束任务或改变敌人血量。

## 接口、存档与界面

新增青溪attributes.ts集中管理类型、资质预设和派生规则；training.ts调用该规则生成消费与资格。wuxia_characters直接采用四维（默认20）、精神（默认20）、资质锁定字段；hp/qi使用非负约束并由事务校验动态上限。新角色精神按预设上限初始化；旧开发库允许重建。

新增严格动作set_aptitude（仅presetId枚举）和rest；客户端不能提交属性值、奖励或派生上限。修习/战斗在提交事务内锁定资质并重验全部资源，重复请求不重复扣除。技能升级后重新读取技能再生成after事实，防止模型收到旧派生值。

WorldView继续使用通用属性展示数组；青溪投影同时提供可用操作与原因。页面优先显示气血/内力/精神、四维、经验/潜能、门派/侠义/银两；技能显示名字与等级，派生能力附说明。若引入通用分组或说明字段，另同步框架契约，不把武侠计算放入Web。

本方案仍待玩法确认。实现时先保存代码检查点，使用空库验证；不保留旧属性或数据迁移。当前版本内requestId结果仍不可修改，重复提交不得重复结算。

## 验收与推进

1. AT-01：预设总和/范围校验，非法输入拒绝；修习或战斗后不能改资质。
2. AT-02：四维及技能影响与公式一致，派生上限与页面/事实/结算一致；均衡、刚健、灵巧、颖悟各跑完整成长路线。
3. AT-03：经验、潜能、精神不足分别给出中文原因；绕过UI提交同样拒绝，事务无部分扣除。
4. AT-04：普通/招式伤害、最低承伤、击杀无反击、败退及恢复边界正确；双方资源均不越界。
5. AT-05：休息不发奖励、不改变敌人，禁止条件与客户端说明一致。
6. AT-06：空库初始化正确；当前版本重复初始化不重置属性，同一请求重放不二次结算。
7. AT-07：两名玩家属性与私有敌人不串档；组队奖励各自原子入账。
8. AT-08：AI输出不能写属性或绕过资格，前端仅展示服务端结果。

先确认本设计，再写行为测试与实现、隔离空库回归，必要时重建开发库部署。福缘、装备、伤势有效上限、经脉与随机命中留待后续独立版本，不以预留字段占用本期实现。
