# 武侠世界地图表现设计

版本：v2，已确认并实现。配合[世界MVP](world-mvp.md)、[验收用例](world-mvp-testing.md)、[实施计划](world-mvp-plan.md)和[实际验证](world-mvp-verification.md)阅读。

## 1. 原则和交付范围

文字负责人物表达、环境细节和历史叙述；地图是主要交互界面。地图呈现权威世界状态，历史记忆解释变化缘由，不通过模型叙述反推数据库事实。

| 层级 | 长期职责 | 本次交付 |
|---|---|---|
| L1 区域战略图 | 区域、势力和地理关系 | 仅显示区域名及位置导航；不制作独立战略图 |
| L2 房间关系图 | 出口拓扑、当前位置、已探索范围及通行状态 | 核心：SVG节点图、固定布局、平移缩放、箭头、迷雾、封锁提示 |
| L3 场景氛围层 | 当前房间人物、物件、环境及结果反馈 | 3类复用模板、可点击对象、简短文字和轻量状态过渡 |

首版不做势力模拟、动态天气规则、背景音乐、粒子系统、Canvas/Konva、自动寻路、地图编辑器接入、GMCP或WebSocket协议。上述为未来候选，不创建空接口或占位服务。当前既有Fastify、PostgreSQL及模型适配保持不变。

## 2. 同源数据与职责

游戏拥有一套世界模型，不要求三个视图只读同一张房间表。静态区域/房间/出口/模板定义与每scope的位置、发现、NPC、物品、任务共同形成状态；宿主产生地图和场景的不同投影。绘图坐标不决定相邻性，画面更新不执行游戏操作。

所有内容、地图投影、可见性和绘制均归武侠example及其Web装配。Harness只处理宿主提供的通用事实、记忆、模型契约和受控提交，不增加room、faction、fog等公共游戏规则。

模型仅提出当前Binding允许的候选，宿主验证后执行。首版不开放reveal_hidden_exit、change_faction或block_room工具；NPC交谈不会取得修改地图权限。拜师成功解锁出口是游戏规则的确定性后果，无需第二次模型调用。

## 3. 拓扑及三种信息范围

房间有稳定ID、类型、模板和固定layout坐标；出口有稳定exitId、源和目标、方向标签及条件。每房间最多8个出向出口。双向通行必须定义两条出口，单向出口只定义一条；上/下等标签不要求额外楼层渲染器。两条反向出口条件不同时必须分别表达通行状态。

1. 已探索：首次进入时持久记录，离开后仍记得地名与已知结构。
2. 当前可感知：v2仅包括当前房间对象与可见出向出口；相邻地点只知基础信息，不远程看到其人物、物品或实时门槛变化。
3. AI可知：由宿主按当前动作选择当前事实及相关历史，不直接复制地图响应，更不等同于全部已探索房间。

局部图由服务器沿出向拓扑有界遍历两跳，至多73个去重节点；这表示图形查询范围，不是透视半径。结果保留当前房间、范围内已探索房间及当前可见出口的直接目标；其他节点和相关边完全不返回。返回节点间只有端点均已探索或属于当前可见出口的边可以显示；未来若引入隐藏出口，必须另加发现条件，不能凭已探索端点泄漏秘密连线。当前没有隐藏出口玩法。

未进入的可见相邻目标用浅色轮廓、名称和“未探索”标记，既不列出对象也不显示行动徽章。不发送全图再用CSS遮罩隐藏。已探索远端仅展示已知地理；动态状态标为未知，不能当实时事实。当前出口显示实际门槛及原因；隐藏与锁定是不同概念。

拓扑可达检查忽略暂时门槛，但必须验证必需地点最终有合法进入路径；锁定的内室不是无效地点。图形局部裁剪不改变游戏真正出口。

## 4. 视觉与交互

```text
┌ 区域名称 / 当前地点 ─────────────── 用户 / 登出 ┐
│ L2 局部地图       │ L3 当前场景      │ 角色属性  │
│ 节点与方向箭头    │ 人物 / 物件      │ 背包      │
│ 缩放 / 回到当前位置│ 出口 / 环境短文  │ 任务      │
├───────────────────────────────────────────────┤
│ 已选对象 → 可用动作 → 补充说明 → 执行           │
│ 最新实际结果                         展开历史  │
└───────────────────────────────────────────────┘
```

| 编码 | v2定义 |
|---|---|
| 节点形状 | 室内方形、野外圆形、街巷圆角方形；附文本图例 |
| 当前位置 | @标记和描边，文本标注“当前位置” |
| 双向/单向 | 双向实线、两端箭头；单向虚线、目标端箭头；不同条件不合并 |
| 封锁 | 当前出口锁图标及文字原因；线型不代替规则 |
| 可交互对象 | 当前房间对话/物件徽章，来源于当前快照；远端不显示实时徽章 |
| 颜色 | 水墨中性色及当前状态强调色；不表示尚未实现的势力或危险数值 |

固定节点坐标跨请求保持稳定，不使用运行时力导向重排。地图支持拖动平移、缩放按钮和回到当前位置；缩放只影响视图。点击节点选中查看基础信息；移动须明确选择当前出口并执行，锁定出口只显示原因，远端节点不能移动。自选节点不自动提交操作。

轻量L3使用共享SVG/CSS素材与对象布局，不逐房间配图。12个房间仅引用3个模板。药包拾取后消失，任务完成后徽章更新，拜师后锁标记解除；这些反馈只在收到已提交状态后出现。任务奖励数字来自服务端结果。

新场景对象支持键盘焦点和同等文字操作列表；不要求hover才能使用。窄屏用“地图/场景/角色”切换面板，操作与最新结果保持可达。可选淡入或描边过渡遵守减少动态效果偏好，不做画面震动或强制闪烁。不加入天气计算和音效资产。

## 5. 状态接口与刷新协议

复用GET /api/mud/current，在一次一致读取中生成以下游戏侧投影：

| 分组 | 字段与约束 |
|---|---|
| 快照标识 | scopeId、worldContentVersion、hostVersion、memoryVersion |
| map | regionId/name、currentRoomId、radius=2、nodes、edges |
| node | roomId、name、kind、layout{x,y}、discovery=visited/frontier、isCurrent；无远端NPC状态 |
| edge | exitId、from、to、direction、bidirectional、access=open/locked/unknown、reason（当前已知时）；出向边表示通行，bidirectional防止未探索反向边被过滤后误画单向 |
| scene | 当前roomId/templateId、环境短文、可见NPC/物件/设施及稳定ID、对象布局、可用动作 |
| 玩家 | 角色属性、背包、任务；与map/scene来自同一快照 |

服务端只序列化投影，不把全量静态世界配置或含秘密的对象直接返回前端。scene内可用动作仍须执行时重验。NPC设定、所有模板资产可分开管理，秘密文本不能编入浏览器公共资源。

刷新流程：玩家提交动作→按requestId查询终态→GET取得权威快照→一次更新地图、场景、背包与任务。失败也刷新快照，并展示失败原因；不乐观移动或预先发奖。请求结果版本可能早于另一个标签已提交的新动作，界面以最新合法快照为准，历史结果只作回执。

同scope丢弃比已显示memoryVersion更旧的响应。切换scope或登出时取消/忽略旧请求，清空旧投影及选择；scope不同不能比较版本大小。刷新失败显示“状态尚未同步”，保留明确标记的旧画面并暂停变更操作，允许重试，不新建游戏。浏览器重新获得焦点时刷新，避免另一个标签的变化长期不可见；无需模拟实时推送。

## 6. 扩展与限制

3000房间合成图仅验证局部查询、过滤和响应范围；记录耗时及大小，不作未经测量的性能承诺。静态定义可在服务端一次校验并建立邻接索引，运行时不得为了两跳查询返回全部房间。新增同类房间只填内容和布局配置。

未来L1读取区域投影，L3可增加天气和氛围；动态势力、隐藏出口、自动寻路、多人推送均需独立规则与验收设计。外部编辑器须先核实具体项目、格式、许可及兼容成本，当前不依赖用户材料中的未验证能力或数量阈值。
